## 1. 구조 — 레포 하나, 배포 둘

### `0f0417f` 레포를 apps/naminglink + apps/inyeonlink로 분리

궁합은 이름 매칭과 성격이 달라 별도 브랜드·도메인으로 가되, 한자 DB·사주 엔진·결제·리포트를
절반 넘게 공유하므로 레포는 하나로 둔다. Vercel 프로젝트 2개가 Root Directory만 다르게
같은 레포를 바라본다.

- `src/`를 통째로 `apps/naminglink`로 이동(코드 수정 없음). git이 전부 rename으로 인식
- **`packages/core`는 1개만.** 계획서(`gunghap_architecture_plan-1.md`)는 패키지 5개
  선분리를 제안했으나 앱이 둘뿐인데 경계를 5개 유지하는 비용이 이득보다 크고, 지금 `src/lib`
  안에서 모듈들이 서로 얽혀 있어 선분리는 순환 참조부터 풀어야 한다. 서브경로 export라
  호출부 코드는 진짜 패키지 5개일 때와 똑같이 생겼다
- **지연 분리** — 인연링크가 실제로 쓰는 것만 옮긴다. 첫 대상은 사주 엔진 하나뿐이었다
- 소비 앱에 `transpilePackages: ["@naminglink/core"]` 필요(.ts 소스를 그대로 export)

### 배포

| 항목 | naminglink | inyeonlink |
|---|---|---|
| Vercel Root Directory | `apps/naminglink` | `apps/inyeonlink` |
| Include files outside root | 켬 (필수 — `packages/core`가 밖에 있음) | 켬 |
| Skip deployments when no changes | 켬 | 켬 |
| 운영 URL | naminglink.vercel.app | inyeonlink.vercel.app |
| 구매한 도메인 | naming-link.com — **미연결** | inyeon-link.com — **미연결** (최종 점검 후) |

- 프로젝트 생성 시 Root Directory 값 **끝에 공백**이 들어가 `Root Directory does not exist`로
  실패했던 이력이 있다. 같은 증상이 나오면 공백부터 확인할 것
- `.vercel/repo.json`의 `directory`도 `apps/naminglink`로 갱신(로컬 CLI용, gitignore 대상)

## 2. 인연링크 v1 — 랜딩 · 입력 · 결과

### 입력을 저장하지 않는다 (사용자 지시)

이 원칙이 아키텍처 전체를 정했다.

- **계산은 POST 본문으로만.** 생년월일이 쿼리스트링에 실리면 Vercel 접속 로그에 그대로 남는다
- **공유 링크는 URL 프래그먼트(#).** 브라우저가 서버로 보내지 않아 링크를 열어도 로그에는
  경로만 남는다. 결과 화면이 클라이언트 렌더인 이유이기도 하다(서버는 프래그먼트를 못 읽음)
- **캐시 없음.** 계획서 §6의 입력 해시 캐싱은 폐기했다. 목적이 "재조회 시 동일 보장"이었는데
  엔진이 전부 규칙 기반이라 결정성으로 대신된다
- **DB 없음** → `gunghap` 스키마도 v1에선 불필요(계획서 4단계 생략)
- 상대방(제3자) 생년월일 수집 문제도 함께 소멸

### 로케일

구조는 23개, 문구는 **ko·en만** 채우고 나머지는 en 폴백. 화면이 흔들리는 동안 23벌을
유지하면 수정할 때마다 23번 손봐야 한다. naminglink 사전과 **공유하지 않는다**.

## 3. 엔진 — v1 → v5

점수는 전부 규칙 기반이다. 유료화 시 재조회 때 숫자가 달라지면 환불 사유가 된다.

최종 매칭률 = 사주 0.7 + 띠 0.3 가중 평균.

### v2 — 출생지 진태양시 (`0f0417f`)

`@fullstackfamily/manseryeok`이 표준 자오선을 **135°(한국)로 하드코딩**해 두어
(`standardMeridian = 135`) 경도만 바꿔 넘기면 해외 출생자에게 `135 - 현지경도`라는 엉뚱한
보정이 들어간다. 뉴욕(-74°)이면 약 14시간이 어긋난다.

라이브러리 보정을 끄고 `packages/core/src/saju/timezone.ts`에서 직접 계산한다.

```
출생지 벽시계 시각 --(IANA 표준시간대)--> UTC --(경도 × 4분)--> 출생지 진태양시
```

IANA 데이터를 쓴 덕에 **과거 규칙까지 자동 반영**된다. 실검증에서 시주가 실제로 바뀐다.

| 사례 | 보정 전 | 보정 후 |
|---|---|---|
| 뉴욕 1990-05-12 13:45 | 丁未 | 丙午 |
| 서울 1988-06-15 10:00 (서머타임) | 癸巳 | 壬辰 |
| 서울 1957-06-15 | — | UTC+9:30 = +8:30 기간 + 서머타임 |

출생지는 23개 로케일 주요국을 덮는 55개 도시(`birthplaces.ts`). 경도가 벌어지는
미국·중국·인도네시아 등은 도시를 나눴다 — 경도 15°는 시주 한 칸이다.

**naminglink는 기존 경로 그대로**(`birthplace` 미전달 시 동작 불변).

### v2 — 성별·배우자성

전통 명리는 배우자 자리를 성별로 다르게 본다. 밝히지 않으면 항목을 빼고 **남은 비중을 재정규화**
한다 — 0점 처리하면 성별을 안 밝힌 사용자가 부당하게 낮은 점수를 받는다.

### v3 — 지장간 + 월령 (`b3a8096`)

오행 보완도가 표면 여덟 글자의 **개수**만 세고 있었다. 개수 대신 **세력**을 쓴다.

- **지장간** — 지지가 품은 천간을 일수 비례로. 寅은 겉으로 木이지만 안에 戊(土)·丙(火)을 품는다
- **월령** — 왕상휴수사로 계절 배수(旺 1.5 ~ 死 0.5). 환절기(辰未戌丑)엔 土도 旺
- 천간 지분 1.0, 지지도 품은 천간에 나눠 총 1.0 (천간과 지지에 같은 무게)

실측으로 판정이 뒤집힌다: 1975-10-03 사례는 가장 부족한 오행이 **土 → 火**로 바뀐다.
같은 날짜라도 木 세력이 봄 3.00 대 가을 0.55.

### v4 — 읽을거리 (`e32cbf6`)

점수만 나열하면 읽을 것이 없다. 강점/눈여겨볼 점(최고·최저 항목을 문장으로), 사주 원국
4주(한자+독음), 오행 세력 막대, 일간 성향(천간 10종), 띠 성향(십이지 12종)을 더했다.

곁들여 사주 계산을 사람당 한 번으로 줄였다 — 두 엔진이 각자 만세력을 돌리고 있었다.

### v5 — 십신 (`25e73f1`)

관계 서술이 얇았다. 명리에서 관계를 읽는 도구가 십신(十神)이다.

- 오행 생극만 보면 둘뿐이지만 음양을 더하면 열 가지. 같은 재성도 **정재와 편재는 결이 다르다**
- **방향이 있다.** 甲이 己를 보면 정재(남성의 배우자 자리), 己가 甲을 보면 정관(여성의 배우자
  자리). 한쪽만 끌리는 관계가 이 비대칭으로 설명된다
- 두 사람을 마주 놓으면 **세 모양으로 접힌다** — 닮은 사이 / 키우고 피어나는 사이 / 다잡는
  사이. 한쪽이 생하면 상대는 반드시 식상으로 보기 때문이다. 앞의 둘은 방향까지 나온다
- 배우자성도 오행에서 십신으로. 정재·정관 2점, 편재·편관 1점 양방향 합산 → 5단계

### 검증 스크립트 (재사용)

- `packages/core/scripts/verify-birthplace.ts` — 진태양시 보정으로 시주가 바뀌는지

## 4. 법적 문서 · 푸터 (`e32cbf6`, `3dfa46c`, `d080545`)

광고를 붙이려면 개인정보처리방침 페이지가 있어야 하는데 아무것도 없었다.

- `/privacy`, `/terms` 신설. naminglink 것을 재사용하지 않았다 — 파는 것이 없고 입력을
  저장하지 않아 "수집하지 않는다"가 방침의 뼈대가 된다. 문서 구조 자체가 다르다
- **푸터는 naminglink와 같은 구조.** 처음에 naminglink를 보지 않고 새로 설계했다가 지적받고
  다시 만들었다. 가운데 정렬 · 정책 링크 한 줄 · 사업자 정보 두 줄(모바일 일곱 줄) · 저작권.
  `tone="light"`가 밝은 글씨라는 의미까지 맞췄다
- 푸터는 **레이아웃이 아니라 각 페이지**에 둔다. 레이아웃은 searchParams를 못 받아 `?lang=`을
  모르고, 그대로 두면 한국어 화면에 영어 푸터가 붙는다. 법적 페이지 제목도 같은 이유로
  `generateMetadata`로 옮겼다
- **미저장 안내·면책은 본문에.** 푸터 작은 글씨는 읽히지 않는데 이 서비스에서 "저장하지
  않는다"는 각주가 아니라 성격 자체다. 랜딩·입력·결과 세 화면 모두에 카드로 둔다

### `0feaf83` 개발 모드 CSP

## 작업 방식 메모

- **dev 서버는 사용자가 띄운다.** 포트로 프로세스를 찾아 죽이지 말 것 — 사용자 서버를 죽인
  사고가 있었다. 검증이 필요하면 `:3099` 같은 빈 포트를 쓴다
- 사전 문구를 스크립트로 치환할 때 `\n`이 실제 줄바꿈으로 들어가 빌드가 깨진 적이 있다.
  문자열 이스케이프가 섞인 치환은 Edit로 하는 편이 안전하다
- 설치는 **pnpm 고정**(`workspace:*` 프로토콜 + 락파일 일원화). 스크립트 실행은 npm도 무방
  (`npm run dev` = naminglink :3001, `npm run dev:inyeon` = inyeonlink :3002)
