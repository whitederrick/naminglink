### 어떻게 했나

### 병렬 처리에 대해

기존 메모리에 "사전 수정 에이전트 병렬 금지"가 있었는데, 그 금지의 근거는 **여러 에이전트가 한

공유 파일인 등록부(`i18n.ts`)만 사람이 마지막에 한 번 썼다.

### 검사 스크립트 (`scripts/verify-i18n.ts`)

타입은 키 집합·중첩까지만 본다. 정작 화면을 깨뜨리는 것은 타입이 못 보는 쪽이다:

## 2. 인연링크 랜딩을 naminglink와 같은 꼴로 (`9e3fd6e`)

요구는 **"데스크탑·모바일 모두 두 페이지가 쌍둥이처럼 보일 것"**이었다.

### 맞춘 것

로고 56px(그림자·모서리 포함) · 워드마크 `Inyeon-Link` · 언어 버튼 `h-10 w-[4.8rem]` `gap-2` ·
더보기 목록 6열 · 헤더와 본문에 **같은 `grid-cols`** · 본문 상단 `lg:pt-[clamp(6.5rem,14vh,8.5rem)]` ·
© 줄 `Inyeon-Link(인연 링크) · Provided by Platforest`.

언어 배치도 naminglink와 같다 — 기본 줄 6개(`ko·en·ja·zh·de·es`) + 더보기 17개.
`LocaleSwitcher`는 서버 컴포넌트로 바꿔 `<details>` 하나로 처리하므로 클라이언트 JS가 늘지 않는다.
링크는 naminglink와 달리 상대 경로(`?lang=`)라 하위 페이지에서 언어를 바꿔도 보던 화면에 남는다.

### 값을 그대로 베끼면 안 되는 자리 (전부 실제로 어긋나 되돌렸다)

| 자리 | naminglink | 인연링크 | 이유 |
| --- | --- | --- | --- |
| 왼쪽 열 칸 높이 | `lg:grid-rows-[5.75rem_12rem_6.25rem]` | 쓰지 않음(margin `mt-5`) | 그쪽 문구 길이에 맞춘 값이라 여기선 빈 칸이 남아 부제·버튼이 밀린다 |
| 오른쪽 열 최소 높이 | `lg:min-h-[18rem]` | `content-start` | 그쪽 카드는 `h-[7.25rem]` 고정이라 괜찮다. 여기 박스는 높이가 내용에 따라 달라 **그리드 행이 늘어나며 박스 하단에 빈 공간**이 생겼다 |
| 오른쪽 열 폭 | `600px` | `34rem(544px)` | 600px에서는 한국어 외 언어에서 왼쪽 제목이 밀렸고, 480px은 카드가 너무 좁았다 |
| 푸터 아래 여백 | `!pb-4` | `!pb-0` | 정책 링크가 5개(로그인 포함)/4개라 접히는 줄이 달라, **값을 맞추면 오히려 높이가 어긋난다** |

**헤더와 본문의 `grid-cols`는 반드시 같이 고칠 것.** 한쪽만 바꾸면 언어 선택기가 오른쪽 카드 열과
어긋나고 더보기 목록도 엉뚱한 폭으로 열린다.

### 배지 상자 제거

랜딩 첫 줄의 배지(`dictionary.tagline`)를 화면에서 뺐다. 한 줄짜리 상자라 언어마다 폭·줄 수가 크게
달라져 그 아래 제목·부제·버튼이 통째로 밀리는 것이 23개 언어에서 가장 큰 불일치 요인이었다.
**문구 자체는 PDF 리포트(`lib/pdf/compatibility-report.tsx`)가 계속 쓰므로 사전 키는 남겼다.**

### 푸터 값 겹침

DB(`site_contents`의 `footer.global`)에 저장된 값에 **항목명이 들어 있다** — `"통신판매업 신고 준비 중"`,
`"사업자등록번호 준비 중"`. 라벨과 합쳐지면 "통신판매업 통신판매업 신고 준비 중"이 됐다.
값이 라벨로 시작하면 떼어 내고, 한국어가 아니면 로케일 표기로 바꾼다. © 줄의 제공사는 등록 상호가
아니라 법인격 접두사(`(주)`·`주식회사`)를 뗀 이름을 쓴다.

## 3. naminglink 결제 전 고지 23로케일 (`feea11c`)

### 무엇이 문제였나

`CheckoutConsent.tsx`가 `!locale || locale === "ko" ? KO : EN`이었다. **한국어가 아니면 22개 언어
구매자에게 전부 영어로 나갔다.** 약관 4종은 이미 23개 언어가 있는데 정작 결제 직전 화면만 빠져 있었다.

전자상거래법 제17조 제2항의 청약철회 제한은 사업자가 *"철회가 불가하다는 사실을 소비자가 쉽게 알
수 있는 곳에 표시하고 동의를 받는 조치"* 를 했을 때만 성립한다. 구매자가 읽지 못하는 언어로 띄운
고지를 그 조치로 보기는 어렵다.

### 어떻게 했나

- `lib/checkout-consent/`로 옮기고 로케일당 파일 하나(`types.ts` + 23개 + `index.ts`).
- 등록부를 **`Record<Locale, ConsentCopySet>`** 로 잡았다(`Partial`이 아니다). 로케일을 늘리면
  컴파일이 깨져 빠뜨릴 수 없다 — 한 언어라도 비면 그 언어 구매자에게 조치를 하지 않은 것이 되므로
  조용히 폴백하게 두지 않는다.
- 클라이언트 번들에 실린다(`CheckoutConsent`가 `"use client"`). 로케일당 1.5KB 남짓, 전체 30KB
  수준이다. **약관 본문(`lib/legal-content`)과 혼동하지 말 것** — 그쪽은 문서 단위라 훨씬 크고 서버 전용이다.
  결제 직전에 반드시 보여야 하는 문구라 지연 로딩으로 비우지 않았다.

### 검사 스크립트 (`scripts/verify-checkout-consent.ts`)

| 검사 | 왜 |
| --- | --- |
| `info` 줄 수(디지털 6 / 주문제작 7) | 상품정보 고시가 요구하는 항목 수 |
| `**강조**` 쌍 수 | 하필 "철회가 제한된다"는 핵심 문장을 감싼다 |
| 한글 잔존 | 번역 누락 |
| 빈 값 | 고지 누락 |

실행: `apps/naminglink`에서 `node_modules/.bin/tsx scripts/verify-checkout-consent.ts`
결과: **23개 × 2종 통과.**

### 번역 원칙과 남은 것

한국어 원문이 기준이다. 영어판이 축약했던 도장 배송 조건(원문 "국내는 택배, 해외는 국제배송" →
en "International shipping outside Korea")은 21개 언어 모두 **원문대로 두 경로를 다 실었다.**
여러 에이전트가 독립적으로 같은 지점을 지적했다.

**남은 것: 영어판(`en.ts`)만 여전히 축약형이다.** 원문에 맞출지 결정 필요.

## 4. naminglink 사업자 정보 서버 렌더 (`c0754b4`)

### 무엇이 문제였나

`SiteFooter`가 클라이언트 컴포넌트라 마운트 후 `/api/site-content?kind=footer`로 값을 채운다.
서버가 보내는 HTML에는 폴백("사업자등록번호 준비 중")이 들어가고, 크롤러가 보는 것도 그것이다.
사업자등록번호·통신판매업 신고번호는 전자상거래법이 요구하는 표시 항목인데 **표시 의무가
자바스크립트 실행에 걸려 있었다.**

### 어떻게 했나

루트 레이아웃(서버)이 `getPublishedFooterContent()`로 읽어 `FooterContentProvider`(컨텍스트)로
내려 주고, `SiteFooter`가 그것을 **초기 상태**로 쓴다. 서버 HTML부터 실제 값이 들어간다.

- 값이 내려오면 API 호출을 **건너뛴다.** 페이지마다 같은 값을 받으러 왕복하던 것도 없어진다.
- DB 읽기 실패 시 `null` → 예전 경로(API)로 떨어진다. `.catch(() => null)`로 레이아웃이 통째로
  죽지 않게 했다.

**컴포넌트를 서버로 바꾸지 않은 이유**: `ServiceShell`·결과 화면 등 **클라이언트 컴포넌트 10곳이
직접 import** 하고 있어 전환하면 그 호출부를 전부 재구성해야 한다. 값만 서버에서 내려 주면 같은
결과를 얻는다.

## 5. 이번에 배운 것 — 측정 방법

작업 중 **"naminglink 푸터가 사업자등록번호를 '준비 중'으로 보여 준다"고 잘못 진단했다.** `curl`로
받은 SSR HTML만 보고 판단했는데, 그 값은 마운트 후 클라이언트가 채우는 것이었다(4절이 바로 그 문제다).

- `curl` HTML로는 **클라이언트가 채우는 값**을 볼 수 없다.
- 여백·정렬·줄간격은 더더욱 볼 수 없다. 이번 랜딩 정합 작업에서 로고 크기·배지 높이·줄간격·박스
  하단 여백이 하나씩 뒤늦게 드러난 것도 같은 이유다.
- Chrome 확장이 연결돼 있어야 실제 화면을 볼 수 있다(이번에는 미연결이라 못 봤다).

## 6. 배포 후 확인이 필요한 것

1. **결제 고지 상자를 한국어 외 언어로 열어 볼 것.** 텍스트 검증은 통과했지만 아랍어 RTL과
   태국어·크메르어처럼 띄어쓰기가 없는 언어에서 항목명이 어떻게 접히는지는 눈으로 봐야 한다.
2. **인연링크 랜딩의 언어 전환.** 밀림은 줄었지만 남아 있다. 다음 후보는 제목의 `max-w-[20ch]`와
   가장 긴 번역 기준 `min-h`다.
3. 인연링크 푸터·랜딩이 실제로 naminglink와 같은 높이로 보이는지.
