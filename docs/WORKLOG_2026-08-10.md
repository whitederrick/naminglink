# 2026-08-10 — 애드센스 정책 위반에서 재심사 준비까지

_커밋 10개 배포 완료. 코드 쪽 재심사 준비는 끝났고, 남은 것은 서치 콘솔·애드센스 콘솔 작업이다._

---

## 0. 무엇이 왜 시작됐나

애드센스 통보: **「정책 위반 — 가치가 별로 없는 콘텐츠」**. 대상은 naming-link(콘솔에 남은
유일한 사이트).

실측으로 본 상태:

    색인 대상 864개  ←  그 뒤의 고유 문서는 36편
    서치 콘솔        552개 중 460개 색인 제외 · 424개는 크롤링조차 안 함

**원인은 「번역이 부족한 것」이 아니었다.** 고유 문서 36편을 864개 주소로 낸 것이다.
`/guide/hanja/sa`는 8,000자 중 **한글 3,436 + 한자 984가 24벌 모두 같은 글자**였는데,
canonical은 로케일마다 자기를 가리키고 hreflang은 24개를 실었다 — 한 벌짜리 화면에 대한
거짓 선언이다.

`docs/issues/`의 08-08 서치 콘솔 내보내기가 그 자리를 정확히 짚고 있었다. 다만 그 크롤링
날짜(08-04~06)는 **안내 문서 23로케일 번역을 배포한 08-09보다 앞이라**, 그 데이터로 판단할 수
있는 것과 없는 것을 갈라야 했다.

---

## 1. 이 서비스는 두 갈래다 (사용자 설명)

| 갈래 | 서비스 | 필요한 언어 |
|---|---|---|
| 한국어 전용 | 한글 이름 → 한자 매핑 · 한글 이름 → 글로벌 이름 | **한국어만** |
| 글로벌 전용 | 글로벌 이름 → 한글 발음 · 글로벌 이름 → 한글 이름 | **23개 언어, 한국어 불필요** |

> 「어차피 쓰지도 못하는 서비스인데 글로벌 번역이 되어 있는 거 아니야?」

korean 갈래 안내를 22개 언어로 옮겨 둔 것은 **읽고 나서 갈 곳이 없는 문서**를 늘린 것이었다.
그래서 방향이 「더 번역한다」가 아니라 **「거짓 선언을 거둔다」**로 정해졌다.

**화면은 아무것도 지우지 않았다.** 거둔 것은 선언뿐이다.

---

## 2. 배포한 것 (커밋 순)

### `75d8247` 한국어 전용 화면을 한 주소로

로케일 주소 → **301**, canonical 한 벌, hreflang 없음, sitemap 한 줄.
로케일 파일에서 korean 갈래 6편 × 22개 언어 = **9,726줄 삭제.**

**강제 장치:** `doc-content/keys.ts`의 `GlobalDocKey`. 로케일 파일에 되살리면 `error TS2353`.
번역기도 `KO_GLOBAL_DOCS`로 거른다 — **거기서 안 거르면 다음 번역이 그대로 되살린다.**

### `a9f0d27` 갈래를 글로 밝히고, 글로벌 화면에서 한국어를 내림

구조는 갈라 두었는데 **어느 쪽도 반대편의 존재를 말하지 않았다.** 소개·안내 허브에 갈래
설명을 23개 언어로 넣었다.

글로벌 화면의 한국어 차단은 **네 갈래를 다 막아야 한다** — 주소·`?lang=ko`·**접속 국가 KR**·
둘의 조합. 세 번째가 놓치기 쉽다: 이 서비스는 접속 국가가 브라우저 언어보다 앞선다.

### `7bdbe52` 배포 주소 차단 + 언어 목록 한 벌

`robots.ts`가 **설정된 `NEXT_PUBLIC_SITE_URL`만** 보고 요청 호스트는 안 봤다. 실 도메인을
넣는 순간 그 판정이 거짓이 되어 `<app>.vercel.app`이 `Allow: /`를 냈다 — **네 앱 중 셋이
크롤링 가능한 사이트 복사본을 하나씩 갖고 있었다.**

### `662b863` 초성 13편 sitemap 등재

각 2,600단어짜리 이 사이트만의 자료인데 sitemap에 없었다. 조건은 **라우트와 같은 함수**
(`indexableChosungSlugs`)에서 온다 — 따로 적으면 404 주소를 색인하라고 내밀게 된다.

### `3efccff` 미지원 언어 광고 코드 제거 + 입력 배너 제거

구글 지원 49개 언어에 **kk·km·mn·uz가 없다.** 광고가 채워지는지와 무관하게 코드를 두는 것
자체가 위반이다. **GAM 보상형도 같은 대상**(정책 문서가 「Google publisher products」다).

입력 화면 고정 배너 둘을 걷어냈다 — 폼은 아직 아무것도 발행하지 않은 화면이고,
`consent_card`는 제출 버튼 옆이라 실수 클릭 배치였다. **승인 뒤에도 되돌리지 않는다**(사용자
결정). 결과 화면 광고는 **결과가 실제로 그려질 때만** 나간다.

### `4fe74a8` 무접두 주소 제거 + 내부 링크

    /                  → 302 → /{감지}      동적 판정은 이 한 곳뿐
    /about /guide …    → 308 → /en/{경로}   고정
    한국어 전용          무접두 유지
    ?lang=             경로형 301 · lang만 지우고 나머지 쿼리는 보존

**하위까지 감지 302로 두지 않은 이유**: 무접두 주소가 「영원히 리다이렉트되는 URL」로 남아
구글이 계속 크롤한다 — x-default URL도 발견 경로다.

그리고 **내부 링크가 옛 주소를 계속 재공급**하고 있었다. `localePath()`가 경로 성격을 몰랐다.
호출부 59곳을 감사하니 **58곳이 링크, 1곳이 선언** — 검토자들이 제안한 3분리는 이미 되어
있었고 첫 번째만 규칙을 모르고 있었다.

### `aae6763` 정책 링크 + 린트

약관 넷이 `<button>`이라 **크롤러가 정책 URL을 따라갈 길이 없었다.** 페이지 이동으로 바꾸면
「서비스 흐름 중 페이지 전환 금지」와 부딪히므로, **진짜 `href`를 두고 클릭만 가로챈다.**

린트 오류 1 + 경고 9 → 0. `alt` 경고 셋은 오탐이었다(react-pdf `Image`).

### `95d5e68` 기존 안내 강화 + 자료 상태 공개

**새 URL 0개.** 864→365로 줄여 놓고 곧바로 문서를 늘리면 「정리했다」는 신호를 스스로 지운다
(외부 검토 의견). 기존 문서에 절을 더했다 — 성 스물여섯 개(코드 값 그대로), 여권 로마자와
방향이 반대라는 것, 그리고 **자료·번역 상태를 있는 그대로**(기계 번역이며 원어민 감수 미실시).

### `afe990f` 쿼리 붙은 주소의 글로벌 전용 판정

`/en/global-to-korean?mode=transliteration`이 **301되는 한국어판을 hreflang으로 선언**하고
있었다. `matches()`가 쿼리를 안 뗐다. 외부 검토가 잡았고, 검사기도 못 잡고 있었다
(표본에 없었고 `toBase()`가 쿼리를 버렸다).

### `0e8996c` 사주·드림 로케일 재생성 + 형제 앱에 안 온 고침

어제부터 남아 있던 빨간불을 껐다. 그 과정에서 **`GLOSSARY_ROMAN`이 그 앱 용어가 아니라는
것**이 드러났다 — 드림 폴백 36건이 태몽·해몽 한 낱말 때문이었고, 채우니 1건이 됐다.

## 5. 되풀이하지 않으려면

### 검사기가 다른 것을 보고 있을 수 있다

하루에 셋이 나왔다.

- **다른 사이트** — sitemap `<loc>`가 절대 주소라, 로컬을 검사하라고 시켰는데 운영을 훑었다
- **다른 화면** — `toBase()`가 쿼리를 버려 `?mode=` 화면의 결함을 못 봤다
- **없는 것** — 본문이 자료로 옮겨진 뒤 `page.tsx`를 계속 읽어 **숫자를 0개 대조**했다

**고침을 일부러 되돌린 빌드로 확인하는 것**이 가장 확실하다. hreflang 결함에서 그렇게 했다.

### 내가 쓴 문장이 번역기를 깨뜨린다

두 번, 각 15분. 설명과 링크를 한 문단에 넣었고, 「자리표시자」라는 낱말을 본문에 썼다.
번역기 결함이 아니라 **원문이 잘못 쓰인 것**이다. `verify-doc-source-safe`를 번역 **전에**
돌릴 것 — 1초다.

### 복제 앱은 고침이 원본으로도 안 돌아온다

`chunkWithRetry`가 naminglink에만 없었다. `verify-guide-numbers`는 naminglink에서만 고쳐져
있었다. **`GLOSSARY_ROMAN`이 그 앱 용어가 아니었다.** 「복사해 갈 때 빠진다」만 경계하면
이 방향을 놓친다.

### 가짜 빨간불을 내는 검사는 없느니만 못하다

`verify-doc-source-safe`에 「링크가 든 긴 문단」 규칙을 넣었다가 뺐다 — 잘 번역돼 있는 기존
문단 수십 개가 걸렸고, 근거 없이 정한 길이였다.

## 6. 남은 일

### 콘솔 작업 (코드로 못 함)

1. 서치 콘솔 sitemap 재제출 + 「중복 페이지」·「발견됨-색인 안 됨」 수정 확인 요청
2. URL 검사로 `/`·`/en/about`·`/guide/hanja/sa`·`/en/guide/how-global-to-korean` 확인
3. **구글 선택 canonical = 선언 canonical** 이 확인된 뒤 애드센스 재심사
4. 통과 전까지 인연·사주·드림은 애드센스 콘솔에 **추가하지 않는다**

3번의 순서가 중요하다. 구조를 바꿔도 **구글이 아직 옛 상태를 들고 있어서**, 재크롤 전에
요청하면 심사자가 예전 모습을 본다.

### 코드 쪽 남은 것

- **첫 화면이 204단어**다. 오늘 한 일은 중복을 없앤 것이지 분량을 늘린 것이 아니다.
  재심사에서 다시 걸린다면 여기일 가능성이 크다. `landingCopies`가 손으로 관리하는 23벌이라
  번역기가 없다
- 승인·색인 안정화 뒤에 글로벌 안내 문서 추가(지금은 URL을 늘리지 않는다)
- `audit-verifiers`의 네트워크 검사 둘이 420초 제한에 걸릴 때가 있다(부하 시)

### 재심사 판정 기준 — 기간이 아니라 조건

    미지원 언어 HTML에 구글 광고 코드   0건      ← 검사기
    내부 링크 3xx                      0건      ← 검사기
    sitemap URL 3xx                    0건      ← 검사기
    canonical·hreflang                 전부 200 ← 검사기
    hreflang 묶음                      상호 참조 ← 검사기
    내부 링크의 ?lang=                  0건      ← 검사기
    구글 선택 canonical = 선언          일치     ← **콘솔에서 사람이**

앞의 여섯은 자동으로 센다. 마지막 하나만 서치 콘솔에서 확인하면 된다.
