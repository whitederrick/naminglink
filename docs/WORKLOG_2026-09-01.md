## 1. 「프로덕션에 올라갔다」가 사실이 아니었다

어제 워크로그 마무리가 이렇게 시작한다.

> **해몽 사전 재구축이 프로덕션에 올라갔다.**

```
$ git status -sb
## main...origin/main [ahead 4]
```

`3c6531e` · `366fcdc` · `cb8e4f8` · `1271c0c` 넷이 **로컬에만** 있었다. origin은 `09aa0e5`
(전량 폐기 결정 문서)에 멈춰 있었고, 운영 화면은 **옛 218개 사전**을 그대로 쓰고 있었다.

커밋·푸시·배포는 셋 다 다른 사건인데 「커밋했다」로 일이 끝난 느낌이 든다. CLAUDE.md §26에
적었다 — **「배포됐다」를 적기 전에 `git status -sb`를 본다.**

## 2. 문서가 틀린 것은 숫자 5건이 아니었다

어제 남긴 빨간불은 `verify-guide-numbers`의 ✗ 5건(「아홉 갈래」)뿐이었다. 그런데 문서를
실제로 읽으며 v2 데이터와 대조하니 **글로 적힌 사실이 여럿 거짓**이었다.

| 문서가 적은 것 | v2의 사실 | 누가 잡았나 |
| --- | --- | --- |
| 「아홉 갈래」 | **여덟** (`number` 갈래가 비었다) | `verify-guide-numbers` |
| 「좋은 쪽이 절반을 넘는다」 | **29.6%**. 가장 많은 것은 「갈리는 것」(34.5%) | 아무도 |
| 「뜻이 하나뿐인 경우가 대부분」 | **61%가 여럿** (678개 중 411개) | 아무도 |
| 「뱀을 품는 것과 물리는 것은 정반대」 | **둘 다 길하다** — 원문이 그렇게 적혀 있다 | 아무도 |
| 「높은 곳에서 떨어졌다」가 걸린다 | **안 걸린다** — `추락` 표제어가 v2에 없다 | 아무도 |
| 「복숭아·밤처럼 열매」 | `밤`이 v2에 없다 | 아무도 |
| 「빛깔과 수」 | `수` 갈래가 비었다. 빛깔은 둘(푸른색·붉은색) | 아무도 |
| 「사물·동물·자연이 가장 두꺼운 셋」 | **사물·행위·동물** (233·131·82) | 아무도 |
| 「행위 — 쫓기다·떨어지다·날다」 | 셋 다 v2에 없다(목욕·잔치·매맞음이 실물) | 아무도 |
| 두 원문(주공해몽·밀러)을 **한 번도 안 밝힘** | 화면은 출처를 갈라 보여 준다 | 아무도 |

**숫자는 자리표시자(`{symbolTotal}`)라 저절로 따라갔다. 글은 안 따라간다.** 그리고 이 중
관문이 보는 것은 숫자뿐이다. CLAUDE.md §26에 §25의 새 얼굴로 적었다.

### 뱀 예시가 가장 나쁘다

「뱀을 품에 안는 것과 물리는 것은 정반대」는 문서 **넷**의 대표 예시였다(about ·
one-symbol-many-meanings · how-to-write · good-and-bad). v2에서 실제로 재 보면:

```
뱀이 품속으로 들어옴      [positive]  귀한 자식을 낳을 조짐
뱀이 사람에게 덤벼듦      [positive]  큰 재물을 얻을 조짐   ← 「물렸다」가 여기로 간다
```

**둘 다 길하다.** 주공해몽은 뱀이 덤벼드는 것을 재물의 조짐으로 읽는다.

`verify-dream-context-parity`는 이 자리를 **통과시켰다** — 그 검사기는 「뜻이 갈리는가」를
묻지 「반대인가」를 묻지 않기 때문이다. **「다르다」와 「반대다」는 다른 주장이다.**

대신 실제로 반대인 짝으로 바꿨다(둘 다 엔진으로 확인함).

```
해가 막 떠오름 [positive] 집안이 번창   ↔  해가 떨어짐 [negative] 부모를 잃을 근심
돼지를 잡음   [positive] 길한 조짐     ↔  돼지가 저절로 죽음 [negative] 흉한 조짐
```

## 3. 23개 로케일 — 한국어 30자리 · en 10편 · 나머지 21개

순서는 `docs/I18N_DOC_CONTENT.md`대로 **① 한국어 → ② 영어 → ③ 21개**다.

1. **ko 30자리**를 고쳤다. 치환마다 「찾은 횟수가 정확히 1인가」를 세고, 하나라도 어긋나면
   **아무것도 쓰지 않고 멈추게** 했다(§10 #44 — `replace`는 실패를 조용히 넘긴다).
   첫 판은 여러 줄 치환 9건이 전부 0건이었다 — **CRLF**다(§7 · §10 #45). LF로 펴서 고치고
   CRLF로 되돌리게 바꾸니 30건 전부 붙었다.
2. **en은 바뀐 10편만 지우고 `--fill-en`**으로 다시 만들었다. 안 바뀐 문서(guide ·
   how-matching-works · no-storage · what-we-do-not-do · notice · contact)는 건드리지 않았다.
3. **21개를 7묶음으로 병렬**로 돌렸다.

### en을 읽어 보고 나서 21개를 돌렸다 — 그 줄이 값을 했다

`--fill-en`이 만든 영어가 서비스를 **1인칭 「I」**로 가리키고 있었다(「I did not create…」).
지우기 전 en에는 그런 자리가 **0건**이었고 전부 「we」였다. 한국어 원문은 주어가 없는
존댓말이라 모델이 매번 다르게 고른다.

**en은 21개 언어의 본이다.** 그대로 돌렸으면 어투가 **스물한 번 복제**됐을 것이다.
13자리를 고치고 나서 21개를 돌렸다. 검사기는 이것을 못 잡는다 — 문법도 맞고 한글도 안 남는다.

### 번역에서 터진 것 셋

| 무엇 | 어떻게 알았나 | 고침 |
| --- | --- | --- |
| **km이 통째로 죽었다** | 백그라운드 도구는 「exit 0」이라 알렸다 — 내가 명령 끝에 `echo`를 붙여 **종료 코드가 `echo`의 것**이 됐다(§10 #3의 새 얼굴). 로그 본문에 `fetch failed`가 있었다 | km만 다시 돌림 |
| **km의 한 문단이 크메르어가 아니라 중국어로 나왔다** | `verify-locale-script` — 「han 문자가 96%다」 | 영어 원문을 다시 써서 세 판 만에 잡음 |
| **zh의 한 줄이 한글 45%** | 같은 검사기 | 영어 예시에 **로마자 표기**를 넣어 한글 비율 자체를 낮춤 |

세 번째가 구조적이다. 「한 글자짜리 상징」을 설명하는 줄은 본디 한글 예시가 많아 임계값
언저리에서 돈다 — 옛 벌은 **아슬아슬하게 통과했을 뿐**이다. 로마자를 넣어 어느 언어로
옮겨도 그 언어의 문자가 다수가 되게 했다.

## 4. 어제 커밋에 들어 있던 결함 셋

문서를 고치다 데이터 쪽을 보게 되면서 나왔다. 셋 다 **어제 커밋된 것**이다.

### 4-1. 「자주 찾는 상징」이 빈 목록이 됐다

상징을 하나도 못 찾은 결과 화면은 대표 상징 아홉을 보여 준다.

```ts
DREAM_SYMBOLS.filter((s) => (s.weight ?? 1) >= 3).slice(0, 9)
```

**v2는 678개 전부가 `weight: 1`**이다(조립기가 그렇게 박아 넣는다). 목록이 빈 배열이 되어
그 절이 화면에서 통째로 사라졌다. tsc·검사기·하니스 어느 것도 안 잡는다 — CLAUDE.md §25와
정확히 같은 자리이고, **같은 교체에서 두 번째**다.

되살릴 때 **새로 고르지 않았다.** 새로 고르면 그것은 내가 지어낸 목록이 된다. 옛 사전에서
`weight: 3`이던 아홉 중 v2에 살아남은 일곱을 그대로 옮겼다 —
**돼지 · 뱀 · 용 · 똥 · 죽음 · 돈 · 이.** (「이빨 빠짐」·「추락」·「쫓김」은 두 원문 어디에도
표제어가 없다.)

그리고 **판정을 한 곳에 모았다**(`POPULAR_SYMBOLS`, §6 — 규칙이 두 곳에 적히면 하나만
고쳐지는 날이 온다). 안내 문서의 `{popularSymbolCount}` 자리표시자는 **아무도 채우지 않아
23개 언어 전부에서 그 문단이 한 번도 안 그려지고 있었다** — 못 채운 자리표시자가 있는
블록은 통째로 빠지기 때문이다. 그것도 함께 채웠다.

### 4-2. 소스에 진짜 NUL 바이트가 박혀 있었다 — 세 번째다

```
$ file scripts/build-dream-dictionary-v2.mjs
scripts/build-dream-dictionary-v2.mjs: data          ← 텍스트가 아니다
```

`grep`은 「Binary file matches」만 내고 내용을 안 보여 준다. §10 #30·#43과 **정확히 같은
사고**이고, 그 두 항목이 이미 CLAUDE.md에 적혀 있었다.

### 4-3. 그 NUL 때문에 `EXPLICIT_IDS`가 한 번도 안 맞았다

```
symbolKey()      "iron" + NUL(0x00) + "다리미"
EXPLICIT_IDS 키  "iron" + 공백(0x20) + "다리미"
```

**구분자가 달랐다.** 그 표는 갈라 놓은 상징의 주소(`/dream/symbol/iron`)를 못 박으려고
있는 것인데 **한 번도 조회에 맞은 적이 없다.** 지금 id가 맞는 것은 slugify의 중복 접미사가
우연히 같은 순서를 냈기 때문이고, 추출 파일이 하나 늘면 조용히 뒤바뀐다.

셋 다 `JSON.stringify([en, ko])`로 감싸 고쳤다(§22 곁가지에 이미 적혀 있던 방법이다).
그리고 **관문 둘을 함께 남겼다** — ① `EXPLICIT_IDS`에 적혔는데 한 번도 안 쓰인 키가 있으면
멈춘다 ② `POPULAR_SYMBOL_IDS`에 적혔는데 사전에 없는 상징이 있으면 멈춘다.
**둘 다 일부러 망가뜨려 exit 1이 나는 것을 확인**한 뒤 남겼다.

### 곁가지 — 조립기를 한 단계만 돌려 별칭 2,072개를 날릴 뻔했다

`build-dream-dictionary-v2.mjs`는 `aliases: []`로 비워 쓰고,
`build-dream-match-tables-v2.mjs`가 km 파일에서 별칭을 채운다. **앞엣것만 돌렸다.**

```
git diff --stat →  644 insertions(+), 3360 deletions(-)
```

§10 #49에 적어 둔 「diff 크기가 내가 넣은 항목 수와 비례하는가」가 그 자리에서 멈춰 세웠다.
`git checkout`으로 되돌리고, **둘을 이어 돌리면 바이트까지 같다**는 것을 먼저 확인한 뒤
스크립트를 고쳤다.

## 7. 남은 빨간불 2건 — 둘 다 오늘 것이 아니다

스윕의 빨간불 셋 중 하나(`verify-locale-script`)는 고쳐서 초록이 됐다. 남은 둘은 **HEAD
에서도 빨간불**임을 확인했다.

### ① `audit-dream-ownterms-multiword.mjs` — **폐기된 사전을 검사하고 있다**

```js
const old = JSON.parse(readFileSync(path.join(LIB, "dream-symbols.data.json")));
```

이 파일은 **옛 218개 사전**이고, 08-31 교체 뒤로 제품 코드는 아무도 읽지 않는다.
검사 대상인 `tooth-fall`·`naked`·`ancestor`는 v2에 없는 id다. 08-31 워크로그가 「그 사전
자체가 교체됐으므로 이제 무의미할 수 있다」고 적어 둔 바로 그 자리다.

**손대지 않았다** — 지우는 것은 되돌릴 수 없고 사용자가 결정할 일이다. 같은 처지인 것이
`apps/dreamslink/scripts/audit-dream-match-real-sweep.mts`이다.

### ② `verify-rendered-locale.mjs` — **일부러 남긴 한국어 예시를 잡는다**

여섯 로케일(ja·es·ru·th·vi·ar) 전부 같은 잎 하나다 —
`guide/how-matching-works`의 요약에 든 **「특별할」**. 이 문서는 「낱말 안에 우연히 들어간
글자」를 설명하는 곳이라 **한국어 예시가 있어야 뜻이 선다.** HEAD에서도 여섯 다 똑같이 1건이다.

고치려면 검사기 쪽에 예외 목록이 필요하다(§11 — 얼리려면 목록으로). **오늘 범위 밖이라
그대로 두고 적어만 둔다.**
