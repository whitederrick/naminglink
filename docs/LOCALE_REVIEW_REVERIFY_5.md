같은 커밋이 스스로 *「힌트는 그물이지 울타리가 아니다」*라고 적어 놓고 바로 그 구멍에

## 2. 고친 것

### 2.1 P0 · 탐지기가 raw SQL 을 안 봤다

`scripts/audit-verifiers.mjs` — `SIDE_EFFECT_HINTS`

그물을 한 칸 조이는 대신 **DB 에 직접 붙는 것 자체**를 묻습니다.

```
pg 임포트 · new Client(          DB 에 직접 붙는 것으로 보인다
raw SQL 쓰기 문장                 insert into · update … set · delete from · truncate
.rpc("...")                      DB 함수를 부른다 — 쓰는 함수일 수 있다
```

`.rpc(` 를 이름으로 가르지 않은 이유: **읽기 함수인지 쓰기 함수인지 이름으로 알 수 없습니다.**
`consume_rate_limit` 는 쓰고 `admin_analytics_snapshot` 는 안 씁니다. 부르면 적게 했습니다.

읽기만 하는 검사기도 한 줄 적게 되지만, **놓쳐서 운영 표에 쓰는 것보다 싸다**고 봤습니다.

### 2.2 셋이 새로 걸렸고 — 본문을 하나씩 열어 봤습니다

**짐작으로 적지 않았습니다.** 4차에서 그렇게 해서 틀렸습니다.

| 파일 | 확인한 것 | 선언 |
| --- | --- | --- |
| `verify-unlock-ticket.mjs` | `issue_/consume_unlock_ticket` RPC + `finally` 의 raw delete | `AUDIT_SIDE_EFFECTS` |
| `audit-db.mjs` | 던지는 SQL 전부 카탈로그·건수 `select` | `AUDIT_NO_SIDE_EFFECTS` |
| `verify-app-split.mjs` | `select` + `admin_analytics_snapshot`(**함수 본문에 쓰기 없음을 마이그레이션에서 확인**) + `begin/rollback` | `AUDIT_NO_SIDE_EFFECTS` |

> Claude App 은 「같은 구멍은 이 한 파일뿐(다른 raw 쓰기 0건)」이라 하셨는데, **쓰는 것**은
> 그 말씀이 맞습니다. 다만 **DB 에 직접 붙는 파일**은 셋이라 셋 다 선언을 요구하게 했습니다.

### 2.3 함께 닫은 것 (Claude App P2·P3)

**① 낡은 `AUDIT_WRAPS` 선언이 조용히 무시됐다.** 그 갈래를 없애면서 읽는 곳이 사라져,
적어도 아무 일이 안 일어납니다 — **적은 사람은 갈음이 선 줄 압니다.** 거짓 안심도 결함이라
보고, 잔재가 있으면 빨간불을 냅니다(현재 0건).

**② `AUDIT_NO_SIDE_EFFECTS` 의 한계를 러너 주석에 적었습니다.** 실제로 쓰는 파일에 그럴듯한
이유를 달면 통과합니다. **코드로 못 막습니다** — 「이 `.query()` 가 무엇을 하는가」는 문자열로
알 수 없습니다. 그래도 쓰는 이유는 **이유 문자열이 책임의 흔적으로 남기** 때문입니다.

**③ 건너뛴 것을 「실행」으로 세지 않습니다.** 예전에는 건너뛴 것만 고른 필터가
「실행 1회 · 통과 0 · 검사 안 됨 1」로 찍혔습니다 — 아무것도 안 돌았는데 하나 돈 것처럼
보입니다. 지금은 이렇게 나옵니다(제 실측).

```
$ node scripts/audit-verifiers.mjs --filter unlock-ticket        exit 2
검사기 1개 · 실행 0회 · 안 부름 1개 — 통과 0 / 검사 안 됨 1 / 빨간불 0
  · naminglink/verify-unlock-ticket.mjs — 안 돌림 — 운영 unlock_tickets 에 …(raw SQL)
```

## 3. 대조군 — 이 시험들이 진짜인지 먼저 봤습니다

새 시험 셋을 **고치기 전 탐지기**에 그대로 걸었습니다.

```
pg 로 직접 붙으면 선언을 요구한다      옛 탐지기: 안 잡음  (기대: 잡음)
raw SQL 쓰기 문장도 잡는다            옛 탐지기: 안 잡음  (기대: 잡음)
쓸 수 있는 RPC 호출도 잡는다          옛 탐지기: 안 잡음  (기대: 잡음)
```

셋 다 `--self-test` 가 **exit 1 로 대조군 실패를 찍었습니다.** 힌트를 넓힌 뒤 셋 다 통과.

**그리고 이번에는 한 걸음 더 했습니다** — 힌트를 고친 뒤 **탐지 범위 자체를 전수로 다시
쟀습니다**. 검사기 전부를 훑어 DB·AI 에 닿는 파일과 그 선언 상태를 세는 스캔입니다.
결과: **11개 · 선언 없음 0개.** 4차의 실수가 「힌트 하나 고치고 전부 잡힌다고 적은 것」이라
그 절차를 마지막에 붙였습니다.

## 4. 이번에 제가 연 자리 — **열어 두지 않고 제 판단까지 적습니다**

3차·4차에서 「막아야 합니까?」로 물어 놓고 그대로 낸 것이 **전부 결함**이었습니다.
그래서 이번에는 물음이 아니라 **결정과 근거**를 적습니다. 틀렸으면 그렇게 말씀해 주십시오.

1. **`.rpc(` 힌트가 넓습니다.** 읽기 전용 RPC 를 부르는 검사기도 선언을 요구받습니다.
   → **넓은 채로 둡니다.** 이름으로 읽기·쓰기를 가를 수 없고, 좁히면 이번과 같은 사고가
   납니다. 지금 걸린 것은 세 파일이고 전부 이유를 적을 수 있었습니다.

2. **`pg` 임포트만으로 선언을 요구합니다.** 읽기 전용 DB 검사기가 늘면 선언이 늘어납니다.
   → **그대로 둡니다.** 선언 한 줄의 비용보다 놓치는 비용이 큽니다. 다만 **선언이 열 개를
   넘으면 다시 봐야 한다**고 봅니다 — 그때는 「읽기 전용 클라이언트」 같은 구조로 가르는 것이
   맞습니다. 지금은 그 수가 아닙니다.

3. **`AUDIT_NO_SIDE_EFFECTS` 는 신뢰에 기댑니다.** 코드로 못 막습니다.
   → **한계를 주석에 적는 것으로 닫았습니다.** 이걸 강제하려면 검사기를 샌드박스에서
   돌리며 실제 커넥션을 가로채야 하는데, 그 장치가 이 관문보다 커집니다.

4. **`AUDIT_WRAPS` 잔재를 경고가 아니라 빨간불로 냅니다.** 실패 방향이 안전한 쪽인데도요.
   → **빨간불로 둡니다.** 「경고는 읽히지 않는다」가 이 저장소가 여러 번 겪은 자리입니다.
   잔재가 0건이라 지금 아무도 안 막습니다.

5. **요약 줄 형식이 바뀌었습니다**(`실행 N회 · 안 부름 M개`).
   → **파싱하는 곳이 없습니다 — 이번에 다시 쟀습니다.** 저장소 전체에서 `audit-verifiers`
   를 부르는 `json`·`yml`·`sh` 가 0건, `.husky` 없음, `.git/hooks` 에 활성 훅 없음.
   (4차에서 확인했다는 이유로 안 재는 것이 오늘 제가 틀린 방식이라 다시 쟀습니다.)
