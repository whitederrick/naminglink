## 1. mb4 재시도 — 쪼개니 한 번에 통과했다

어제 `mb4`는 콘텐츠 필터로 실패한 뒤 재시도 큐에서 밀려 끝내지 못했다. 어제 워크로그의
진단("원인은 특정 표제어가 아니라 배치 크기/처리 시간으로 보인다 — 다음엔 20~25개
단위로 쪼갤 것")을 그대로 따랐다.

`mb4.json`(29개)을 `mb4a.json`(15개, Andirons~Apprentice)·`mb4b.json`(14개,
Apricot~Ashes)로 쪼개 에이전트 둘을 병렬로 띄웠다. **콘텐츠 필터는 다시 나지 않았다** —
어제 의심했던 "원인 표제어"는 결국 없었고, 크기 문제였다는 진단이 맞았다.

| 배치 | 표제어 | 항목 | 비고 |
| --- | --- | --- | --- |
| mb4a | 15 | 56 | `Apparel` 하나가 21개(색깔·상황별로 조짐이 많은 긴 문단) |
| mb4b | 14 | 27 | |

**제외한 것**: `Apparel` 끝의 각주 `[16] See Clothes and Coat.`(참조 지시)와 같은 문단의
일반론 마무리(`There are few dreams in which the element of evil is wanting...` — 조짐이
아니라 해석 태도 서술). **인종·민족 표현으로 제외한 항목은 0건** — 이 29개 표제어에는
해당 표현이 없었다(어제는 m5·m6에서 3건 나왔다).

### 곁가지 — 중단된 에이전트의 결과물이 남아 있었다

작업 도중 두 에이전트가 중단됐다(사용자 조작으로 보이나 사유는 확인 못 함). 중단 알림만
보고 "둘 다 날아갔다"고 적지 않고 **파일부터 확인**했더니:

- `m4a.json` — 없음(아무것도 못 만들고 중단)
- `m4b.json` — **27개 항목이 이미 완성돼 있었고 검사기도 통과**했다

`m4b`는 다시 돌리지 않고 재검증만 해서 살렸다. **중단 알림은 "작업이 없어졌다"가 아니라
"에이전트가 멈췄다"이다** — 산출물의 유무는 파일로 확인할 것.

## 2. 통합 검증 — 밀러 결과 13개 파일

```
node scripts/verify-dream-cite.mjs <m1 m2 m3 m4a m4b m5 m6 m7a m7b m8 m9a m9b miller-pilot>
→ 합계: 항목 786개 · 위반 0건 · exit 0
```

내역: m1=66 · m2=70 · m3=87 · **m4a=56** · **m4b=27** · m5=91 · m6=99 · m7a=60 ·
m7b=48 · m8=99 · m9a=42 · m9b=26 = **771개** (+ 파일럿 15 = 786).
어제 688개에서 m4a·m4b(83개)만큼 정확히 늘었다 — **수치가 예상과 맞는지 대조했다.**

### 대조군을 밀러 경로로 새로 만들었다

`--self-test`(5종)는 **주공해몽 경로만** 시험한다 — 원문 줄 집합(`ZHOUGONG_LINES`)에
있는지 보는 갈래다. 밀러는 **문단을 이어 붙여 부분 문자열로 보는 다른 갈래**(`millerFlat`)라
자체 대조군이 그 코드를 한 줄도 안 지난다. 그래서 직접 만들었다:

- `m4a.json` 사본에서 인용 한 줄만 `good will among friends` → `great wealth among friends`로
  위조 → **위반 1건 · exit 1로 잡혔다.**
- 확인 후 사본은 지웠다(스크래치패드에 만들어 작업 트리엔 잔재 없음).

**"검사기가 통과했다"를 적기 전에 그 검사기의 그 갈래가 살아 있는지 본다**(CLAUDE.md §22).
자체 대조군이 있어도 **내 데이터가 지나는 갈래를 지나는지**는 따로 봐야 한다.

## 3. 표제어 커버리지 대조를 처음으로 넣었다 — 검사기가 못 보던 자리

**`verify-dream-cite.mjs`는 누락을 못 잡는다.** 소스를 열어 확인했다(164~186줄) — 결과
파일의 항목을 `items.forEach`로 훑으며 "이 인용이 진짜인가"만 본다. **표제어 하나가
항목을 0개 냈으면 그 표제어는 검사기 시야에 아예 없다.** 그런데 배치 추출에서 가장
흔한 결함은 "지어냄"이 아니라 **"빠뜨림"**이다.

어제까지 "688개 · 위반 0건"을 여러 번 보고했지만, **그 688개가 입력 표제어의 몇 개를
덮는지는 아무도 세지 않았다.** 오늘 처음으로 입력(`mb1~mb9`의 headword)과 결과
(`cite.locator`)를 스크립트로 대조했다(§10 #40·41 — 손으로 세지 않음):

```
입력 표제어(mb1~mb9): 299
결과 항목 771개 · 결과가 다룬 표제어: 298
빠진 표제어 1건: Barrel
입력에 없는 표제어 0건
```

**빠진 1건은 결함이 아니었다** — `Barrel`(mb6)의 원문은 전체가 `[19] See Cask.`,
참조 지시뿐이고 조짐이 없다. 규칙 2("각주·참조는 의미 항목이 아니다")대로 제외된 것이
맞다. **"빠졌다"를 결함으로 적기 전에 원문을 열어 봤다**(CLAUDE.md §4).

입력 299개는 어제 301개에서 `Abortion`·`Absalom` 둘을 뺀 수와 맞는다.

## 4. 오늘 알아차린 실수 — CLAUDE.md §24로 적음

「인용이 진짜인가」를 보는 검사기를 만들어 놓고 **「빠뜨린 것이 없는가」는 아무도 안 보는
상태로 사흘을 갔다.** 자세한 것은 CLAUDE.md §24. 요지는:

> 검사기가 훑는 것은 **결과 파일에 있는 것**이다. 없는 것은 검사기 시야에 없다.
> 원문에서 항목을 뽑는 작업의 관문에는 **진위 검사와 커버리지 대조가 둘 다** 있어야 한다.
