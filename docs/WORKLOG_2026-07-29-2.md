## 1. 상품 14건 판매 잠금

`product_settings`에서 naminglink 상품 14건이 `enabled=true`였다. 토스 실채널 키가 없는 상태라
이용자에게는 **눌러도 아무 일 없는 구매 버튼**이 보이는 상태였다. 인연링크 4건만 꺼져 있어
오히려 반대로 돼 있었다.

`node scripts/toggle-products.mjs --off --service naminglink` → **20건 전부 판매 중지.**
이력(`product_setting_history`)도 함께 남겼다.

### 곁들여 고친 스크립트 결함

첫 실행이 이력 INSERT에서 죽었다. `Prefer: return=minimal`이 PATCH에는 204를 주지만 **POST에는
201 + 빈 본문**을 주는데, 상태 코드로만 갈라 `response.json()`을 부르고 있었다. 응답 본문을
먼저 text로 받아 비어 있으면 null을 돌려주도록 고쳤다. (죽은 지점이 파싱이라 서버 INSERT는
이미 통과한 뒤였고, 스크립트가 이미 원하는 상태인 행을 건너뛰므로 재실행에도 이력은 안 겹쳤다.)

## 2. 글로벌 SEO 1·2순위 (`docs/SEO_STATUS_2026-07-28.md` 우선순위 ①②)

### 만든 것

| 파일 | 하는 일 |
| --- | --- |
| `src/lib/seo.ts` | 사이트 절대주소·색인 대상 경로·canonical·hreflang을 만드는 **한 곳** |
| `src/lib/seo-legal.ts` | 약관 4종 metadata(정적 사전에서 읽어 DB 왕복을 늘리지 않는다) |
| `src/app/sitemap.ts` | 공개 9경로 × (23 로케일 + x-default) = **216 URL** |
| `src/app/robots.ts` | 운영만 색인 허용, 미리보기 배포는 통째로 차단 |

페이지별 `generateMetadata`: `/`, 서비스 3종, 약관 4종, 도장 주문.
`noindex`: 로그인·계정·결과 3종.

### 판단이 필요했던 지점

**canonical을 언어판 자신으로 둔다.** `?lang=`이 있으면 그 주소가 canonical이고, 없으면
로케일 없는 주소(x-default)가 canonical이다. 여기서 언어판을 로케일 없는 쪽으로 몰면
23개 언어판이 색인에서 통째로 사라진다.

**hreflang은 자기 자신을 포함해 24개를 싣는다.** 구글은 한쪽이라도 상대를 되가리키지 않으면
그 쌍을 무시한다.

**robots로는 최소한만 막았다**(`/api/`, `/naming-artist`, `/admin`). 결과·계정·로그인은 robots가
아니라 화면 쪽 noindex로 막는다 — robots로 막으면 크롤러가 페이지를 못 읽어 **noindex 자체를
못 보고**, 외부 링크가 하나라도 있으면 내용 없이 URL만 색인되는 더 나쁜 상태가 된다.

**미리보기 배포 차단.** Vercel은 커밋마다 공개 URL을 만든다. 그것이 색인되면 운영과 똑같은
내용이 중복으로 잡힌다. `VERCEL_ENV !== "production"`이면 전면 Disallow.

### 빌드 산출물로 잡은 결함 3건

세 건 다 **코드를 읽어서가 아니라 실제 출력물을 보고** 발견했다.

1. **사이트맵이 깨진 XML이었다.** `/global-to-korean?mode=transliteration`을 색인 대상에 넣었더니
   Next 16의 sitemap 생성기가 `<loc>`와 hreflang href의 `&`를 **XML 이스케이프하지 않았다**
   (`&lang=`이 그대로). 575곳이 어긋나 문서 전체가 파싱 불가였다 — 한 URL이 깨지면 사이트맵
   전체를 못 읽는다. **쿼리가 둘 이상인 주소는 sitemap에 넣지 않는 것**으로 정리하고 주석에
   이유를 남겼다. 그 화면의 canonical·hreflang은 페이지 metadata에 그대로 있다(HTML 속성은
   React가 이스케이프하므로 안전하다). 제대로 된 해결은 그 화면에 자기 경로를 주는 것이고,
   경로 기반 URL 전환(우선순위 ③)과 함께 하는 편이 맞다.
2. **음차 화면 제목이 비어 있었다**(`Naming-Link | Naming-Link`). 그 문구가 `app/page.tsx` 안의
   지역 상수라 사전 조회가 빗나갔다. `lib/i18n.ts`로 옮기고 `getServiceCopy(locale, slug)`로
   합쳐, **화면과 검색 결과가 같은 사전을 보게** 했다.
3. **루트 레이아웃의 canonical이 모든 하위 페이지로 상속됐다.** 로그인·계정·결과 화면까지
   "이 페이지의 정본은 홈"이라고 말하고 있었다. 루트 레이아웃에서 `alternates`를 빼고
   `/`의 것은 `app/page.tsx`가 스스로 붙이게 했다.

### 검증

- `sitemap.xml.body`를 `[xml]`로 파싱 → **OK, 216 url, 이스케이프 안 된 `&` 0건, x-default 216건**
- 3099 포트에 운영 빌드를 띄워 실제 HTML 확인 → 서비스 페이지 alternate 24개(x-default 포함),
  언어판 canonical 자기 자신, 로그인·결과 `noindex, follow` + canonical 없음

### 도메인

`NEXT_PUBLIC_SITE_URL` 하나로 갈린다. 미설정 시 `https://naminglink.vercel.app`로 떨어진다.
**실 도메인은 색인이 쌓이기 전에 넣을 것** — 나중에 바꾸면 색인된 URL이 통째로 이동한다.

## 3. 결제 일원화 — 국내 포트원·카카오페이 경로 제거

### 확인한 것 (제거 전 상태)

| 흐름 | 국내 | 해외 |
| --- | --- | --- |
| 후보 일괄 공개 | 토스, **토스 키 없으면 포트원 폴백** | 포트원 페이팔 |
| 한자 상세 | 토스, **토스 키 없으면 포트원 폴백** | — |
| 이름 도장 | 토스, **토스 키 없으면 포트원 폴백** | 포트원 페이팔 |
| 글로벌 PDF | — | 포트원 페이팔 |
| 인연링크 리포트 | 토스(폴백 없음) | 포트원 페이팔 |

즉 **일원화돼 있지 않았다.** 국내 폴백이 살아 있었고, `getPortOnePublicConfig("kakaopay")`는
카카오페이 키가 없으면 단일 채널 키(`NEXT_PUBLIC_PORTONE_CHANNEL_KEY`)로 한 번 더 떨어져
`payMethod: "CARD"`로 결제창을 열었다.

### 왜 폴백이 위험한가

토스 키를 넣지 않은 상태에서도 결제창이 열린다 — **계약하지 않은 채널로 돈이 흐른다.**
"결제 경로가 끊기지 않게" 하려던 장치인데, 오픈 전 지금은 끊기는 쪽이 맞다.

### 고친 것

- `portone.ts` → `getPortOnePaypalConfig()` **하나만** 남겼다(채널 인자·국내 분기·단일 채널 키 폴백 삭제)
- 상품표의 `channel: "kakaopay" | "paypal"` → **`provider: "TOSS" | "PORTONE_PAYPAL"`**
  (`unlock-products.ts`, `goods-products.ts`, 인연링크 `report-product.ts`)
- 주문 라우트 4곳: 결제사는 상품표의 `provider`가 정한다. 토스 키가 없으면 국내 주문은 **503**
- 클라이언트 3곳: 국내 버튼 조건을 토스 키 하나로. 죽은 `PortOne.requestPayment` 분기와
  그에 딸린 sessionStorage 리디렉션 복구 장치를 삭제
- CSP: 카카오 출처(`*.kakao.com`, `*.kakaopay.com`) 삭제. `paymentsConfigured`는 페이팔 채널 키 기준
- `.env.example` 양쪽: `NEXT_PUBLIC_PORTONE_CHANNEL_KEY`·`_KAKAOPAY` 제거
- 문구: 도장 국내 결제 버튼 "카카오페이로 결제" → **"카드·간편결제"**
  (토스 통합결제창은 카드·토스페이·카카오페이·네이버페이가 함께 뜬다. 한 수단만 적으면 어긋난다)

### 그대로 둔 것

약관의 "토스페이먼츠를 통해 … 간편결제(토스페이·카카오페이·네이버페이·페이코 등)" 문구는
**사실이라 유지**한다. 카카오페이가 토스 통합결제창 **안의 수단**으로 들어오는 것과, 포트원
카카오페이 **채널**로 직접 결제하는 것은 다른 이야기다.

   자기 경로를 주는 일도 여기에 딸려 온다.
3. **프로그래매틱 페이지** — 우선순위 ④.
4. **실결제 검증** — 도장, 글로벌 프리미엄 PDF, 음차 PDF, 인연의 결 PDF. 전부 코드는 끝났고
   키만 남았다. 실채널 전환 시 `PORTONE_ALLOW_TEST_CHANNEL` 삭제 + 웹훅 시크릿 교체.
