## 1. 형제 셋 승격 — 하나씩 올려 대조군을 남겼다

`932697a`(광고 로케일 게이트 + GAM·CSP)를 인연 → 사주 → 드림 순으로 Production에 올렸다.
한 번에 올리지 않은 이유는 [[sibling-apps-global-ad-loader-removed]]에서 얻은 것 그대로다 —
**아직 승격 안 한 도메인이 「고치기 전」을 계속 보여 준다.**

    승격 전   세 도메인 다 X-Ad-Mode 헤더 없음 (옛 코드)
    회차 1    inyeon  review·ko    saju·dreams 헤더 없음
    회차 2    saju    review·ko    dreams 헤더 없음
    회차 3    dreams  review·ko

`vercel promote`는 Preview를 그대로 옮기지 않는다 — **운영 환경변수로 새로 빌드한다**고
확인 프롬프트가 알려 준다. [[root-docs-commit-redeploys-all-apps]]에 적어 둔 그대로였다.

### `vercel link`이 작업 트리를 건드린다

운영 환경변수 **이름만** 보려고 `vercel link`을 했는데 세 가지를 남겼다.

    .vercel/                 (gitignore 대상)
    apps/<앱>/.gitignore     새로 만들거나 줄을 더한다  ← sajulink는 추적 중인 파일이었다
    .env.local               VERCEL_OIDC_TOKEN 블록을 덧붙인다 (dreamslink는 파일 자체를 새로 만듦)

메모리에는 `vercel env pull` 금지가 적혀 있었는데(Sensitive 값이 `[SENSITIVE]`로 와서 로컬을
망가뜨린다) **`link`도 `.env.local`을 만진다는 것은 안 적혀 있었다.** 값은 살아남았지만
(`grep -c SENSITIVE` 0건으로 확인) 추적 중인 `.gitignore`가 바뀐 것은 커밋에 섞일 뻔했다.
전부 원복했다.

## 2. 애드센스 사이트 등록 — 코드 스니펫은 실패하는 것이 정상이다

사용자가 「사이트를 확인할 수 없습니다」를 만났다. 고른 방법이 **애드센스 코드 스니펫**이었다.

    <script async src="…/adsbygoogle.js?client=ca-pub-…"></script>

**이 사이트들에는 그 스크립트가 일부러 없다.** 2026-08-11 P0에서 걷어냈고, 되돌리면 naming-link
을 반려시킨 구조가 그대로 돌아온다. 대신 남겨 둔 두 가지가 살아 있음을 실측으로 보였다.

    <meta name="google-adsense-account" content="ca-pub-5084236528895241">   세 도메인 다 있음
    /ads.txt   HTTP 200   google.com, pub-5084236528895241, DIRECT, f08c47…   세 도메인 다 있음
    /robots.txt   Allow: /                                                    안 막힘

**Ads.txt 스니펫 또는 메타 태그**로 바꿔 확인하면 통과한다. 셋 다 그렇게 등록했다.

## 3. P3 — 광고를 발행한 화면에만 (`23462f8`)

슬롯 ID를 넣기 **전에** 해야 하는 일이었다.

### 먼저 — 셋은 광고를 실을 길이 아예 없었다

`src/lib/adsense-loader.ts`가 **naminglink에만 있었다.** P0에서 전역 `<script>`를 걷어내면서
**대신 부를 자리를 만들지 않았다.** 슬롯 ID를 넣어도 `adsbygoogle.push({})`만 배열에 쌓이고
스크립트가 없어 **광고가 영영 안 나올 상태**였다.

파일이 없는 것을 「아직 안 만든 것」으로 읽으면 안 된다 — **없어진 것**이었다.

### 걷어낸 자리 24곳 — 네 종류 화면이 두 슬롯을 함께 썼다

    PageHeader          top          모든 화면이 함께 쓰는 머리글
    GuideShell          top·bottom   안내 문서
    LegalDocumentView   bottom       약관·개인정보·환불
    입력 화면            bottom       /compatibility /affinity /reading /today /dream

**`NEXT_PUBLIC_ADSENSE_SLOT_BOTTOM` 하나를 넣으면 위 전부에 광고가 나가는 구조였다.**
2026-08-10 반려 사유와 정확히 같은 자리다. 사주는 `result` 자리가 **아예 없어서** 슬롯을 넣어도
결과 화면 광고가 0건이었을 상태였다 — 「자리가 셋 다 있다」가 「셋 다 쓰인다」는 뜻이 아니었다.

### 남긴 자리 — 화면마다 둘

    inyeon   compatibility_result_{header,inline}   affinity_result_{header,inline}
    saju     reading_result_{header,inline}         today_result_{header,inline}
    dreams   dream_result_{header,inline}   symbol_list_{header,inline}
             symbol_detail_{header,inline}          ← 상징 상세 215장

머리글은 제목 바로 아래, 중간은 **읽는 도중**의 섹션 경계(무료와 유료의 경계이거나 다음 절
앞)다. **맨 아래에는 두지 않는다** — 아무도 안 본다.

드림 사전(목록·상세)에 둘지는 사용자에게 물었다. 「무료가 본체·광고가 주 수익」인 앱이고
상징 215장은 실제 발행 콘텐츠라 **둔다**로 정했다.

### `AdBanner`를 naming-link과 같게

`placement` → `variant`+`slotKey`. 슬롯 키가 `AdPlacement` 타입이라 표에 없는 이름은 컴파일이
깨진다. 화면에 보이는 라벨은 **「광고」 한 단어**(23로케일, 사전이 갖는다), 서술형은
`aria-label` 전용. 높이는 바깥 상자가 정하고, `!max-w-full`+`[contain:inline-size]`를 함께 두고,
`data-full-width-responsive`는 끈다.

### 운영 상태 라우트가 슬롯 이름을 손으로 적고 있었다

`api/ops/status`가 `adSlots.top`을 직접 참조해 표를 고치자 컴파일이 깨졌다.
`Object.entries(adSlots)`에서 파생시켰다 — **자리를 더할 때는 타입이 안 잡아 준다.**

## 4. 슬롯 ID 자리에 퍼블리셔 ID가 들어갔다

사용자가 넣은 값이 열네 자리 전부 **`5084236528895241`**이었다.

    퍼블리셔 ID     pub-5084236528895241   16자리   계정에 하나    이미 들어가 있다
    광고 단위 ID    4148237335             10자리   자리마다 하나  ★ 단위를 만들어야 생긴다
    GAM 네트워크    23368513235                     보상형        안 쓴다

애드센스가 **사이트 확인 화면**에서 보여 준 ads.txt 줄에서 가져온 값이다. **그 줄은 코드가 이미
자동으로 내고 있어 어디에도 붙여넣을 필요가 없는데**, 화면에 나란히 보이니 그것이 슬롯 ID로
읽혔다. 광고 단위를 아직 만들지 않은 상태이기도 했다.

**화면으로는 안 보인다.** 틀린 슬롯은 no-fill과 똑같이 빈 자리로 나오고, 승인 전에는 no-fill이
정상이라 「아직 승인이 안 나서 그렇겠지」로 지나간다. 잡힌 것은 서버 HTML에서 `data-ad-slot`을
직접 읽었기 때문이다.

사용자가 단위 14개를 만들어 값을 교체하고 세 앱을 다시 배포했다.

## 5. 검사기 — 틀린 값이 빌드를 세운다 (`84d7f9d`)

값이 Vercel에 있으므로 **로컬 스크립트로는 못 잡는다.** `lib/ads.ts`는 `next.config.ts`가 직접
읽으므로, 여기서 던지면 빌드가 설정 로드 단계에서 죽는다.

- **형식** — 값이 있는데 숫자 10자리가 아니면 던진다. 오류문이 「어디서 가져오는 값인지」와
  「무엇과 헷갈렸는지」를 함께 말한다. 빈 값은 통과 — 자리를 하나씩 켜는 것이 설계다
- **중복** — 같은 슬롯 ID가 두 자리에 있으면 던진다. 복사해 붙이고 이름만 바꾸는 실수를 잡는다

대조군으로 확인했다. 오늘 실제로 들어갔던 값을 넣으면 이 문장으로 죽는다.

    NEXT_PUBLIC_ADSENSE_SLOT_COMPATIBILITY_RESULT_HEADER: 광고 단위 ID는 숫자 10자리여야
    합니다. 받은 값 "5084236528895241" (16자리).

**naminglink에는 안 넣었다.** 그 앱의 슬롯 6개가 Vercel에 Sensitive로 들어가 있어 값을 읽을 수
없고, 형식이 다른 값이 하나라도 있으면 **버는 앱의 빌드를 세우게 된다.**

## 6. 실측 — 기대값이 두 갈래고 양쪽 다 맞았다

### 서버 HTML

    inyeon  /ko/compatibility/result  4148237335    /ko/affinity/result  3542516490
    saju    /ko/reading/result        4072999530    /ko/today/result     8524109380
    dreams  /ko/dream/symbols      ins 2   6594437271 3290400904
            /ko/dream/symbol/pig   ins 2   3968273932 5869296937
            /ko/dream/result       ins 1   8687031962

    입력 · 약관 · 개인정보 · 안내 · kk · en        전부 ins 0

**드림이 가장 확실한 검증이다** — 상징 목록·상세가 서버에서 그려지므로 머리글과 중간이 **둘 다**
서버 HTML에 나온다. 인연·사주 결과 화면은 저장된 결과를 복원해야 중간 배너가 붙어 `ins 1`까지만
보인다. **`ins 1`을 결함으로 읽지 말 것.**

### 브라우저 — 로더는 서버 HTML로 확인할 수 없다

`ensureAdsenseLoader()`는 브라우저에서 도는 코드다. `<ins>`가 있다고 로더가 붙는 것은 아니다.

    /ko/dream/symbols   로더 ✅ pagead2…/adsbygoogle.js?client=ca-pub-…
                        ins 2 · 높이 100px 고정 · data-ad-status="unfilled"
                        문서폭 1905 < 뷰포트 1920 (가로 넘침 없음)
    /ko/terms           로더 0 · ins 0 · gpt 0
    /ko/dream (입력)     로더 0 · ins 0

`unfilled`은 **승인 전이라 정상**이다 — 요청이 나갔다는 뜻이고, 채워졌다는 것과는 다른 말이다.

**광고 있는 화면에는 `<ins class="adsbygoogle adsbygoogle-noablate">`가 `<body>`에 하나 더
붙는다.** 로더가 스스로 만드는 자동 광고(앵커) 자리다. 로더를 광고 자리에서만 부르도록 옮긴
덕에 **발행한 화면에만 생긴다** — 약관·입력에는 로더가 없으니 이 자리도 없다.

## 7. 이 날 내가 낸 실수

- **슬롯 ID 형식 검사를 값 넣기 전에 안 세웠다.** 관문은 앞에 있어야 하는데 사고가 난 뒤에
  만들었다. 변수 목록을 안내하면서 「10자리」라고 적기까지 했으면서, 그것을 세는 코드는 안
  만들었다 — 규칙은 손이 아니라 검사기가 센다
- **`vercel link`이 작업 트리를 건드릴 것을 예상 못 했다.** 메모리에 `env pull` 금지가 있었는데
  `link`은 안전하다고 단정했다. 추적 중인 `.gitignore`가 바뀌었다
- **진행 상황을 안 알려 사용자가 「얼마나 걸려」·「뭐해」를 여러 번 물었다.** 관문을 도는 동안
  침묵했다
- **마무리 보고를 길게 써서 두 번 끊겼다.** 「이제 정리하자」는 짧게 달라는 뜻이었다
