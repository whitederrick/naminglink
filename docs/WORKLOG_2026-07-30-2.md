## 2. 공유 썸네일 (`adf369f`)

인연링크 링크를 카카오톡·페이스북에 올리면 그림 없는 작은 카드로 떴다. `og:image`가 없었기
때문이다. `twitter:card`를 `summary_large_image`로 적어 두었어도 이미지가 없으면 큰 카드가
되지 않는다 — naminglink에서 오늘 오후 겪고 고친 것과 같은 자리다.

**23로케일마다 한 장씩 굽는다.** 메타 태그의 title·description은 이미 로케일별로 나가는데
그림에 박힌 글자만 하나면 어긋난다. 새기는 문구는 사전의 `brand`·`landing.title`·
`landing.privacyTitle`을 그대로 쓴다 — 사전을 고치면 이미지도 함께 고쳐지는 편이 옳다.

굽는 방법은 naminglink와 같다(헤드리스 크롬 → JPEG). Pillow는 raqm 없이 빌드돼 있어 아랍어
낱글자가 이어지지 않고 크메르 모음 기호가 제자리를 못 찾는다. 브라우저는 그 정형을 원래
하는 일로 한다. 산출물로 확인했다 — 아랍어는 우→좌로 앉고 어두운 막이 깔린 쪽에 글자가 온다.

```
scripts/render-og-images.ts   23장 · 합계 1.97MB (장당 90KB 안쪽)
assets/fonts/                 ar·th·km·hi 폰트 4종 추가(OFL, 대장에 기록)
```

배선은 세 곳이다 — 루트 레이아웃·랜딩·`buildPageMetadata`. 페이지가 `openGraph`를 정의하면
Next는 상위 값을 **덮어쓰므로** 한 곳만 넣으면 나머지 화면에서 썸네일이 빠진다. 루트 레이아웃의
정적 `metadata`를 `generateMetadata`로 바꾼 것은 요청 언어를 알아야 그림을 고를 수 있어서다.

## 3. 언어판을 경로로 (`b9a3040`)

언어판이 `?lang=ko`로만 갈렸다. 구글의 다국어 URL 권장안에서 쿼리 파라미터는 가장 낮은
선택지다. `/ko/compatibility`로 옮겼다.

**라우트 파일은 그대로 둔다.** 미들웨어(`src/proxy.ts`)가 `/ko/compatibility`를
`/compatibility?lang=ko`로 rewrite하므로 각 페이지는 예전처럼 `searchParams.lang`만 읽는다.
`[locale]` 아래로 옮기면 얻는 것은 같은데 바꿀 코드가 훨씬 많다.

**옛 주소도 그대로 200이다.** 이미 공유된 링크를 끊지 않는다. canonical과 sitemap만 경로
쪽을 가리켜 검색엔진에는 하나로 모인다.

루트 레이아웃은 `searchParams`를 못 보므로 미들웨어가 `x-locale` 헤더로도 알려 준다. 없으면
`/ar/…`인데 `<html lang="en">`이 나가 스크린 리더가 엉뚱한 언어로 읽고 `dir="rtl"`도 틀어진다.

### 언어 선택기 (감사 L의 인연링크판)

랜딩에만 있었다. 검색·광고·공유 링크로 궁합 화면에 곧바로 들어온 사람은 언어 판정이 어긋나도
바꿀 방법이 없었다. `PageHeader`에 넣어 궁합·인연의 결·결과·약관 4종까지 전부 덮었다.

지금 보던 화면에 머문 채 언어만 갈린다 — 그래서 경로를 prop으로 받는다. 서버 컴포넌트라 지금
경로를 스스로 알 수 없고, 이것 하나로 머리글을 클라이언트 컴포넌트로 내릴 이유는 없다.

## 4. 운영 알림 (`45298ce`)

`notifyOps`를 그대로 옮겼다. 여기도 사람이 손대야 끝나는 일이 `console.error` 한 줄로만
남고 있었다.

| 부르는 자리 | 등급 | 비고 |
| --- | --- | --- |
| 레이트리밋 확인 불가 | warn | 통과는 그대로 시킨다(아래) |
| 토스 결제 승인 실패 | critical | 반복되면 키·채널 설정이나 토스 장애다 |
| 리포트 발급 실패 | critical | **결제는 끝났는데 물건이 안 나간 자리다** |

**fail-open을 그대로 뒀다.** naminglink는 같은 경로에 전역 AI 상한이 실려 있어 전역 한도만
fail-closed로 돌렸지만, 이 앱은 규칙 엔진이라 요청당 외부 비용이 없다. 막아서 지킬 돈이
없는데 정상 이용자를 막는 것은 손해뿐이다.

**보내는 주소만 다르다.** naminglink는 자기 도메인에서 뽑지만 이 앱은 아직 실 도메인이 없어
`inyeonlink.vercel.app`이 나온다 — 인증하지 않은 도메인은 Resend가 거절하고, 이 함수는 실패를
조용히 삼키므로 **알림이 통째로 사라진다.** 인증을 마친 `naming-link.com`에서 보내되 제목에
`[inyeon-link]`를 달아 어느 서비스인지 알린다.

받는 주소도 DB(`getCompanyInfo()`)가 아니라 상수를 본다. 이 알림이 가장 필요한 순간이 DB를
못 믿는 순간이라, 주소를 찾다가 알림까지 함께 실패하면 안 된다.

## 5. 광고 자리와 GAM 보상형 (`0b40956`)

### 최상단·최하단 (사용자 요청)

광고가 제목 옆과 결과 중간뿐이었다. 화면에서 가장 먼저·가장 마지막에 눈이 닿는 자리가 비어
있었다.

```
top     머리글보다 앞. 브랜드 줄 위
bottom  푸터 바로 위
```

**흐름 안의 자리다.** 스크롤하면 같이 올라간다 — 화면에 붙어 따라다니는 스티키가 아니다.
구글이 '앵커 광고'라 부르는 그것은 자동 광고로만 공식 지원되고, 직접 `position: fixed`로
만들면 정책 위험이 있다(사용자 결정).

**옛 `form` 자리는 걷어냈다.** 입력 화면 맨 아래에 있던 자리인데 하단 배너와 붙어 광고 둘이
나란히 나온다. 환경변수 `SLOT_FORM`은 더 이상 읽지 않는다.

### 보상형을 GAM으로 되살림

`submitAdGateEnabled`가 한동안 항상 거짓이었다. 애드센스 표시 광고를 오버레이에서 걷어내면서
(감사 B) 판단 근거가 함께 사라졌기 때문이다. 이제 GAM 보상형 광고 단위가 있을 때만 참이 된다
— 띄울 광고 없이 5초를 붙잡으면 이용자만 잃고 버는 것이 없다.

**타이밍 결함 하나를 고쳤다.** 5초 타이머를 보상형 시도가 끝난 뒤에 시작한다. 함께 돌리면
15초짜리 광고를 보는 중에 5초가 지나 **광고 뒤에서 결과 화면으로 넘어가 버린다.** 끝까지
보면 기다림 없이 통과하고, 광고가 없거나(no-fill·차단기) 닫으면 그때부터 5초를 센다.

오버레이를 미리 감추지도 않는다 — 구글 보상형은 자기 화면을 더 위에 그리므로 가릴 필요가
없고, 감춰 두면 광고가 끝내 안 뜨는 경우 최대 4초 동안 화면이 텅 빈다.

### CSP

광고 단위가 있을 때만 열린다. `frame-src` 판정에 보상형을 빼먹으면 단위를 넣어도 아무것도
안 뜨므로 그 조건에도 넣었다.

```
광고 전부 꺼짐   verify-ads-csp.ts ALL PASS (구글 도메인 0개, frame-src none)
보상형만 켬      script/connect/frame-src에 securepubads·googleads만 추가
문서 순서        top → 제목+header → bottom → footer (입력·결과·약관 모두)
```

## 6. 계산 근거 안내 문서 (`90327ab`)

애드센스가 보는 것 중 하나가 콘텐츠 분량인데, 색인 가능한 페이지가 일곱 개뿐이고 그중 넷이
약관이었다. naminglink에서 같은 문제를 같은 방식으로 풀었다(감사 G, 고유 페이지 9 → 30).

**엔진에 이미 있는 것을 글로 옮겼을 뿐이다. 지어낸 내용이 없다.**

| 갈래 | 문서 | 근거 |
| --- | --- | --- |
| 서비스 근거 | 사주 궁합은 무엇을 보나 | `engines/saju.ts` 네 항목과 비중 |
| 관계표 | 십이지 관계 — 합·충·원진 | `engines/branches.ts` 일곱 관계 전부 |
| 띠 | 띠 궁합은 왜 연지를 보나 | `engines/zodiac.ts` |
| 십신 | 십신과 배우자 자리 | `engines/relations.ts` 짝 여섯 |
| 오행 | 억부용신 — 지금 필요한 기운 | `engines/yongsin.ts` 경계값 45%/35% |
| 우리 기준 | 인연의 결 — 총점을 내지 않는 이유 | `engines/affinity.ts` |
| 시각 | 출생 시각을 진태양시로 고칩니다 | `core/saju/engine.ts` 표준시 변천 |
| 개인정보 | 입력한 정보를 저장하지 않는 방식 | 프래그먼트 전달 구조 |
| 영어판 | How we calculate compatibility · What happens to the dates you enter | 위 문서의 영문 |

**표의 숫자를 글에 옮겨 적지 않았다.** `BRANCH_RELATION_SCORE`·`SAJU_WEIGHTS`·`ENGINE_WEIGHTS`를
그 자리에서 읽어 그린다. 손으로 적으면 규칙을 고쳤을 때 화면과 글이 갈리고, 그 갈림은 아무도
눈치채지 못한다.

한 페이지에 다 넣지 않았다. 주로 휴대폰에서 보는 글이라 한 화면에 쌓으면 아무도 끝까지 읽지
않는다. 대신 문서 하나가 1,300~2,600자라 "대량 생성 콘텐츠"로 보이지 않는다.

**링크 문구를 사전에 넣지 않았다.** 문서 자체가 한국어판·영어판 둘로만 갈리는데 링크 문구만
23벌을 만들면 이탈리아어 링크를 눌러 영어 문서가 나온다. 문서가 갈리는 방식과 링크가 갈리는
방식을 같게 뒀다. 링크 자리는 셋 — 입력 화면(미저장 안내 아래) · 결과 화면(점수 직후) · 푸터.

sitemap은 `guide-index.ts`에서 경로를 받아 온다. 문서를 더할 때 `seo.ts`를 함께 고쳐야 한다면
언젠가 한쪽만 고쳐지고 그 문서는 sitemap에 없는 채로 남는다.

## 7. 배포 후 실측 (`d93266e`)

빌드 성공을 확인의 근거로 삼지 않는다(오늘 오후 그 함정에 한 번 빠졌다 — `AUDIT_2026-07-30.md`
§7). 운영 주소로 실제 요청을 보내 확인했다.

```
/ko · /ko/compatibility · /ko/affinity · /ko/guide     200
/compatibility?lang=ko (옛 주소)                        200
/ar/terms                                               200
/zz/compatibility                                       404
안내 문서 10편 (ko)                                     전부 200
canonical  https://…/es/affinity
og:image   https://…/images/og/og-cover-es.jpg          이미지 자체도 200
robots.txt Disallow: /                                  ← 도메인 전이라 정상
sitemap    432 URL (18경로 × 24) · XML 파싱 통과
```

마지막 줄이 중요하다. **`NEXT_PUBLIC_SITE_URL`이 배포 주소인 동안에는 sitemap 432개를 만들어도
크롤러가 전부 차단된 상태로 본다.** 의도된 동작이다 — 배포 주소로 색인이 쌓이면 도메인을
연결하는 순간 URL이 통째로 이동한다.

## 8. 지금 잠겨 있는 것과 여는 순서

인연링크는 아직 오픈 전이고 애드센스 신청도 하지 않았다. 코드를 고치지 않고 환경변수만으로
전부 잠겨 있다.

| | 지금 | 여는 값 |
| --- | --- | --- |
| 광고 | 스크립트도 안 붙고 CSP도 조인 채 | `NEXT_PUBLIC_ADSENSE_CLIENT` |
| 광고 자리 4곳 | 아무것도 안 그림 | `SLOT_TOP`·`SLOT_BOTTOM`·`SLOT_HEADER`·`SLOT_RESULT` |
| 보상형 게이트 | 게이트 자체가 없음(즉시 결과) | `NEXT_PUBLIC_GAM_REWARDED_UNIT` |
| 운영 알림 | 로그만 남음 | `RESEND_API_KEY` |
| 결제 | `product_settings.enabled=false` | 관리자 화면 |
| 색인 | robots 전면 Disallow | `NEXT_PUBLIC_SITE_URL` |

**순서.** 애드센스는 사이트 단위 승인이다.

```
① 실 도메인 연결  →  ②  ADSENSE_CLIENT만 채우고 심사 신청  →  ③ 승인 후 슬롯 ID 등록
```

도메인 없이 배포 주소로 심사를 넣으면 나중에 도메인을 붙이는 순간 다른 사이트가 되어
재심사다. ②에서 슬롯 ID를 비워 두는 것은 심사 기간에 빈 광고 자리를 보이지 않게 하려는
것이다 — 심사원이 찾는 것은 페이지에 박힌 퍼블리셔 스니펫이다.

## 9. 남겨 둔 판단

- **입력 화면의 광고가 셋이다**(상단·제목 옆·하단). 결과 화면은 길어서 괜찮지만 입력 화면은
  폼 하나뿐이라 광고가 콘텐츠보다 많아 보일 수 있다. 심사에서 걸리면 `SLOT_HEADER`를 비우면
  된다 — 코드 수정 없이 그 자리만 사라진다.
- **랜딩에는 상·하단 광고를 넣지 않았다.** 히어로가 `100svh`라 위에 배너를 얹으면 첫 화면이
  통째로 밀린다. 랜딩 푸터도 히어로 안에 있어 하단 자리를 넣을 곳이 없다.
- **배경 사진 3장이 2MB 안팎이다**(`landing-hero.png` 2.2MB 등). `next/image`가 최적화해
  내려보내므로 감사 E(963KB 로고를 `unoptimized`로 그대로 보내던 것)와는 사정이 다르다.
  급하지 않지만 원본을 줄여 두면 빌드가 가벼워진다.
