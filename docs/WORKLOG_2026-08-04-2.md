## 2. 설계 문서와 실제 엔진이 어긋난 곳 셋

도메인 문서는 아이디어 시점에 쓰인 것이라 저장소 현실과 갈렸다. **지시서가 "실제 파일을 열어
확인"하라고 못 박은 이유가 이것이다.**

### 2-1. 지지 관계의 종류

설정값(`saju_scoring_defaults.json`)은 **형(刑)·파(破)·해(害)**를 전제하는데 이 저장소의
`branches.ts`는 그 셋을 계산하지 않는다. 대신 **반합(半合)**과 **원진(怨嗔)**이 있다(인연링크
엔진 v7·v8에서 들어왔다).

없는 관계에 점수를 매기는 대신 **있는 관계**에 맞췄다.

```
삼합 +6   반합 +3(삼합의 절반)   육합 +6   충 -7   원진 -3(형·파·해 자리 값)
```

### 2-2. 기신(忌神)을 엔진이 내놓지 않는다

`resolveYongsin`은 필요한 오행(용신)만 준다. **"용신이 아닌 전부"로 두면 안 된다** — 그러면
설계의 네 갈래 중 뒤 둘(`용신을 생함 +10`·`용신을 극함 -12`)이 영영 실행되지 않는다.
첫 갈래에서 걸러지지 않은 것이 전부 셋째 갈래(기신 -20)로 떨어지기 때문이다.

억부의 뜻대로 **반대 방향으로 더 밀어붙이는 오행만** 기신으로 봤다.

```
신강 → 기신 = 비겁·인성   (이미 넘치는데 더 보태는 것)
신약 → 기신 = 재성·관성   (얇은데 더 빼앗거나 치는 것)
중화 → 기신 없음          (억부로 가릴 수 없다)
```

**식상은 어느 쪽에서도 기신이 아니다.** 신약에게 부담이긴 해도 재성·관성만큼 직접적이지 않고,
신강에게는 오히려 용신이다. 사용자 확인을 받은 판단이다.

### 2-3. 새 타입을 만들지 않았다

도메인 문서가 `Natal` 타입을 제안하는데, **`PersonReading`(engines/prepare)이 이미 그것**이다.
원국·오행 세력·강약·용신·왕상휴수사가 전부 들어 있다. 새로 만들면 같은 것이 두 벌이 된다.

## 3. 오늘의 운세 엔진 (`lib/engines/today-fortune.ts`)

**순수 함수다.** 난수도, 현재 시각을 읽는 코드도 없다 — 날짜는 부르는 쪽이 넘긴다. 이 파일이
시각을 읽으면 서버 시간대에 따라 결과가 갈리고, 재현성이 이 서비스가 파는 것이다.

일진은 만세력에 **오늘 날짜를 생일처럼 넣어** 나온 일주를 쓴다. 시각은 넣지 않는다 — 진태양시
보정이 자정 근처에서 날짜를 옮겨 같은 날에 두 값이 나올 수 있다.

### 검사기는 점수를 검사하지 않는다

가중치는 튜닝 대상이라 값을 고정하면 검사가 곧 깨진다. **바뀌면 안 되는 성질**을 본다.

```
✓ 같은 날 두 번 = 같은 값            ✓ 60일 뒤 일진이 되돌아온다(60간지)
✓ 60일 점수가 5~98 안               ✓ 등급이 점수 구간과 일치
✓ 27종으로 흩어짐(한 값에 안 붙음)   ✓ 용신 날 60 > 기신 날 48
✓ 가중치를 낮추면 점수도 내려간다     ✓ 서울 자정 기준
✓ 대조군 둘
```

**60간지가 되돌아오는지**를 넣은 것은 만세력이 제대로 돌고 있다는 뜻이기 때문이다.

## 4. 비용 경계 — GPT는 결제한 리포트에서만

사용자 지시다. **무료 화면과 앞으로 만들 SEO 상징 페이지가 이 서비스의 획득 엔진**이라,
조회마다 모델을 때리면 API 비용·응답 지연·광고 페이지 속도가 한꺼번에 나빠진다.

```
무료  /api/saju · /api/today · 화면 전체   →  엔진 값 그대로 (0원, 0지연)
유료  /api/report/pdf (결제 확인 후)        →  GPT + 캐시
```

### naming 것을 가져왔다

새로 설계하지 않았다. 같은 `OPENAI_API_KEY`, 같은 `gpt-4o-mini` 기본값, 같은 JSON 강제.
**언어명 표(23개)도 `lib/openai.ts`에서 그대로 옮겼다** — 두 벌로 두면 한쪽만 고쳐지고,
그 어긋남은 "왜 이 언어만 영어로 나오지"로만 보인다.

### 캐시 키와 그 이유

```
입력해시 + 엔진버전 + 프롬프트버전 + locale + tier + 날짜(KST)
```

**재발급이 이 캐시의 존재 이유다.** 한 주문으로 다섯 번까지 다시 받을 수 있는데
(`REISSUE_LIMIT`), 그때마다 모델을 부르면 한 번 판 값으로 다섯 번 비용을 낸다.

지금은 프로세스 안 캐시다. 서버리스라 인스턴스가 바뀌면 사라진다. **DB 표로 옮기는 것은 운영
DB를 건드리는 일이라 따로 정할 문제**로 남겼다.

### 해설이 없어도 문서는 나간다

키가 없거나 모델이 흔들리면 `null`이 오고 엔진 값만으로 낸다. **모델이 흔들렸다고 결제한
사람이 아무것도 못 받으면 안 된다.** 면책은 모델 문장이 없으면 사전의 고정 문구를 쓴다 —
그 줄이 빠지는 경우는 없다.

### 경계를 검사기로 못 박았다

`scripts/verify-ai-cost-boundary.mjs`. **한 줄 import로 조용히 깨지는 규칙**이라 사람이 아니라
파일이 센다. 무료 라우트에 일부러 넣어 보고 실제로 잡히는 것까지 확인했다.

처음에는 못 잡았다 — 호출(`interpretSaju(`)만 찾고 import를 안 봤기 때문이다. 패턴을 넓히니
이번에는 PDF 렌더러가 걸렸는데 그건 **타입만** 들여오는 자리라 `import type` 줄을 가려냈다.

## 6. `ai_usage_logs`는 태깅이 아니라 스키마 변경이다

"service 태그만 붙이면 된다"는 계획이 있었는데 **그 컬럼이 없다.**

```sql
ai_usage_logs( id, naming_log_id, user_id, service_type, model, ... )
                    ↑ naming_logs FK        ↑ naming의 메뉴 enum
```

`service_type`은 서비스 구분이 아니라 naming의 메뉴(`HANJA_MEANING_MATCH` 등)이고,
`naming_log_id`는 **naming에 묶인 FK**라 사주는 채울 것이 없다.

그래서 **후방호환 마이그레이션**이 필요하다(사용자 정정으로 확정).

1. nullable `service` 컬럼 추가 → 기존 행 backfill → `naming_log_id` nullable화
2. naminglink 콘솔 쿼리에 `WHERE`/`GROUP BY service` 추가 → 기존 숫자 불변

**지금 오염은 0이다.** 사주는 아직 아무것도 기록하지 않는다. 유료 런칭 전까지 끝내면 잃는
데이터가 없고, 리테마 작업을 막지도 않는다.

## 7. 오늘 걸린 함정

- **`Record<AppKey, …>`가 타입으로 강제되지 않는 자리가 있다.** `AdminProductSettings`의
  `COPY`가 키 둘뿐인데 `AppKey`를 셋으로 늘려도 tsc가 잡지 않았다. 증분 캐시를 지우고 다시
  돌려도 같았다. 이유는 파지 않았고 **실제 위험만 막았다** — `COPY[app]`이 `undefined`가 되면
  화면이 제목 없이 뜬다. 다음 사람이 같은 자리를 밟도록 주석에 남겼다.
- **`.next/dev/types`에 남은 생성 파일이 빌드를 깬다.** dev 서버가 남긴 것이고 코드 문제가
  아니다. `Unexpected keyword or identifier`처럼 엉뚱한 오류로 보인다. 지우고 다시 돌린다.
- **`tsconfig.tsbuildinfo`가 검사를 건너뛴다.** 타입 오류가 0으로 나오면 이것부터 의심할 것.
- **히어독 안의 `\n`이 한 겹 벗겨진다.** 파이썬 문자열에 `\\n`을 쓰면 실제 줄바꿈이 들어가
  TypeScript 문자열이 깨진다. `chr(92) + "n"`으로 넣어야 한다(오늘 두 번 걸렸다).
- **`tsx`가 naminglink에만 설치돼 있다.** 다른 앱의 검사 스크립트는
  `../naminglink/node_modules/.bin/tsx`로 돌린다.

### ⑦가 왜 블로커인가

**화면이 아직 "궁합"이라고 말한다.** 제목·설명·가이드 문서·약관 서비스명이 전부 인연링크
것이다. 이용자에게 잘못된 서비스명이 노출된다.

분량이 크다 — i18n 23로케일의 서비스 문자열, legal 문구, 가이드 문서 교체(`guide/affinity`·
`how-compatibility` 삭제 후 원국·오행·용신·오늘의 운세로), SEO title/description/OG.

### 이미지도 임시다

로고·배경·OG가 전부 인연링크 것이다. **파일 이름을 그대로 뒀다** — 교체할 때 한 자리만
바꾸면 되게 하기 위해서다. 프롬프트는 `docs/image_prompts_saju_dream.md`에 있다.

### 운영 콘솔

4서비스 재구성은 앱 버전 Claude가 맡는다. 그쪽에 전해야 할 것 둘:

- **`Record<AppKey, …>`가 타입으로 강제되지 않는 자리가 있다**(§7). 새 서비스를 넣을 때 화면이
  조용히 빈칸으로 뜬다.
- **`orders.service`·`site_events.app`·`ad_events.app`은 DB 제약이 값을 정한다.** 위
  마이그레이션을 적용해야 `sajulink` 행을 쓸 수 있다.
