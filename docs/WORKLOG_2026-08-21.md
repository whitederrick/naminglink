## 1. 검수 관문 — 재검증 다섯 판

### 1.1 무엇이 닫혔나

두 검토자가 **독립적으로 같은 결함을 낸 것이 세 번**이었다. 그 셋이 이 관문의 뼈대였다.

| 판 | 결함 | 고침 |
| --- | --- | --- |
| 3차 | `CANNOT_RUN`을 출력 **아무 데나**에서 찾아 진짜 실패를 「못 돎」으로 덮었다 | 사유는 **마지막 줄**에서만 읽는다 |
| 3차 | `AUDIT_WRAPS`가 **선언만 하면 참** | (4차에서 갈래 자체를 없앰) |
| 3차 | `originAllowed`의 접두사가 **아래로** 열려 있었다 | 잎 78개 집합으로 판정 |
| 4차 | **스윕이 OpenAI를 실호출하고 운영 DB에 썼다** | 부수효과 선언 + 기본 제외 |
| 4차 | 새 `translated` 잎을 **승인할 방법이 없었다**(거짓 거부) | `originIds`/`translatedIds` 양쪽 |
| 4차 | 「감싸짐」 자취가 여전히 약했다 | **갈래를 없애고** 감사기가 직접 돌린다 |
| 5차 | `verify-unlock-ticket`이 raw SQL로 **운영 표에 쓰는데 기본 스윕에서 돌았다** | 탐지기가 DB 접속 자체를 묻는다 |
| 5차 마감 | `AUDIT_WRAPS` 잔재 검사가 `continue`에 가려 **절반의 파일에서 안 돌았다** | 검사를 맨 앞으로 |

### 1.2 「감싸짐」은 세 판 만에 없앴다

```
1판  부르기만 하면 참         → 공격 스크립트가 제품 검사기를 스윕에서 지웠다
2판  선언하면 참              → 부르지도 않으면서 적기만 해도 참이 됐다
3판  출력에 이름이 있으면 참   → 「나는 그것을 부른 적이 없다」라고 찍어도 참이 됐다
```

셋 다 **감싼 쪽이 통제하는 문자열**을 증거로 삼았다. **규칙을 세 번 조였는데 병이 그대로면,
고칠 것은 규칙이 아니라 구조다.** 지금은 `audit-pdfs.mjs --audit-plan`이 인자만 알려 주고
감사기가 제 손으로 돌린다. 대가는 `.py` 셋이 스윕당 두 번 도는 것(실행 100 → 115회).

### 1.3 최종 관문 실측 (`7be07e5`)

```
--self-test                     exit 0   낱말 갈래 10 · 부수효과 선언 12
공격 일곱 묶음                   exit 0   체크 25개
네 앱 tsc                       0건
전수 스윕 97개                   실행 108회 · 안 부름 7개
                                통과 108 / 검사 안 됨 7 / 빨간불 0   exit 2
탐지 범위 전수 재측정            DB·AI에 닿는 검사기 11개 · 선언 없음 0개
```

「안 부름 7」은 전부 부수효과 선언분이다. **이 스윕은 비용도 DB 쓰기도 없다.**

## 3. 방향 전환 — 광고 개방 조건

「비한글 광고를 붙이기 위한 사전 작업이 이 정도로 방대한 것인지 모르겠다」에서 시작했다.
전략 문서를 `docs/locale-ad-strategy` 브랜치에 두었다(`66bbed7`, PR 없음).

**핵심 진단**: en을 켜려면 잎 705개에 사람 판정이 필요한데, en·ja 외 20개 언어는 **읽을
사람이 없어** 그 조건이 영원히 안 채워진다. 반면 2026-08-10에 실제로 걸린 사유는 번역
품질이 아니라 **구조**로 본다. **걸린 적 있는 위험에는 관문이 없고, 걸린 적 없는 위험에는
넘을 수 없는 관문이 있었다.**

문서는 두 검토자에게 **일곱 자리를 지적받아 낮췄다.** 성질은 하나다 — **증명한 만큼만 말한다.**

```
판정 원인      「구조였다」           → 「가장 유력한 원인」(확정 불가)
hreflang       「중복을 막는다」       → 관계를 알리는 신호(판단은 구글이 한다)
ad_events 0건  「봇은 광고를 실행 안 한다」 → 「현재 계측에서 관찰되지 않았다」
스팸 정책      「검토 부재가 금지 대상」 → 자동·사람 여부가 기준이 아니다
신고자         「그 언어의 원어민」     → 보장 없음. 사용자 피드백이지 검수가 아니다
신고 0건       「검토 절차의 증거」     → 「채널이 돌았고 접수가 없었다」까지만
미처리 임계    자동 차단              → **스팸 신고로 광고를 끌 수 있다**
```

`ad_events` 자리는 특히 그렇다. 지금 광고 코드는 `ko`에만 나가므로(`ads.ts:124`) 비한국어
페이지에는 **애초에 광고 스크립트가 없다.** US발 0건은 봇의 성질과 무관하게 당연한 값이었다.

**최종 임계 경로**(신고 채널을 조건에서 뺐으면 순서에서도 빼야 한다):

```
① 구조 실측  ② 거래 문구 사람 확인  ③ 광고 조건 변경  ④ en 개방  ← 여기까지
⑤ 신고 채널(관측망, 병행/후속)  ⑥ 형제 셋 이식
```

## 4. 푸터 돌아가기 — 사용자 관찰에서 시작

**사용자 관찰**: 결과 화면에서 푸터 「이용 안내」로 들어가 돌아가면 결과가 아니라 **입력
화면**으로 간다. 「소개·문의·공지」는 어디서 들어가도 「처음으로」뿐이다.

원인은 같은 푸터에서 **규칙이 셋**이었기 때문이다. 결과 화면 주소는 `?id=<uuid>`라 미리
만들어 둘 수 없어, 출처 표를 아무리 늘려도 못 담는다.

**첫 고침은 틀렸다.** `history.back()`으로 통일했는데 `window.history.length > 1`은
「우리 화면이 있다」가 아니라 「이 탭에 아무 이력이나 있다」다 — 남의 사이트에서 주소를 치고
들어온 사람을 **남의 사이트로 되돌려 보낸다.** 코덱스가 P2로 막았다.

**지금**: 떠나는 쪽이 자기 주소를 `returnTo`로 실어 보낸다(`src/lib/return-to.ts`).
서버 HTML에는 넣지 않는다 — `?id=<uuid>`가 무한히 내부 링크로 공급되면 이 저장소가 이미
겪은 색인 문제가 재발한다. **눌릴 때 브라우저에서** 붙인다.

### 눌러 봤다 (dev :3001)

```
직접 방문 /ko/about              「처음으로」→ /ko    ← history.length 가 7인데도
?returnTo=https://example.com    거부 → /ko
?returnTo=//example.com          거부 → /ko
?returnTo=/\example.com          거부 → /ko
?returnTo=/global-to-korean/result?id=abcdef&mode=…   「이전 화면으로」→ 그대로(?id= 보존)
끝에서 끝까지   /hanja-meaning → 푸터 「소개」 → 뒤로 → /hanja-meaning
```

검사기 `verify-return-to.ts`(막을 것 14 · 통과할 것 8 · 붙이기 4). **대조군**: 「한 겹
풀어서도 본다」를 빼니 `/%2F%2Fevil.com`이 통과하고 빨간불이 났다.
