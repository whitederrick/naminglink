## 4. "왜 자꾸 실수하냐"는 질문 — 원인을 되짚었다

사용자가 이 사고를 보고 반복되는 이유를 물었다. 정리한 답은 둘이다.

1. **계획 실행 단계로 넘어가면 관성이 붙는다.** 조사 단계에서 파일의 손 댓글도 봤고
   `existing()`이 `JSON.parse`를 쓴다는 것도 읽었는데, 실행 직전에 그 둘을 다시 맞대어
   보지 않았다. 조사가 꼼꼼했다는 사실 자체가 실행을 덜 의심하게 만들었다.
2. **세션을 넘어 남는 습관이 없다.** CLAUDE.md·memory에 적힌 글자만 남고, 그마저 대개
   "이번엔 이렇게 하지 마라"는 사례별 패치이지 "관찰한 것을 실행 직전에 항상 재대조한다"는
   일반 규율로 옮겨지진 않는다. 그래서 같은 모양의 실수는 막아도 다른 옷을 입은 같은
   종류의 실수는 다시 뚫린다.

이어서 사용자가 "그래서 CLAUDE.md·작업내용·memory를 기록하라고 했는데 안 읽는 거냐"고
물었다. 확인해 보니:

- **CLAUDE.md·MEMORY.md는 실제로 매 세션 강제로 컨텍스트에 실린다** — 안 읽는 게 아니다.
- **하지만 WORKLOG("작업내용")는 자동으로 안 실리고, 08-21-2 이후로 하나도 안 쓰였다.**
  일주일치(신고 채널·해몽 사전 확장·도메인 사고·오늘 이 배치)가 기록 없이 흘렀다.
- 읽는 것과 실행 순간에 그것을 다시 불러와 대조하는 것은 별개라는 것도 함께 짚었다.

사용자가 "무조건 쓰라"고 확정했다. 이 파일이 그 재개다.

시험은 초록불이었다.

원인은 기존 "산 정상에 오름"의 매칭 키가 "올랐"·"올라갔"처럼 흔한 동사 어간이었던 것 —

### 7.1 잡은 버그 — "술"이 한 번도 안 걸리고 있었다

그 문자열 전체가 있어야 걸리고, 별칭도 "와인"(외래어)뿐이었다. **평범한 "술을 마셨다"는
이 상징이 생긴 이래 단 한 번도 안 걸리고 있었다.** 이 상징을 이번에 처음 실제로 시험해
보다가 드러났다. 별칭에 "술"을 추가해 고쳤다.

**같은 뿌리의 두 번째 결함**도 함께 나왔다 — `term_en`이 "alcohol / wine"이라 own-term
필터가 정확 일치만 보고 "wine" 낱말 자체는 못 걸렀다. 그 결과 기존 "함께 술을 나눔"의
영어 키워드에 있던 "wine"이 상징 이름이나 다름없는데 공짜 점수를 받아 새 문맥과 매번
동점이 났다 — 4·5차 배치의 "동점 때문에 대표 의미가 이긴다" 결함과 같은 종류다. 상징
이름과 겹치는 낱말을 빼서 고쳤다.

```
verify-dream-context-parity   실패 5건(전부 기존 결함, 무관)
verify-dream-match            ALL PASS
verify-guide-numbers          ALL PASS

```

새 문맥 20개를 손으로 `matchDream`에 태워 정답을 재확인했다(임신 신호가 있을 때 감의
태몢 의미가 우선하는 것도 함께 확인).

## 8. 매칭 결함 발견 — 사용자에게 물어 사전 확장을 계속하기로 함

"술(음료)" 사고를 보고한 뒤, 같은 병(term_ko에 "("·"·"가 있는데 각 조각이 별칭에 없어
한국어로 안 걸릴 수 있는 상징)이 몇 개나 더 있는지 훑어봤다. `눈(眼)`(별칭 0개, 가장
심각) 등 12개를 memory에 목록으로 남겼다. 사용자에게 "사전 확장을 계속할지, 이 결함부터
조사·수정할지" 물었고, **사전 확장을 계속하는 쪽**으로 정해졌다 — 결함 목록은 memory에
남겨 두고 나중에 다룬다.

### 9.1 시험하며 잡은 것 — 또 다른 어미·활용형 함정

이번엔 "동점" 문제가 아니라 **매칭 자체가 안 걸리는** 자리가 여럿 나왔다.

- 매칭 키의 활용형이 실제 문장과 어간부터 달랐다("꺾여"↔"꺾였", "placing"↔"placed").
- **자동 시험이 상징 자체를 아예 못 찾은 자리**도 있었다(책·글쓰기) — 내가 쓴 테스트
  문장이 애초에 그 상징의 트리거 낱말을 포함하지 않았다. 문장을 고쳐 넣었다.
- **손으로 다시 돌려 보다가 "결혼"의 구조적 결함을 하나 더 찾았다** — 이번 배치가 만든
  것은 아니다. "내가 결혼했다"(가장 흔한 말투)가 전혀 안 걸린다. 원인은
  `isStandalone`의 경계 검사가 조사 목록(`PARTICLES`)만 보는데, "했다"의 "다"는 조사가
  아니라 어미라 그 목록에 없다 — "결혼했는데"·"결혼하는"처럼 뒤에 "는데"·"는"이 오면
  걸리고 "결혼했다"·"결혼했어요"처럼 문장이 끝나면 안 걸린다. 같은 병을 "글쓰기"
  별칭(`글을 쓰`)에서도 겪었다("쓰던"은 안 걸리고 "쓰는"은 걸림). **이번 배치 범위 밖이라
  고치지 않고 기록만 남긴다** — 여러 상징의 여러 별칭에 걸쳐 있을 구조적 문제라
  `isStandalone`/`PARTICLES` 자체를 다시 볼 별도 작업이 필요해 보인다.

```
verify-dream-context-parity   실패 5건(전부 기존 결함, 무관)
verify-dream-match            ALL PASS
verify-guide-numbers          ALL PASS
tsc                           0건
dreamslink build               성공
```

새 문맥 14개를 손으로 `matchDream`에 태워 정답을 재확인했다.
