## 1. 개발·운영을 DB가 아니라 행 단위로 가른다 (`92092ad`, `2d90bec`)

로컬과 Vercel이 **같은 Supabase 프로젝트**를 본다. 이걸 나눌 것인가가 오늘의 첫 질문이었다.

### 나누지 않기로 한 이유

- **결제 가맹 심사가 사이트 URL 단위다.** 스테이징 도메인을 만들면 심사가 복잡해진다.
  지금 가장 급한 것이 결제 심사 통과인데 분리가 그 길을 막는다
- 무료 플랜은 7일 무활동 시 정지되고 장기 방치 시 삭제 위험이 있다. 프로젝트를 여럿 굴리면
  "복구하고 시작하기"가 매번 반복된다
- 운영자가 한 명이라 스테이징의 본래 값(남의 변경을 검증)이 없다
- 참조 데이터(한자·발음·서체·배경)는 dev/prod가 **같아야 정상**이라 공유가 오히려 이득

사용자가 짚은 실제 위험 지점은 셋이었다 — **상품 관리, 주문 관리, 배송 관리.** 성격이 달라
해법도 다르게 두었다.

| 성격 | 예 | 처리 |
|---|---|---|
| 이용자·결제가 만드는 행 | orders, premium_analysis_sessions | `is_test` not null + 래퍼 경유 |
| 운영자가 정하는 설정 | product_settings, site_contents | 컬럼 없음. **로컬 쓰기 403** + 읽기 값만 덮기 |
| 참조 데이터 | 한자 DB, 발음, 서체, 계절 배경 | 아무것도 안 함. 공유 |

**제어면을 행으로 나누지 않은 이유**: 나누는 순간 운영 값과 어긋나기 시작한다. 로컬에서 필요한
것은 "켜 본다"뿐이므로 `DEV_PRODUCTS_ENABLED=ALL`로 읽어 온 값만 덮는다(DB 무접촉).
로컬에서 상품을 켜 보려고 `enabled`를 바꾸면 **운영에서 실제로 판매가 열린다** — 결제 키가 없는
상태라면 눌러도 아무 일 없는 구매 버튼이 이용자에게 보인다.

### 판정은 한 곳, 기본값은 운영

`packages/core/src/env.ts`
```
VERCEL_ENV=production  → 무조건 운영 (APP_ENV 무시)
APP_ENV=dev            → 개발
그 외                   → 운영
```

오판 비용이 대칭이 아니다. 로컬을 운영으로 착각하면 통계가 지저분해질 뿐이지만, **운영을
개발로 착각하면 실주문이 관리자 목록·매출에서 사라져 돈을 받고 상품을 안 보내게 된다.**

### 빠뜨림을 막는 장치 셋

| 층 | 방법 | 빠뜨리면 |
|---|---|---|
| DB | `is_test` not null, **기본값 없음** | INSERT가 에러로 실패 — 로컬 첫 시도에 터진다 |
| 코드 | `lib/order-writes.ts` 래퍼가 유일한 입구 | — |
| 검증 | `scripts/verify-env-isolation.ts` | 배포 전 스윕에서 걸림 |

기본값을 없앤 것이 핵심이다. `default false`가 남아 있으면 새 주문 라우트가 컬럼을 빠뜨려도
**조용히 운영 행이 된다.** 다만 기본값을 바로 없애면 아직 배포되지 않은 옛 코드가 주문을 못
만들므로, 마이그레이션을 둘로 나눠 **배포 뒤에** 기본값을 뗐다.

`--verify-guard`로 실제 INSERT를 시도해 거부되는 것까지 확인했다(롤백, 행 남지 않음):
```
null value in column "is_test" of relation "orders" violates not-null constraint
```

### 대시보드 통계는 SQL 함수 안에 있었다

`admin_analytics_snapshot`이 매출·주문 수를 세므로 **앱 코드만 고쳐서는 테스트 행이 매출에
그대로 잡힌다.** 인자 `p_include_test`를 더하고 주문 집계를 `live_orders` 하나로 모았다.
관리자 화면에는 "테스트 주문 포함" 스위치와 테스트 배지를 두었다.

### 정정한 것

`seed-sample-orders.mjs`가 `orders`를 통째로 비운다고 했는데 **틀렸다.** 실제로는
`.eq("metadata->>sample","true")`로 샘플 행만 지운다. 위험은 없었다.

### 적용한 마이그레이션

- `20260728100000_test_data_isolation` — is_test(백필), 부분 인덱스, 통계 함수 교체
- `20260728120000_mark_legacy_dev_orders` — 개발 중 만든 미결제 주문 4건 + 세션을 테스트로
- `20260728110000_test_flag_drop_default` — **배포 확인 후** 기본값 제거

### 이 방식이 못 하는 것

- 파괴적 마이그레이션 리허설 → 그날만 `supabase start`로 임시 DB(상시 dev DB는 두지 않는다)
- 운영 PII의 물리적 격리 → 로컬 service_role 키는 여전히 실배송 주소를 읽는다. 도장 실주문이
  들어오기 시작하면 `.env.local`에서 키를 빼는 것을 별도로 판단할 것

## 2. 미리보기가 전부 깨져 있었다 (`4d718b3`) — 오늘의 진짜 사고

사용자 신고: "등록된 배경이 안 보이고, 배포된 것에서 서체 미리보기도 깨져 있다."

DB는 정상이었다 — 서체 18종 전부 `preview_path`가 있고 배경 4종도 `enabled=true`였다.

원인은 **어제 CSP를 조인 것**(`b94c2ee`)이었다. Supabase 주소를 `connect-src`에만 넣고
**`img-src`에 넣지 않았다.**

```
img-src 'self' data: blob:                  ← Supabase 없음
connect-src 'self' https://….supabase.co    ← 여기만 있었음
```

서체 미리보기·배경 이미지는 Storage **공개 URL**로 불러온다. 브라우저가 전부 차단했고,
`connect-src`를 쓰는 로그인·운영 콘솔은 멀쩡했다.

**조용히 깨지는 종류다.** 오류도 로그도 없이 이미지만 안 나오니 콘솔을 열기 전에는 "등록이
안 된 것"과 구분되지 않는다. 실제로 원인을 두 번 잘못 짚을 뻔했다(빈 목록 → 데이터 문제로 오인).

영향 범위: 관리자 배경 관리 + **이용자 서체 선택 화면(한글 발음 전환·한글 이름 전환 양쪽)**.
배포 후 사용자가 스마트폰에서 서체 미리보기 정상 확인.

## 3. 국내 결제를 토스 결제창에 연결 (`1f03f11`) — 어제 남긴 것

서버는 어제(`b23b488`) 끝나 있었고 화면만 남아 있었다. 한자 상세·일괄 공개·도장 셋 다
`checkout.provider`로 갈라 토스 결제창을 띄운다. 해외(페이팔 SPB)는 그대로다.

### 세 화면이 같은 규칙을 쓰도록 맞췄다

토스 주문은 `provider_payment_id`를 orderId로 두므로 결제 식별값도 orderId다. **도장 주문만**
응답에서 포트원식 `paymentId`를 내려주고 있어 함께 고쳤다. 덕분에 복귀 처리가 셋 다 같아진다.

### 돌아오는 자리

토스는 승인 라우트를 거치므로 화면이 붙인 쿼리가 살아남지 않는다. 승인 라우트가
`payment=paid&orderId=`를 붙여 주므로 복귀 처리에서 그 값을 받는다.

**한자 상세만 별도 처리가 필요했다.** 결과 화면은 `premiumSession`으로 어느 분석을 이어받을지
정하는데 그 값은 서버가 방금 만든 것이라 클라이언트가 미리 넣을 수 없다. 그래서 주문의
`returnPath`에 서버가 `?premiumSession=`을 넣는다.

복귀 시 confirm은 그대로 부른다. 토스 주문은 서버가 이미 승인했으므로 PAID를 보고 지나가고
(`alreadyPaid`), 쿼리를 지어내도 서버가 결제 상태를 다시 보므로 화면만 열리지 않는다.

### 버튼 활성화 조건

국내는 **`NEXT_PUBLIC_TOSS_CLIENT_KEY` 하나로 열린다.** 포트원은 넷을 모두 요구하지만 국내는
이제 포트원을 거치지 않는다(토스 키가 없을 때만 폴백). 해외는 그대로.

`@tosspayments/tosspayments-sdk` 2.7.1 추가(인연링크와 같은 버전). 결제창은 **동적 import**라
결제를 시도하지 않는 이용자의 번들에는 실리지 않는다.

## 4. 운영 콘솔 정리 (`f57f900`, `c148add`)

### 기준 데이터 화면 삭제

`/naming-artist/data`는 9개 분류의 범용 JSON 창고였는데, 그 뒤 각 항목이 전용 자리를 갖게 됐다.

| 분류 | 실제 자리 |
|---|---|
| 상품·가격 | `product_settings` |
| 한자 데이터 | `official_hanja_entries` |
| 번역·문구 | 코드의 i18n 사전 23로케일 |
| 광고 슬롯 | 환경변수 |
| AI 프롬프트·모델 | `prompts.ts`, `OPENAI_MODEL` |

실측: **서비스 코드 참조 0곳, 운영 DB 저장 0행.** 화면·API·컴포넌트를 지우고, 사용자 확인 후
표 2개도 `20260728130000_drop_master_data`로 삭제했다(404 확인). 비어 있는 표를 남겨 두면
"여기서 가격을 바꾸면 되나?" 하고 헷갈리게 만든다.

### 운영자 계정과 회원 분리

한 표에 섞여 있어 **운영자 계정 옆에도 삭제 버튼이 있었다.** 삭제는 회원의 개인정보 삭제 요청을
이행하는 수단이고 운영자 계정에는 그 근거가 없다. 실수로 지우면 콘솔 접근 권한이 사라진다.

- `/naming-artist/admins` — 운영자. 조회·비활성화만, **삭제 버튼 없음**
- `/naming-artist/users` — 굿즈 구매 회원. 삭제 유지, 의미 없던 권한 필터 제거

출처는 `auth.users` 하나이고 화면만 가른다. 판정은 `admin-auth`의 `hasAdminRole` 한 곳을 쓴다 —
`role === "admin"`만 보면 **`roles` 배열로 부여된 관리자가 회원 목록에 섞인다.**
**서버도 운영자 계정 삭제를 거부한다** — 화면에서 버튼을 감추는 것은 막은 것이 아니다.

### 서체 관리 화면

스토리가 표의 절반을 차지해 정작 필요한 것이 안 보였다.

- 스토리 열 제거 → **상세 팝업**(전체 스토리·저작권자·출처·번역 언어·큰 미리보기)
- 목록에 **미리보기·선택수** 추가, **10개씩 페이징**
- 정렬값을 표에서 바로 수정(포커스를 벗어나면 저장)

**정렬 규칙은 손대지 않았다.** `선택수 내림차순 → 정렬값 오름차순`이라 인기순이 자동으로
앞서되 동률이면 관리자가 정한 값을 따른다(사용자 요구와 이미 일치). 지금은 모든 선택수가 0이라
사실상 정렬값 순서다. 왜 그 순서인지 보이도록 선택수를 함께 띄웠다.

### 그 밖에

- **좌측 메뉴가 사라지는 화면 둘** — PDF 테스트·배경 관리만 `AdminShell`로 감싸지 않아 들어가면
  나갈 길이 없었다. 둘 다 감쌌다
- **PDF 테스트 화면** — 제목을 `글로벌 이름 전환 PDF 테스트`로(이 화면은 글로벌 3종만 다룬다).
  상품명을 `한글 이름 프리미엄 종합 리포트 / 한글 발음 전환 아트팩 / 한글 이름 변환 아트팩`으로
  바꾸고 `(서체 N개 · 후보 M개, 가격)`을 붙였다. **서체 수는 박지 않고 `product_settings`에서
  읽는다** — 적어 두면 상품 설정을 바꾼 순간부터 거짓말이 된다. 출력 언어는 `en (영어)` 형식
- **"테스트 주문 포함" 위치 고정** — 조작 영역을 세로로 쌓고 헤더 정렬을 위쪽으로. 가로로 두면
  조회 기간이 없는 화면에서 체크박스가 옆으로 밀려 매번 눈으로 찾게 된다
- **콘솔 이름** — `Naming Artist`를 전부 제거(서비스 어디에도 쓰지 않는 이름). 랜딩과 같은
  `BrandMark`(40px) + `운영자 콘솔` 배지. 크기는 Tailwind 클래스가 아니라 인라인 스타일로 준다
  (클래스로 덮으면 우선순위가 스타일시트 순서에 달린다)
- **설명 폭** 768px → 1024px. 상한을 아예 풀지 않은 것은 넓은 화면에서 한 줄이 길어지면 다음 줄
  첫머리를 놓치기 때문
- **인연링크 해외가 폴백** `US$2.99` → `US$1.99`. 7월 27일 인하 때 DB를 읽는 경로만 보고
  **조회 실패용 상수를 놓쳤다** — 약관이 옛 가격을 싣게 되는 자리였다

3. 관리자 화면에서 **상품 켜기**(지금은 `product_settings.enabled=false` 다크 런치)
4. 인연링크 Vercel Supabase 변수 + 도메인 연결, 통신판매업 신고번호

### 확인이 남은 것

- 관리자 **배경 관리 화면의 배경 미리보기**(서체 미리보기는 정상 확인됨. 같은 원인이라 함께
  풀렸을 것으로 보지만 눈으로 보지는 못했다)
- 첫 실결제에서 **브라우저 콘솔의 CSP 위반 보고** — 카드사 인증창 도메인은 발급사마다 다르고
  아직 미검증이다
