## 1. 5분 안에 돌려 보기

```bash
git fetch origin && git checkout 4772003

# ① 판정기가 사는가 — 몇 초입니다. 스윕 앞에 서도록 옮겼습니다
node scripts/audit-verifiers.mjs --self-test

cd apps/naminglink
# ② 공격 일곱 묶음 — 이게 본론입니다(⑦ 이 이번에 는 것)
npx tsx --tsconfig scripts/tsconfig.sweep.json scripts/verify-review-attacks.ts

# ③ 자격증명이 **있는** 경로 — 이번에 처음 돌게 됐습니다

# ④ 자격증명이 **없는** 경로도 여전히 못 돎인가

cd ..
node scripts/audit-verifiers.mjs --filter zzz-nothing      # 실행 0회 → exit 1

```

**판정은 종료 코드가 아니라 출력 본문으로 부탁드립니다.** `exit 1` 은 「잡았다」가 아니라
「끝났는데 0이 아니다」입니다 — 죽어도 1이고 파일이 없어도 1입니다.

### 제 쪽 실측 (`4772003`, 2026-08-21)

```

verify-review-attacks                   exit 0   공격 일곱 묶음
verify-legal-source (자격증명 있음)     exit 0   「물어봤고 legal.* 게시본이 없었다」

네 앱 tsc                               0건      (--listFiles 로 고친 파일을 봤는지 확인)
전수 스윕 97개 · 실행 100회             통과 96 / 못 돎 1 / 감싸짐 3 / 빨간불 0   exit 2
```

**전수 스윕이 `exit 2` 인 것이 이번 변경의 일부입니다.** 못 돎 1건(`verify-premium-test` —
dev 서버 필요)이 있어서입니다. 예전에는 같은 상태에서 `exit 0` 이 나왔습니다.

3차 때와 총계가 비슷하지만 **구성이 다릅니다.** 3차의 못 돎 2건은 「빌드 산출물 없음 +
자격증명 없음」이었고, 지금은 자격증명 쪽이 **실검사로 바뀌어** 사라졌습니다(아래 2.4).

## 2. 고친 것

### 2.1 P0 · `CANNOT_RUN` 을 출력 **아무 데나**에서 찾았습니다

`scripts/audit-verifiers.mjs` — `classify()`

그 낱말이 *비정상 종료의 사유인지*를 묻지 않고 출력 전체에서 찾았습니다. 실물이 둘입니다.

```
verify-review-attacks.ts:155  절 제목으로 「④ CANNOT_RUN 이 통과로 새는가」를 **늘** 찍는다
                              → 이 공격 묶음은 뚫려도 스윕에서 빨간불이 될 수 없었다
verify-legal-source.ts:273    환경변수가 없으면 본문 중간에 「· CANNOT_RUN —」을 찍는다
                              → 자격증명 없는 컴퓨터에서 이 검사기의 exit 1 이 안 보였다
```

**두 번째가 더 나쁩니다.** 「환경이 없다」와 「결함이 있다」는 함께 나는 상태인데 갈래가
하나로 접혔습니다. 제품 검사기이고, 그 상태가 흔합니다.

→ **사유는 마지막 줄에서만 읽습니다.** 프로세스는 멈춘 자리에서 이유를 말합니다.

이 규칙 때문에 **사유 뒤에 힌트를 찍던 검사기들이 거짓 빨간불이 됩니다.** 그래서 그쪽도 같이
고쳤습니다 — `audit-bundle-secrets.mjs` **네 앱**(순서만 뒤집음) · `verify-premium-test.mjs`
두 갈래(사유 한 줄을 끝에 붙임). 안 고쳤으면 빌드·dev 서버 없는 컴퓨터마다 없는 결함이
신고됩니다. **막는 쪽으로 틀린 것도 결함입니다.**

### 2.2 P0 · `AUDIT_WRAPS` 는 **선언만 하면 참**이었습니다

`scripts/audit-verifiers.mjs` — `resolveWrapped()` · `scripts/audit-pdfs.mjs`

2026-08-20 에 「부르면 감싼 것」을 「선언해야 감싼 것」으로 바꿨는데, **규칙만 바뀌고 병은
그대로였습니다.** `wrapDeclarations()` 가 보는 것은 ⓐ자기 자신 ⓑ없는 파일 ⓒ중복 선언 셋뿐이고
실제로 부르는지는 아무도 안 봤습니다.

→ **이번 실행의 자취**를 요구합니다. 감싼 쪽 **출력에 감싸진 파일 이름**이 있어야 갈음이 섭니다.
소스 grep 으로 판정하지 않습니다(그 방식이 2026-08-20 에 거짓 초록불을 냈습니다). 그래서
`audit-pdfs.mjs` 가 부른 스크립트 경로를 출력에 남기게 했습니다.

**환경이 없어 감싼 쪽이 못 돌았으면 자취가 없어도 빨간불이 아닙니다**(못 돎입니다). 그것도
대조군에 넣었습니다 — 아니면 렌더 산출물 없는 컴퓨터마다 없는 결함 셋이 납니다.

### 2.3 P0 · `originAllowed` 의 접두사가 **아래로** 열려 있었습니다

`apps/naminglink/scripts/locale-manifest.ts`

끝점(`docs.about.`)을 찍어 **옆으로 새는 이름**(`docs.aboutXxx`)은 막았는데, 막은 것이 옆뿐이고
**접두사 아래로 새로 생기는 잎은 그대로 통과**했습니다.

실물 위험은 `notices.` 입니다. **공지는 운영 중에 늘어납니다.** 한국어로 써서 en 으로 옮긴
공지가 `notices.items.*` 로 들어오면 옮긴 글이 `reviewSourceHash` 없이 원문으로 둔갑합니다.

78/121 갈래는 `df1c6b4` 대조로 얻은 **한 시점의 판정**인데, 규칙이 접두사라 **그 시점에 얼지
않았습니다.**

→ 접두사로 판정하지 않습니다. 갈라 둔 **잎 78개를 그대로 적고**(`ids: readonly string[]`)
그 집합으로만 판정합니다. 접두사는 이제 **묶음 이름**이고, 그 아래 목록에 없는 잎이 생기면
`originDocsEnErrors()` 가 「옮긴 것인지 영어로 새로 쓴 것인지 갈라 적을 것」이라고 잡습니다.
**조용히 통과시키지도, 조용히 거부하지도 않습니다.**

### 2.4 곁가지 — 함께 닫은 것

**① 감사기 자신이 못 돎이 있어도 `exit 0` 이었습니다** (Claude App P1).
화면에는 「통과가 아니다」라고 찍으면서. **종료 코드를 읽는 것은 사람이 아니라 스크립트입니다.**
→ `0` 전부 돌았다 / `1` 빨간불·대조군 깨짐·실행 0회 / `2` 검사 못 한 것이 있다.

**② `audit-bundle-secrets` 의 「비밀 0개」가 못 돎으로 강등됐습니다** (Claude App P1).
그건 스스로 내는 **의도된 빨간불**인데 문구에 `.env.local` 이 들어 있었습니다. 2.1 을 고치니
제 갈래로 갑니다(마지막 줄이 사유가 아니므로).

**③ 판정기 대조군이 스윕 **뒤에** 돌고 있었습니다.**
판정기가 깨졌는지 알려면 97개를 7분 돌려야 했고, 그 7분은 이미 못 믿을 것이었습니다.
→ 앞으로 옮기고 `--self-test` 를 뒀습니다. **관문은 비싼 단계 앞에.**

**④ `verify-legal-source` 의 「못 돎」은 자격증명이 없어서가 아니었습니다.**
`apps/naminglink/.env.local` 이 **46줄로 있었습니다.** 그 검사기가 읽지 않았을 뿐이고, 같은
폴더 `verify-premium-ai-usage.ts` 는 읽고 있었습니다. **빠진 것은 파일이 아니라 배선입니다.**
그 사이 ⑥ 운영 현황은 **한 번도 검사되지 않았고**, 제 기록에는 「이 컴퓨터에 `.env.local` 이
없다」고 적혀 있었습니다.

파싱을 `load-env-local.ts` 한 곳에 모았습니다(같은 파싱이 한 벌 더 있었습니다). 그리고
**배선을 넣자 공격 ④ 가 뚫렸습니다** — 그 공격은 자식의 `SUPABASE*` 를 지워 「못 물어보는」
상태를 만드는데, 검사기가 파일을 스스로 읽으니 자격증명이 되살아났습니다. `legal-source.ts`
가 reader 를 **주입**하게 만든 것과 같은 이유로 이음매(`NAMINGLINK_IGNORE_ENV_LOCAL`)를 뒀습니다.

## 4. 특히 봐 주셨으면 하는 것 — **이번에는 열어 둔 채 묻지 않으려 했습니다만**

아래는 제가 **닫았다고 생각하는데 확신이 없는** 자리입니다. 3차의 실수를 되풀이하지 않도록,
「막아야 합니까?」가 아니라 **「제가 막은 방식이 틀렸습니까?」**로 묻습니다.

1. **마지막-줄 규칙이 제가 못 본 검사기를 거짓 빨간불로 만들지 않는가.**
   낱말을 낼 수 있는 검사기 11개(넷은 같은 파일)를 찾아 경로를 봤고, 오늘 실제로 걸린 둘은
   고쳤습니다. 그런데 **오늘 안 걸린 갈래**(다른 앱 포트를 보는 경우 등)는 코드로만 봤습니다.
   `verify-premium-test` ③ 갈래는 실제로 못 돌려 봤습니다.

2. **`named` 자취 판정이 너무 약하지 않은가.** 증거가 「출력에 파일 이름이 있다」입니다.
   감싼 쪽이 **부르지 않고 이름만 찍어도** 통과합니다. 실행 자체를 증거로 삼으려면 감싼 쪽이
   구조화된 표식을 내야 하는데, 거기까지 갈지 판단이 필요합니다.

3. **`NAMINGLINK_IGNORE_ENV_LOCAL` 이 새 구멍이 아닌가.** 자격증명 읽기를 끄는 스위치입니다.
   켜면 검사기가 「못 돎」으로 끝나고 못 돎은 통과가 아니지만(스윕이 `exit 2`), **못 돎을
   만들어 낼 수 있는 스위치**인 것은 맞습니다.

4. **`exit 2` 가 부르는 쪽을 깨지 않는가.** 제가 먼저 셌습니다 — **자동으로 부르는 자리는
   없습니다.** `.github/workflows` 는 `premium-cleanup-cron.yml` 하나뿐이고 이 스윕과 무관하며,
   husky 훅도 `package.json` 스크립트도 부르지 않습니다. 지금 부르는 것은 사람과 검토자뿐입니다.
   **그래도 제가 못 본 자리가 있으면** 알려 주십시오(제가 센 방법: 저장소 전체에서
   `audit-verifiers` 를 찾아 문서·주석을 걸러냈습니다).

5. **잎 78개 목록이 옳은가.** 인벤토리에서 뽑아 넣었으니 **지금 상태와는** 일치합니다.
   문제는 그 78/121 갈래 자체입니다 — 3차 때 「`guide` 121개 중 사람이 쓴 것이 섞여 있지
   않은가」를 물었고 Codex 가 「전부 translated, 대응 ko 경로 존재」를 확인해 줬습니다.
   **잎 하나하나로 보신 것인지** 확인 부탁드립니다.

6. **새 잎 검사가 거짓 거부를 만들지 않는가.** 이제 묶음 아래 목록에 없는 잎이 생기면
   빨간불입니다. 사람이 영어로 새 소개 문단을 쓰면 **한 번은 반드시 걸립니다.** 그게 의도인데
   (갈라 적게 하려고), 운영 중 공지 추가처럼 잦은 일에 걸리면 무시하는 법부터 배우게 됩니다.

7. **`verify-legal-source` 가 이제 매 스윕마다 운영 Supabase 를 읽습니다**(읽기 전용).
   전수 스윕이 도는 빈도를 생각할 때 괜찮은지.

## 5. 아직 안 한 것 — 그대로입니다

- **en 검수를 실제로 시작하지 않았습니다.** 이번 고침도 「시작하면 걸릴 자리」를 없앤 것이고,
  78개를 origin 으로 적은 manifest 를 만들어 본 것은 아닙니다. Codex 지적대로 **manifest 와
  검수 packet 생성기가 없어** 사람 검수는 아직 시작 전입니다.
- **띄워서 눌러 본 것이 없습니다.** 전부 코드와 검사기 출력입니다.
- `verify-premium-test` 는 dev 서버가 필요하고 **OpenAI 비용이 들어** 제 판단으로 안 돌렸습니다.
  전수 스윕의 못 돎 1건이 그것입니다.
- **운영 번들 기준 비밀 누출 검사** — 제가 `next build` 를 돌리지 않았습니다. Codex 가
  3차 때 빌드해서 「번들 61개 · 서버 비밀 9개 유출 없음」을 확인해 줬습니다.
