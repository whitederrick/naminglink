## 2. 인연링크 도메인 연결

```
inyeon-link.com        Vercel inyeonlink 프로젝트 · Production
www.inyeon-link.com    308 → apex
가비아 DNS             A @ 216.198.79.1 · CNAME www 9cafeabe0102ab47.vercel-dns-017.com.
결과                   apex 200 · www 308 · 인증서 발급 완료
```

### naming-link과 DNS 값이 다르다

Vercel이 IP 대역을 확장해 **새로 등록하는 도메인에는 다른 값을 준다.**

| | naming-link (07-29 등록) | inyeon-link (08-03 등록) |
| --- | --- | --- |
| apex | `A @ 76.76.21.21` | `A @ 216.198.79.1` |
| www | `A www 76.76.21.21` | `CNAME www <프로젝트별 값>` |

Vercel 안내: *"We're expanding our IP range. The legacy records … will continue to work."*
**옛 값도 계속 돌지만 섞지 말 것.** www의 CNAME은 **프로젝트마다 값이 다르므로** 화면에 나온
것을 그대로 써야 한다.

### 순서를 지켰다

`NEXT_PUBLIC_SITE_URL`은 **DNS가 붙은 것을 확인한 뒤에** 넣었다. naming-link 때는 먼저 넣어
두었다가 **canonical이 가비아 파킹 페이지를 가리키는** 상태가 있었다(`WORKLOG_2026-07-30.md` §1).

```
DNS 등록 → 200 확인 → NEXT_PUBLIC_SITE_URL(Production만) → 재배포 → robots 확인
```

**Preview에는 넣지 않았다.** 안 넣으면 프리뷰가 `*.vercel.app`으로 떨어져 robots가 계속
차단한다 — 프리뷰가 색인되는 사고를 구조가 막아 준다.

### 연결 후 자동으로 열린 것

`lib/seo.ts`가 `siteUrl`에서 전부 갈라져 나오도록 돼 있어 **따로 켤 스위치가 없었다.**

```
robots.txt   Disallow: /  →  Allow: /  ·  Disallow: /api/  ·  Host·Sitemap 명시
canonical    inyeonlink.vercel.app  →  inyeon-link.com
hreflang     23로케일 + x-default
sitemap      552 URL (표본 10개 전부 200)
```

### 인연링크 SEO는 **이미 돼 있었다**

앞선 문서와 메모리가 "미착수"라고 적고 있었는데 **낡은 정보였다.** 7월 30일 운영 이식 때
sitemap·canonical·hreflang·경로 URL이 전부 만들어져 있었고, 도메인이 없어 작동만 안 하고
있었다. 도메인을 붙이는 것으로 끝났다 — 추가 작업이 없었다.

### 셀프 광고 링크 (`08e12ed`)

`SelfAdCard`가 *"도메인이 살면 `<a href>`로 바꾸면 된다"*고 적어 둔 자리다. `inyeon-link.com`이
200을 돌려주므로 링크로 전환했다. `place-link.com`은 **아직 개발 중**이라 글자로 뒀다 —
주석에 "응답 없음"이 아니라 "개발 중"이라고 적었다. 전자로 적으면 다음 사람이 고치러 든다.

## 3. 구글 서치 콘솔 — 처음 도입

지금까지 **한 번도 쓰지 않고 있었다.** naming-link이 5일째 떠 있었는데 구글이 얼마나
가져갔는지 확인할 방법이 없는 상태였다.

두 도메인 모두 **도메인 속성**(DNS TXT)으로 등록했다. URL 접두어 방식보다 나은 이유는
apex·www·앞으로 만들 서브도메인을 한 번에 덮고 **코드 수정이 필요 없기** 때문이다.

```
inyeon-link.com   TXT @  google-site-verification=3UMsiL0Lgx…
naming-link.com   TXT @  google-site-verification=jcm4hhC-Ckn…
```

sitemap 제출 결과:

| | URL | 상태 |
| --- | --- | --- |
| `naming-link.com/sitemap.xml` | 624 | 성공 |
| `inyeon-link.com/sitemap.xml` | 552 | 성공 |

## 4. 오늘 걸린 함정

- **Vercel Settings 사이드바에 Domains가 없다.** UI가 바뀌어 팀 Settings와 프로젝트 Settings가
  헷갈린다. 직접 주소가 확실하다 —
  `vercel.com/<team>/<project>/settings/domains`
- **Add Domains 대화상자는 "하나의 destination"만 받는다.** apex와 www를 한 번에 넣으면 둘 다
  같은 설정이 걸린다. **두 번에 나눠** 넣어야 한다(apex=Production 연결, www=308 리디렉션).
- **`Include apex and www variants` 체크는 해제해야 한다.** 방향을 자동으로 정해 버려서 앞서
  만든 apex 설정을 덮을 수 있다.
- **308이지 307이 아니다.** 307은 임시라 검색엔진이 www와 apex를 **둘 다** 들고 간다.
- **서치 콘솔 목록 화면은 갱신이 늦다.** 상세 화면이 정본이다.

## 5. 내가 틀렸던 것 셋

기록으로 남긴다. 같은 방식으로 또 틀릴 수 있다.

**① "인연링크 SEO 미착수"** — 낡은 메모리를 보고 말했다. 실제로는 다 돼 있었다.
**메모리는 쓸 때의 사실이지 지금의 사실이 아니다.**

**② "본문 크기 제한이 없다"** — `readJsonBodyLimited`라는 **헬퍼 이름**으로 찾았는데 그 앱은
같은 일을 인라인으로 하고 있었다. **기능이 아니라 이름을 찾으면 없는 결함을 만든다.**

**③ "naming-link sitemap만 실패했으니 진짜 문제"** — 목록 화면의 시차를 보고 성급히 단정했다.
잠시 뒤 둘 다 성공으로 바뀌었다. **한 화면만 보고 결론 내지 말 것.**

전부 **남의 답을 기다리는 것**이라 코드 쪽에서 급히 할 일이 없다.

| 항목 | 기다리는 것 |

| 애드센스 | naming-link 심사 결과 → **그 뒤에** 인연링크 사이트 추가(`NEXT_PUBLIC_ADSENSE_CLIENT` + 슬롯) |
| 토스 키 | → 통신판매업 신고 → 실주문 검증(ar 로케일 필수) → 테스트채널 정리 → 엄격 CSP |

**애드센스를 지금 인연링크에 추가하지 않기로 했다.** 계정 첫 승인이 걸린 상태라 지금 얹어도
광고가 안 나오고(얻는 것이 없고), 갓 연결해 색인 0인 도메인을 심사 중에 더하면 심사자가 볼
표면만 늘어난다. naming-link 승인 후 추가하면 그때는 색인도 쌓여 있다.

### 며칠 뒤 볼 곳

`색인 생성 → 페이지`의 "생성되지 않음" 사유. 아래 둘은 **정상이니 놀라지 말 것.**
