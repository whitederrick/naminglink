## 1. 형제 셋에 GAM·CSP 이식 (`7217110`)

어제 naminglink에서 잡은 결함 묶음을 인연·사주·드림에 그대로 옮겼다. 셋은 파일이 다 있었지만
**넷이 같은 코드였으므로 같은 자리에서 같이 죽어 있었다.**

- **`enableServices()` 누락** — 슬롯을 정의하고 `display`까지 불러도 서비스를 켜지 않으면
  광고를 요청하지 않는다. 늘 4초 뒤 `unavailable`로 떨어지던 원인
- 공식 순서로 정렬, `display()` 뒤의 `refresh()` 제거
- 모든 종료 경로가 같은 `cleanup()`을 지나게 · 이벤트마다 `event.slot === slot` 확인
- **광고가 보이면 준비 대기 시계를 끄고 닫힘용 안전망(5분)으로 교체**
- CSP: `www.gstatic.com` · `cm.g.doubleclick.net` · `*.safeframe` · `fonts.googleapis.com` ·
  **`media-src` 지시문 신설** · `connect-src`에 `fundingchoicesmessages`

검증: tsc 0 · eslint 0 · `verify-ads-csp` ALL PASS(셋 × 끔/켬) · **켠 상태 CSP 12줄이
naminglink와 문자열까지 일치**.

### 처음 잰 값은 틀렸다 — Git Bash가 값을 바꿔치기했다

```
NEXT_PUBLIC_GAM_REWARDED_UNIT=/23368513235/test_rewarded
→ "C:/Program Files/Git/23368513235/test_rewarded"
```

MSYS가 `/`로 시작하는 값을 윈도 경로로 변환한다. 형식 검사를 통과하지 못하니 GAM이 꺼진
상태가 되고, 검사기는 **「광고 꺼짐」 갈래를 검사해 ALL PASS**를 찍었다. 초록불인데 재려던
것을 재지 않은 상태였다. `MSYS_NO_PATHCONV=1`로 다시 쟀다.

## 2. 정적화 — 왜 레이아웃을 둘로 갈랐나

`app/layout.tsx`가 `getRequestLocale()` → `headers()`를 불렀다. **루트 레이아웃에서 요청
헤더를 읽으면 그 아래 전부가 정적 렌더링에서 빠진다.**

이 앱에는 주소 체계가 둘이다 — 로케일이 붙는 주소(`/ja/about`)와, 화면이 한국어뿐이라
붙지 않는 한 벌짜리 주소(`/hanja-meaning`)다. `<html lang>`은 루트 레이아웃만 정할 수 있어
**둘을 한 레이아웃에 담을 수 없다.**

```
app/(korean)/    <html lang="ko">     요청을 읽지 않는다
app/[locale]/    <html lang={locale}>  generateStaticParams = 23개 · dynamicParams = false
```

**공개 주소는 하나도 바뀌지 않는다** — 라우트 그룹은 경로에 나타나지 않고, 로케일은 예전에도
이용자가 보던 주소에 있었다(미들웨어가 안에서만 평평한 라우트로 되돌렸다).

### 요청을 읽던 자리를 옮겼다

- 화면 스물여덟: `getRequestLocale(searchParams.lang)` → `const LOCALE = "ko"` 또는
  `routeLocale(params.locale)`
- 미들웨어의 로케일 rewrite와 `x-locale`·`x-block-korean` 헤더 계약 제거
- 안내 문서의 `?from=`은 **돌아가기 목적지**만 바꾼다 → 브라우저가 읽는다(`GuideBackLink`)
- 안내 허브의 `?from=`은 **카드 순서**만 바꾼다 → 서버는 기본 순서로 그리고 브라우저가
  CSS `order`만 갈아 끼운다(`GuideEntryOrder`). 순위표는 서버가 계산해 넘겨 갈래 판정
  규칙이 두 곳에 생기지 않는다

### 값이 굳지 않게 했다

정적화는 **그때 읽은 값을 HTML에 박는다.**

```
docValues()              unstable_cache + PRODUCT_SETTINGS_TAG    금액
getPublishedPolicyDocument()  POLICY_CONTENT_TAG                  약관·개인정보·환불·가격
api/admin/products · site-content   저장·게시할 때 revalidateTag
```

푸터는 이미 `FOOTER_CONTENT_TAG`가 같은 일을 하고 있었다.

### 일부러 동적으로 남긴 셋

```
/notice              ?page= 쪽번호를 서버가 읽어야 목록이 잘린다
/stamp-order         ?name= 채움 + 모델별 실시간 금액
/global-to-korean    한 주소에 서비스가 둘(?mode=), canonical도 갈린다
```

색인 139건 중 43건이 여기 해당한다. 나머지 96건은 이제 미리 만들어진다.

### 개인·운영 화면도 정적이지만 값은 안 담긴다

`/account`·`/login`·`/naming-artist/**`가 함께 미리 만들어진다. 셋 다 `"use client"`
껍데기이고 **서버에서 DB를 읽는 자리가 0건**임을 확인하고 남겼다 — 정적 HTML에 담기는 것은
틀과 문구뿐이고 데이터는 로그인 뒤 브라우저가 받는다.

## 4. 형제 셋 광고 게이트 (`318629d`) — 등록 전 필수

실측: 인연·사주·드림 셋 다 `adsAllowedForLocale`·`adEligibleLocales`·`AD_MODE`가 **0건**
이었다. 이대로 애드센스에 등록하면 kk·km·mn·uz 화면에 광고 코드가 나간다 — 게시자 정책이
금지하는 자리이고, naminglink가 8월 10일에 겪은 반려의 이웃이다.

- **심사/운영 모드** — `NEXT_PUBLIC_AD_MODE`, 기본값은 심사
- **지원 ∩ 검수** — 구글 지원 19개 언어 ∩ 사람이 읽어 본 언어. 지금은 **ko 하나**
- **`X-Ad-Mode`·`X-Ad-Locales`** — 렌더링을 가르는 값과 같은 모듈에서 헤더를 만든다
- **배선이 핵심이다** — `AdBanner`가 실제로 부르게 했다. 실을 수 없는 언어에서는 `<ins>`도
  `adsbygoogle.push()` 요청도 개발 자리 표시도 나가지 않는다. `ads.txt`와 소유권 메타는
  건드리지 않는다(사이트 연결이 살아 있어야 심사가 코드를 찾는다)

앱마다 따로 재고 넘어갔다 — 셋 모두 `ko true / en false / kk·km·uz·mn false`,
적격 `ko`, 미지원 `uz,mn,km,kk`, AdBanner 호출 있음, `verify-ads-csp` ALL PASS.

  `ADSENSE / GAM / SELF`
