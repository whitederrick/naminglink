## 1. 검사기의 두 구멍을 막았다 (`fb7655d`)

같은 병이었다 — **실패를 실패로 내놓지 않는 것.**

### 화면이 실제로 떴는지 센다

`verify-no-ad-requests`가 응답 코드를 보지 않았다. 경로가 틀리거나 라우트가 사라지면 아무것도
없는 주소를 열어 놓고 **「광고 요청 0건」으로 조용히 통과**했다.

본문 프레임의 최종 응답 코드를 받아 기대값과 맞춘다. **프레임을 가르는 것이 핵심이다** — 화면
안의 광고 iframe도 `Document` 응답을 내므로, 안 가르면 광고가 붙은 화면에서만 엉뚱한 코드를
읽는다.

이 검사에는 **대조군이 안에 들어 있다.** 같은 회차에서 200 기대 일곱과 404 기대 하나가 동시에
맞아야 하므로, 코드를 못 읽고 있으면 통째로 실패한다.

> 이 구멍은 그날 저녁에 바로 값을 했다. 형제 앱 실측에서 「응답 코드 어긋남 1건」이 떴고,
> 원인은 내가 검사 경로에 넣은 `/en/login`이 **형제 앱에 없는 라우트**였던 것이다.

### 답이 안 오면 던진다 (exit 13)

외부 점검이 「다른 PC에서 `Network.enable`에 멈추고 exit 13으로 끝난다」고 보고했다. **내 PC에서는
재현되지 않았다.** 그래도 검사기 결함이었다.

Node의 종료 코드 13은 **unsettled top-level await**다. `cdp.send`에 시간 한계가 없어 답이 안
오면 약속을 영영 붙들었고, 소켓이 닫혀도 아무도 깨우지 않았다 — 오류도 실패도 없이 조용히
죽는다.

진짜 원인은 **포트를 추측한 것**이었다.

    const port = 9222 + Math.floor(process.pid % 500);   // ← 이것

원격 디버깅을 켠 크롬이 이미 떠 있으면 **남의 브라우저에 붙는다.** PC마다 재현이 갈린 이유가
이것이다. 고침은 포트를 고르지 않고 크롬에게 묻는 것 — `--remote-debugging-port=0`을 주고
크롬이 자기 프로필에 적은 `DevToolsActivePort`에서 주소를 읽는다.

함께: CDP 30초 한계(넘으면 **명령 이름과 함께** 던진다) · 소켓 close/error에 남은 약속 깨우기 ·
크롬이 먼저 죽으면 즉시 알리기 · 모는 쪽이 깨지면 **「확인 못 함」 + exit 1**.

## 5. P0 — 전역 로더를 걷어내고 하나씩 승격했다 (`24132b0` · `9dd3012`)

세 앱 `layout.tsx` 한 파일씩, 두 군데씩. 다른 파일은 건드리지 않았다.

1. `generateMetadata()`에 `google-adsense-account` 소유권 메타 — 로더를 빼도 사이트 연결이
   끊기지 않는다. 주석에 「`adsEnabled`는 **게재가 아니라 연결** 여부다. 비우면 `ads.txt`가
   404가 되고 이 태그도 함께 죽는다」를 박았다
2. 전역 `<script>` 제거 — 자리에 왜 없는지를 남겼다

**env가 아니라 코드로 껐다.** env를 비우면 다음에 값을 넣는 순간 되살아나는 고침이다.

### 브랜치로 올리고 하나씩 승격

`main`에 밀면 그 순간이 naming-link의 Production 브랜치를 건드리는 순간이다. 그래서
`p0-sibling-ads` 브랜치로 올렸다 — 브랜치 푸시는 Preview만 만든다. 새로 만든 이름이라 어느
프로젝트의 Production 브랜치일 수도 없다.

승격은 **하나씩** 했다(외부 제안). 롤백 범위가 한 프로젝트로 좁아지고, **덤으로 대조군이
생긴다** — 아직 승격 안 한 도메인이 「고치기 전」 상태를 계속 보여 준다.

    회차 1  inyeon 승격   inyeon 0건 · saju 56건 · dreams 56건   ← 뒤 둘이 대조군
    회차 2  saju 승격     inyeon 0건 · saju 0건 · dreams 64건    ← dreams가 대조군
    회차 3  dreams 승격   셋 다 0건 + 일부러 낸 요청은 잡힘      ← 대조군을 만들어 세움

마지막 회차에는 살아 있는 대조군이 없어지므로, 광고 호스트로 **요청을 일부러 한 번 만들어**
탐지기가 살아 있는지 먼저 확인했다. 이것이 없으면 「0건」과 「측정이 죽었다」가 구별되지 않는다.

### 최종 상태 — 네 도메인이 같아졌다

    로더 adsbygoogle.js   0건
    소유권 메타           <meta> 1개 · ca-pub-5084236528895241
    ads.txt               200 · pub ID 유지
    화면 8곳 × 3도메인     애드센스 요청 0건 · 응답 코드 어긋남 0건 · ALL PASS · exit 0

**GAM 보상형 관문은 그대로 뒀다**(사용자 결정). 제출 경로에서 `gpt.js`가 계속 실린다 — 이용자가
직접 선택해 보는 광고이고 결과를 만드는 행동에 붙어 있어 「콘텐츠 없는 화면의 광고」와 다른
자리다. inyeon·saju는 관문이 배선돼 있고 **dreams는 `AdWatchOverlay`가 있는데 어느 폼도 부르지
않는다**(복제 앱이 배선을 빠뜨린 그 패턴).

## 6. 이 날 내가 낸 실수

### 「naming-link은 재배포하지 않는다」고 적어 놓고 세 번 재배포시켰다

승격하려고 열어 본 Vercel 이력이 이걸 보여 줬다.

    101de87  docs 하나          → Production
    facd3bb  docs + CSV         → Production
    fb7655d  scripts + .agents  → Production
    038a6a3  docs 하나          → Production

**저장소 뿌리의 문서 커밋이 네 프로젝트를 전부 재배포한다.** 「루트 디렉터리에 변경 없으면
건너뛰기」가 걸려 있지 않다. 규칙을 세운 사람이 그 규칙을 깼다.

피해는 없는 것으로 보인다 — 네 커밋 모두 naminglink 앱 소스를 안 건드렸고 재배포 뒤 실측한
값이 의도한 심사 상태 그대로였다. 다만 **「피해가 없었다」와 「해도 되는 일이었다」는 다른
말이다.** 이 관측이 main 병합 보류의 근거가 됐다.

### 관문 없이 비싼 실행부터 던졌다 (사용자 지적)

검사기 편집 여섯 개를 하고 **바로 5~7분짜리 운영 실행을 걸었다.** 문법 검사 같은 싼 관문을 앞에
두지 않았고, 운영에 비회원 분석 1건을 만드는 실행을 확인 없이 던졌다.
`stage-gates-not-more-checks`에 「관문은 비싼 단계 **앞**에」라고 적어 둔 그 자리다.

### 옮겨 적으면서 한정어를 떨어뜨렸다

워크로그에는 「양성 `/hanja-meaning` **결과**」라고 옳게 적혀 있었다. 그것을 정리 문서로 옮기며
「결과」 두 글자가 떨어져 **「`/hanja-meaning`은 광고가 나가는 화면」**이 됐다. 입력 화면에는
광고가 없고, 광고는 제출 뒤 결과 화면에서 나가며 그 화면은 `noindex`다. **한 단어가 빠지면서
권고 목록의 근거가 통째로 뒤집혔다.** 기록은 옳았고 전파에서 깨졌다.

### 짐작으로 판정했다 — 세 번

## 7. 남은 일

### 지금 할 수 있는 것 — 없다

애드센스 갈래는 **naming-link 심사 결과를 기다린다.** 결제 갈래(B·C)는 토스 키·통신판매업
번호·페이팔 심사를 기다린다. 코드로 지금 할 일이 없다.

### 하지 말 것

- **`main`을 밀지 말 것.** `git status`에 `ahead 2`가 보여도 그렇다. main 푸시가 곧
  naming-link Production을 건드리는 순간이고, 그 커밋 중 하나는 저장소 뿌리의 문서다
- **naming-link의 화면·주소·광고·콘텐츠를 바꾸지 말 것**
- **열린 중복 23개(naming 6 · inyeon 17)에 손대지 말 것.** 2차 조치는 재거절이 확인된 뒤다
- **형제 앱을 애드센스 콘솔에 추가하지 말 것.** 심사 중에 색인 0인 도메인을 더하면 심사자가
  볼 표면만 늘어난다

### 승인이 나면 — 순서대로

1. **`NEXT_PUBLIC_AD_MODE=live` + 재배포.** 광고 관문·문구·후보 잠금이 함께 돌아온다.
   **잊기 쉬운 자리다** — 관문을 끈 것은 일시적 조치였고 그동안 후보 열기 광고 수익이 0이었다
2. `npx tsx --tsconfig scripts/tsconfig.sweep.json scripts/verify-ad-mode.ts`로 양쪽 확인
3. **`p0-sibling-ads`를 `main`에 합치고 푸시.** 이때 naming-link이 재배포돼도 무방하다
4. **P1** — `packages/core`에 광고 정책 한 벌. **형제 셋만 먼저**, naming-link의 `ads.ts`
   이관은 그 뒤. 경계는 「판정 규칙과 타입은 core, 어느 화면 어느 슬롯은 앱」
5. **P2** — `verify-no-ad-requests`가 앱을 인자로 받게. 목록은 `APP_KEYS`에서 읽고,
   **표에 없는 앱은 실패**. 전역 로더 부활을 잡는 정적 검사도 함께
