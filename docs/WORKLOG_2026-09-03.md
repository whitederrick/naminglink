## 1. 배치 55 — 밀러 `Hurricane`·`Husband`

표제어 둘 · 항목 16개. 새 상징 하나 — `hurricane`(태풍). `Husband` 열둘은 이미 있는
`husband`(남편)에 붙였다.

**`Husband` 하나가 열두 항목이라 두 표제어로 판을 끊었다**(배치 크기는 표제어 수가 아니라
일감으로 잡는다 — 배치 43·50과 같은 판단). `Hut` 부터는 다음 판이다.

### 별칭 「태풍」을 `wind` 에서 `hurricane` 으로 넘겼다

밀러가 `Wind` 와 `Hurricane` 을 따로 두고, 「태풍」은 태풍의 것이 더 정확하다
(§25 곁가지 — 「대문」 `door`→`gate` · 「말벌」 `bee`→`hornet` 과 같다).
**「회오리」·「강풍」·「돌풍」은 `wind` 가 그대로 갖는다.** 다른 상징의 판별어에 있는 「태풍」은
안 건드렸다 — 한국어 판별어는 별칭 임자와 무관하게 산다.

프로브에 `wind` 의 옛 답 둘을 지킴 케이스로 넣어 안 깨진 것을 확인했다.

### `husband` 는 **판별어 표가 비어 있었다**

의미가 하나(주공해몽 「남편을 품에 안음」)뿐이라 판별어가 없어도 됐다. **열둘을 붙이는
순간 모두 있어야 한다**(배치 35·38에서 배운 자리) — 기존 것도 함께 채웠다. 안 채웠으면
그 의미가 0점으로 남아 어떤 문장으로도 안 뽑힌다.

그리고 그것이 **이 상징의 기본값**이라 판별어를 「품에 안았」로 좁게 적었다 — 얼린 자리는
동점을 전부 가져간다(§30 곁가지). 기본값은 `FALLBACK_FIRST` 에 **있던 값 그대로** 얼렸다:
밀러 열둘이 전부 좁은 상황(떠남·죽음·창백함…)이라 기본값 자리가 아니다.

### 「여성이~」 갈래가 열둘인데도 부딪치지 않았다

배치 50~52에서 **한 상징에 「여성이~」 갈래는 하나뿐**이라는 것을 세 번 만났는데, `Husband`
표제어는 **열두 문장이 전부 아내가 남편을 보는 이야기**인데도 문제가 없었다.

→ **가르는 것이 「여성이냐」가 아니라 「남편이 무엇을 하느냐」이기 때문이다**(떠남·꾸짖음·
죽음·창백함·앓음·딴 여자…). 「여성이~」가 부딪치는 것은 **성별이 유일한 구분일 때**이지
그 갈래가 여럿일 때가 아니다 — 배치 50의 기록을 이렇게 좁혀 둔다.

### 영어 판별어가 또 글자로 물렸다

```
unfaithful ⊂ unfaithfulness    남편이 앓고 있음 ↔ 남편이 딴마음을 품었다고 꾸짖음
```

배치 50~52의 `horse` 와 같은 자리다. 둘 다 이번에 넣은 것이라 뒤엣것을 `ails` 로 갈았다.

### 커버리지 — 안 넣은 문장 셋은 **풀이의 뒷말**이다

```
"You will move and remove to distant places…"   ← 무너지는 집에서 끌어냄의 뒷말
"If disagreeable conclusions are avoided…"      ← 멀어지며 커 보임의 뒷말
"Unfavorable conditions follow this dream…"     ← 추문이 남의 뒷말
```

셋 다 **새 꿈 그림이 아니라 앞 항목 풀이의 이어지는 말**이라 각 항목의 `interpretation_ko`
에 녹였다. 커버리지 대조에서 비어 보이는 것이 옳고, 패치 머리말에 적었다(§24).

## 2. ⓪ 전수 grep — **겹친 이름 아홉이 전부 안전했다**

새 이름과 별칭이 기존 이름을 품는 자리가 아홉인데, **전부 앞 글자가 한글이라 `isStandalone`
이 막는다.** 품음 관계를 찾은 자리에서 멈추지 않고 손으로 한 번 돌려 본 결과다(§25 곁가지).

```
광견병 ⊃ 광견(dog)      「병」이 조사가 아니다        안전
공수병 ⊃ 병(illness)     「수」가 한글이다            안전
초가집·오두막집 ⊃ 집     〃                          안전
히아신스꽃 ⊃ 꽃(flower)  〃                          안전
히솝풀 ⊃ 풀(grass)       〃                          안전
하이에나 ⊃ 이(teeth)     〃                          안전
히아신스 ⊃ 신(deity)     〃                          안전
```

**하나는 실제로 뺐다 — 「성가」.** `choir`(성가대)가 이미 그 자리를 쥐고 있고 뜻도 가깝다.
`hymn` 의 별칭은 「찬송」·「찬송가 부르는 소리」·「찬송가 소리」로 두었다.

## 3. 지킴 케이스가 **옛 상처 하나**를 찾았다 — 배치 56이 만든 것이 아니다

프로브에 매 판 넣는 「옛 답이 그대로인가」 여섯 중 하나가 빨간불이었다.

```
「미친개에게 물렸다」  →  바란 것: 미친개에게 물림   나온 것: 개에게 물림
```

`dog` 의 세 의미가 **「미친개」라는 말을 아무도 안 갖고 있었다**(배치 27a 이래).

```
개에게 물림       「물렸 깨물 물린」
미친개를 봄       「미쳐 날뛰 거품을」    ← 「미친개를 보았다」는 0점 → 기본값으로 떨어졌다
미친개에게 물림   「광견에게 발작 침을」  ← 「미친개에게 물렸다」는 0점 → 넓은 쪽에 뺏겼다
```

**어떤 관문도 못 본다** — 낱말이 겹치지도 죽지도 않았다(§30 곁가지). 셋 다 초록불이었다.

고침은 **낱말을 나눠 갖지 않고 차례로** 풀었다(§25 곁가지 3) — 좁은 쪽에 「미친개에게」·
「미친개를」·「미친개가」·「미친개한테」를 주고, `m27a.json` 에서 미친개 둘을 「개에게 물림」
**앞으로** 옮겼다. 「물렸」을 형제끼리 나눠 가지면 `verify-dream-km` 이 「동점 위험」으로 막는다.
**첫 의미(기본값 「사나운 개가 나타남」)는 안 건드렸다** — 패치가 되읽어 확인한다.

# 배치 57 — 밀러 `Ice`·`Icicles`·`Ice Cream`

## 1. 넣은 것 — 표제어 셋, 상징 셋, 항목 열여덟

```
Ice(12문장) → 얼음(8) + 고드름(4)      ← 한 표제어를 두 상징으로 갈랐다
Icicles(1)  → 고드름(1)
Ice Cream(5) → 아이스크림(5)
```

**`Ice` 의 열두 문장 가운데 넷은 고드름 이야기다**(처마·울타리·나무·늘푸른나무). 이용자가
「고드름」이라고 쓰지 「얼음」이라고 쓰지 않으므로 `icicle` 상징으로 옮겼고, `Icicles` 표제어의
한 문장이 그 다섯째가 됐다. **인용의 `locator` 는 원문 그대로 남긴다**(넷은 `Ice`, 하나는
`Icicles`) — 커버리지 대조는 그 값으로 세므로 두 표제어가 다 채워진다.

「Eating ice… If you drink ice-water…」는 **한 문단에 든 두 그림**이라 항목 둘로 갈랐다.

## 2. 「처녀가 얼음 위를 걸음」을 넣을 수 있었던 까닭

배치 50~52에서는 「여자가·여성이·처녀가」 갈래가 **둘 이상**이라 문장을 뺐다. 여기는
그 갈래가 **하나**이고 짝이 되는 일반 문장(「얼음 위를 걸음」)이 따로 있다 —
`처녀 아가씨 처자` 대 `걸었 걸어가 밟고` 로 **1:1 동점**이 되고, 좁은 쪽을 파일에서
앞에 두어 풀었다(§25 곁가지 3). 배치 55에서 좁힌 규칙이 그대로 들어맞은 자리다.

같은 수를 고드름에도 썼다 — 「나무에서 떨어지는 것」과 「나무에 달린 것」이 「나무에」로
동점이 되므로 **떨어지는 쪽을 앞에** 두었다. 「늘푸른나무」와 「나무에」도 같다.

## 3. 대표(첫) 의미의 판별어를 좁게 적었다

`ice` 의 「얼음을 봄」과 `ice-cream` 의 「아이스크림을 먹음」이 기본값 자리다. 여기에
「보았」·「먹었」 같은 흔한 말을 주면 **구체적인 형제가 영영 안 뽑힌다**(§30 곁가지).
각각 「얼음덩이 커다란」·「맛있게 달콤」만 남겼다 — 아무것도 안 걸리면 어차피 이 자리로
떨어지므로 제 일을 한다. 실제로 「아이들이 아이스크림을 먹고 있었다」가 아이들 쪽으로 갔다.

## 4. 관문에서 하나 걸렸다 — 뜻이 아니라 **글자**가 물렸다

```
verify-dream-km  「thin」(처녀가 얼음 위를 걸음) ⊂ 「ba-thin-g」(얼음물에 몸을 담금)
```

# 배치 58 — 밀러 `Absalom`~`Illness` (앞 배치들이 빠뜨린 셋을 함께 채웠다)

## 1. 넣은 것 — 표제어 일곱, 항목 열다섯

```
새 상징 여섯   압살롬 · 습기 · 이상형 · 어리석은 사람 · 게으름 · 우상

```

이미 이유가 적혀 있다.

**`Abortion` 은 넣지 않았다 — 이유를 여기 적는다.** 밀러의 두 문장은 낙태를 두고
「수치와 불행」·「직무 태만」을 점친다. 낱말이 비하인 자리(§31 앞갈래)도, 같은 그림이
이미 있는 자리도 아니다 — **오늘의 이용자에게 그대로 보여 주기에 해로운 판정**이라는
셋째 이유다. 23개 언어 화면에 뜨는 글이라 되돌리려면 이 줄을 지우고 다시 넣으면 된다.

## 2. `Illness` 를 기존 `병` 에 붙이면서 **기본값이 뒤집혔다**

조립기의 관문이 잡았다(§30).

```
illness (병)   전: 병들어 누웠는데 남이 부축해 줌   후: 여자가 제 병을 앓는 꿈을 꿈
```

`m58.json` 이 `r*.json` 보다 먼저 정렬되므로 밀러 의미가 첫째로 올라간 것이다.
**있던 답 그대로 얼렸다**(`FALLBACK_FIRST`) — 들어온 밀러 의미는 「꾸는 사람이 여자」라는
조건이 붙은 자리이지 아무것도 안 걸린 꿈이 떨어질 자리가 아니다.

가르는 것이 성별뿐인 자리인데도 넣을 수 있었던 까닭은 **그 갈래가 하나**이고 짝이 되는
것이 일반 문장(「자기가 병듦」)이라서다 — 배치 55에서 좁힌 규칙, 배치 57의 「처녀가 얼음
위를 걸음」과 같은 자리다.

## 3. 프로브가 다섯을 잡았다 — 셋은 내 데이터, 둘은 내 문장

```
안 걸림  어리숙해 보이는 아이들을 보았다   → 상징 이름이 문장에 없었다 (별칭 넷을 더했다)
안 걸림  내가 빈둥거리고 있었다            → 「빈둥거림」은 「빈둥거리고」에 안 걸린다
안 걸림  친구들이 빈둥거리는 것을 보았다    → 〃
안 걸림  병들어 누웠는데 …                → **내 문장이 틀렸다** (아래)
```

**「빈둥거림」이 또 같은 병이다**(§29 곁가지 ① · 이번이 여덟 번째). 뒤에 오는 「고」·「는」·
「며」가 조사가 아니다 — 완전한 활용형 여섯을 별칭으로 올렸다.

**「병들어 누웠는데」는 내 문장이 틀렸다.** 「병」 뒤의 「들」이 조사가 아니라 `illness` 가 안
걸리고, 「병들어」는 **`disease`(병듦)가 이미 별칭으로 갖고 있다** — 남의 이름이라 뺏지
않는다(§28). 문장을 「병이 나서 누웠는데」로 고쳤다. 이용자가 실제로 쓰는 꼴이고 상징
이름이 그 안에 있다.

## 4. 기록만 해 둔 것 — `crab` 이 「의미가 중복인 자리」의 여덟 번째다

지킴 케이스 「게를 보았다」가 「게들을 봄」으로 갔다. 읽어 보니 **어느 쪽이 옳다고 말할 수
없는 자리**였다.

```
[0] 게들을 봄  (밀러 Crabs, 흉)   To dream of crabs, … many complicated affairs …
[2] 게를 봄    (주공해몽, 길)      螃蟹主百病消散
```

**둘 다 「게를 보았다」라는 같은 그림이고 길흉이 반대다.** 판별어로는 못 가른다 —
메모리에 적힌 「의미가 중복인 7곳」(`blood`·`shackles`·`bee`·`bathing`·`annoy`·`bride`·
`childbed`)과 같은 갈래이고, `crab` 이 여덟째다. **이번 변경이 만든 것이 아니다.**
지킴 케이스는 판정이 서는 「연인에게 게 꿈이 나타남」으로 바꿨다.

## 4. 프로브가 **옛 상처 하나**를 찾았다 — 배치 62가 만든 것이 아니다

지금까지 스물여덟 판에서 밀어낸 기본값은 거의 다 **있던 답으로 되돌렸다.** 이번은
배치 54(`hunting`·`embrace`)와 같은 **바꾸는 것이 옳은 자리**다 — 다리미 꿈의 가장
일반적인 그림은 「다림질을 함」이고, 있던 주공해몽 의미는 **숯불 다리미**라는 좁은 상황이다.
`FALLBACK_FIRST` 에 **새 값으로** 적어 얼렸다(여든다섯).

## 3. 한 글자 이름 「섬」을 그대로 썼다

§29 곁가지 ③은 **한 글자 이름은 동형이의어 활용형에 걸린다**고 경고한다. 「섬」을 실제로
따져 보니 안전했다 — 「섬기다」·「섬세한」은 뒤가 한글이라 `isStandalone` 이 막고, 「제주섬」
처럼 앞이 한글인 자리도 막힌다. `verify-dream-km` 도 통과했다(막는 것은 **한 글자 이름에
한 글자 별칭**을 다는 자리다). 조사를 붙인 꼴(「섬을」·「섬이」·「섬에」)을 별칭으로 함께 올렸다.

## 4. 프로브가 넷을 잡았다 — 전부 §29 곁가지 ①

```
「다림질하」 + 다     ✗   「다」는 조사가 아니다 — **「다림질하다」까지 올려야 한다**
「차가워」   ≠ 차가웠  ✗   판별어도 이용자가 칠 꼴로
「근질거」   + 렸다   ✗
```

**「~하」로 끝낸 별칭이 「~하다」에 안 걸리는 것**은 배치 30에서 「말을 잘」+해서로 이미 겪은
자리인데, 이번엔 **「하다」 자체가 뒤에 오는** 꼴이라 또 밟았다.

## 2. **표제어가 `Jailer` 라도 그 꿈의 사물이 「간수」가 아닐 수 있다**

「무리가 옥문을 부수려 함」을 `jailer` 에 붙였다가 **프로브가 「간수로는 안 걸린다」**고 잡아

그 사물이 있는가」다). **표제어를 임자로 삼는 습관이 만든 자리**이고, 이번이 처음이다.

## 3. 옛 상처 — **「옥에 갇혔다」가 운영에서 `jade`(옥)로 답하고 있었다**

`prison` 의 화면 문구 여섯이 「옥에…」인데 별칭에 그 꼴이 없었다. 실측하면 이랬다.

```
「옥에 갇혀 앉아 있었다」   → jade / 「금은과 주옥을 봄」    ← 나가던 답이다
「남을 감옥에 집어넣었다」  → prison / 「남을 옥에 들여보냄」 (이쪽은 옳다)
```

「옥」은 한 글자라 별칭으로 못 올린다 — **구슬 옥과 감옥 옥이 같은 글자다.** 구절째
(「옥에 갇혀」·「옥에 들어갔다」·「옥에 집어넣었다」·「옥중」·「옥문」) 올려 **감옥도 함께
걸리게** 했다. **`jade` 쪽은 안 건드렸다** — 누가 「옥」의 임자인지는 사람이 정할 일이고,
코드가 대신 정하면 그 판단이 묻힌다(§28).

**구절 별칭도 낱말 경계에서 끝나야 한다** — 처음에 「옥에 갇」으로 올렸더니 뒤의 「혀」가
조사가 아니라 막혔다. §29 곁가지 ①이 **한 낱말이 아니라 구절에도 그대로 적용된다.**
