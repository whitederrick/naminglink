## 1. 배치 55 — 밀러 `Hurricane`·`Husband`

표제어 둘 · 항목 16개. 새 상징 하나 — `hurricane`(태풍). `Husband` 열둘은 이미 있는
`husband`(남편)에 붙였다.

**`Husband` 하나가 열두 항목이라 두 표제어로 판을 끊었다**(배치 크기는 표제어 수가 아니라
일감으로 잡는다 — 배치 43·50과 같은 판단). `Hut` 부터는 다음 판이다.

### 별칭 「태풍」을 `wind` 에서 `hurricane` 으로 넘겼다

밀러가 `Wind` 와 `Hurricane` 을 따로 두고, 「태풍」은 태풍의 것이 더 정확하다
(§25 곁가지 — 「대문」 `door`→`gate` · 「말벌」 `bee`→`hornet` 과 같다).
**「회오리」·「강풍」·「돌풍」은 `wind` 가 그대로 갖는다.** 다른 상징의 판별어에 있는 「태풍」은
안 건드렸다 — 한국어 판별어는 별칭 임자와 무관하게 산다.

프로브에 `wind` 의 옛 답 둘을 지킴 케이스로 넣어 안 깨진 것을 확인했다.

### `husband` 는 **판별어 표가 비어 있었다**

의미가 하나(주공해몽 「남편을 품에 안음」)뿐이라 판별어가 없어도 됐다. **열둘을 붙이는
순간 모두 있어야 한다**(배치 35·38에서 배운 자리) — 기존 것도 함께 채웠다. 안 채웠으면
그 의미가 0점으로 남아 어떤 문장으로도 안 뽑힌다.

그리고 그것이 **이 상징의 기본값**이라 판별어를 「품에 안았」로 좁게 적었다 — 얼린 자리는
동점을 전부 가져간다(§30 곁가지). 기본값은 `FALLBACK_FIRST` 에 **있던 값 그대로** 얼렸다:
밀러 열둘이 전부 좁은 상황(떠남·죽음·창백함…)이라 기본값 자리가 아니다.

### 「여성이~」 갈래가 열둘인데도 부딪치지 않았다

배치 50~52에서 **한 상징에 「여성이~」 갈래는 하나뿐**이라는 것을 세 번 만났는데, `Husband`
표제어는 **열두 문장이 전부 아내가 남편을 보는 이야기**인데도 문제가 없었다.

→ **가르는 것이 「여성이냐」가 아니라 「남편이 무엇을 하느냐」이기 때문이다**(떠남·꾸짖음·
죽음·창백함·앓음·딴 여자…). 「여성이~」가 부딪치는 것은 **성별이 유일한 구분일 때**이지
그 갈래가 여럿일 때가 아니다 — 배치 50의 기록을 이렇게 좁혀 둔다.

### 영어 판별어가 또 글자로 물렸다

```
unfaithful ⊂ unfaithfulness    남편이 앓고 있음 ↔ 남편이 딴마음을 품었다고 꾸짖음
```

배치 50~52의 `horse` 와 같은 자리다. 둘 다 이번에 넣은 것이라 뒤엣것을 `ails` 로 갈았다.

### 커버리지 — 안 넣은 문장 셋은 **풀이의 뒷말**이다

```
"You will move and remove to distant places…"   ← 무너지는 집에서 끌어냄의 뒷말
"If disagreeable conclusions are avoided…"      ← 멀어지며 커 보임의 뒷말
"Unfavorable conditions follow this dream…"     ← 추문이 남의 뒷말
```

셋 다 **새 꿈 그림이 아니라 앞 항목 풀이의 이어지는 말**이라 각 항목의 `interpretation_ko`
에 녹였다. 커버리지 대조에서 비어 보이는 것이 옳고, 패치 머리말에 적었다(§24).

# 배치 56 — 밀러 `Hut`~`Hyssop` (07:40~)

## 1. 넣은 것

표제어 일곱 · 항목 열셋. **일곱 다 새 상징이고 기존 상징의 의미는 하나도 안 건드렸다.**

```
Hut(3) 오두막 · Hyacinth(1) 히아신스 · Hydrophobia(3) 공수병 · Hyena(2) 하이에나 ·
Hymns(1) 찬송가 · Hypocrite(2) 위선자 · Hyssop(1) 우슬초
```

`Hymns` 는 본문 한 문장 뒤에 `[97] See Singing.` 이 붙어 있다 — 참조 지시는 항목이 아니다.
`Hyena` 의 「If lovers have this dream…」은 **가르는 것이 꾸는 사람뿐**이라 넣지 않고
`interpretation_ko` 에 녹였다(§「여성이~」 갈래와 같은 자리, 09-03 배치 55에서 좁힌 규칙).
`Hyssop` 의 「if a woman…」도 같다.

## 2. ⓪ 전수 grep — **겹친 이름 아홉이 전부 안전했다**

새 이름과 별칭이 기존 이름을 품는 자리가 아홉인데, **전부 앞 글자가 한글이라 `isStandalone`
이 막는다.** 품음 관계를 찾은 자리에서 멈추지 않고 손으로 한 번 돌려 본 결과다(§25 곁가지).

```
광견병 ⊃ 광견(dog)      「병」이 조사가 아니다        안전
공수병 ⊃ 병(illness)     「수」가 한글이다            안전
초가집·오두막집 ⊃ 집     〃                          안전
히아신스꽃 ⊃ 꽃(flower)  〃                          안전
히솝풀 ⊃ 풀(grass)       〃                          안전
하이에나 ⊃ 이(teeth)     〃                          안전
히아신스 ⊃ 신(deity)     〃                          안전
```

**하나는 실제로 뺐다 — 「성가」.** `choir`(성가대)가 이미 그 자리를 쥐고 있고 뜻도 가깝다.
`hymn` 의 별칭은 「찬송」·「찬송가 부르는 소리」·「찬송가 소리」로 두었다.

## 3. 지킴 케이스가 **옛 상처 하나**를 찾았다 — 배치 56이 만든 것이 아니다

프로브에 매 판 넣는 「옛 답이 그대로인가」 여섯 중 하나가 빨간불이었다.

```
「미친개에게 물렸다」  →  바란 것: 미친개에게 물림   나온 것: 개에게 물림
```

`dog` 의 세 의미가 **「미친개」라는 말을 아무도 안 갖고 있었다**(배치 27a 이래).

```
개에게 물림       「물렸 깨물 물린」
미친개를 봄       「미쳐 날뛰 거품을」    ← 「미친개를 보았다」는 0점 → 기본값으로 떨어졌다
미친개에게 물림   「광견에게 발작 침을」  ← 「미친개에게 물렸다」는 0점 → 넓은 쪽에 뺏겼다
```

**어떤 관문도 못 본다** — 낱말이 겹치지도 죽지도 않았다(§30 곁가지). 셋 다 초록불이었다.

고침은 **낱말을 나눠 갖지 않고 차례로** 풀었다(§25 곁가지 3) — 좁은 쪽에 「미친개에게」·
「미친개를」·「미친개가」·「미친개한테」를 주고, `m27a.json` 에서 미친개 둘을 「개에게 물림」
**앞으로** 옮겼다. 「물렸」을 형제끼리 나눠 가지면 `verify-dream-km` 이 「동점 위험」으로 막는다.
**첫 의미(기본값 「사나운 개가 나타남」)는 안 건드렸다** — 패치가 되읽어 확인한다.
