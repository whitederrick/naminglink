# 작업 기록 2026-08-02 — PDF 지면 정밀 점검과 근본 원인

> 어제(`WORKLOG_2026-08-01.md`)는 **글자가 찍히는가**를 전수로 봤다. 오늘은 **자리가 맞는가**를
> 같은 수준으로 올렸다. 사용자 지적이 계기다 — "케이스가 달라질 때마다 결함이 계속될 것 같다."

## 0. 그 지적이 옳았다

어제까지 각 상품은 **입력 한 가지**로만 렌더했다. 그러니 그 입력에서 나오는 지면만 봤고,
케이스를 하나 늘릴 때마다 결함이 하나씩 나왔다. 실제로 그랬다.

| 무엇을 늘렸나 | 그때 나온 결함 |
| --- | --- |
| 로케일 10 → 23 | 이탈리아어 꼬리글 겹침, 한글 아트 빈 지면(11개 로케일) |
| 이름을 상한(24자)으로 | 표 머리행이 옆 칸을 덮음(23로케일 전부) |
| 한글 표기를 상한(51자)으로 | 음절 상자가 지면을 가로지름 |
| 해설을 상한(2,000자)으로 | 문단이 지면 밖으로 흘러넘치고 빈 장이 생김 |
| 검사 기준을 엄격히 | 카드 여백만 남은 빈 지면(14개 파일) |

## 1. 근본 원인은 둘이다

### ① @react-pdf는 **넘침을 오류로 알리지 않는다**

칸을 넘어도, 지면을 넘어도, 겹쳐 찍혀도 렌더는 성공한다. 그래서 "이 값은 이 정도 길이겠지"
라는 **암묵적 가정**이 코드 곳곳에 박히고, 가정이 깨져도 아무도 모른다. 어제 글리프에서 겪은
것과 정확히 같은 구조다(서체에 글자가 없어도 오류가 없었다).

무엇이 가정이었나:

- 표 머리행에 들어가는 이름은 짧다 → 24자면 옆 칸을 덮는다
- 꼬리글은 한 줄이다 → 이탈리아어 고지는 두 줄이라 본문을 침범한다
- 한 절은 한 장을 넘지 않는다 → `wrap={false}`가 붙어 있어 넘치면 **쪼개지 못하고 흘러넘친다**
- 왼쪽 단 두 절·오른쪽 세 절이면 균형이 맞는다 → 언어마다 분량이 달라 한쪽만 넘친다

### ② 값의 길이는 **우리가 정하지 않는다**

이용자가 적고(이름·바람), 모델이 쓰고(해설), 번역자가 늘린다(23로케일). 케이스를 하나씩
더해 가며 잡는 방식으로는 끝이 없다 — 이것이 사용자 지적의 핵심이다.

## 2. 그래서 이렇게 바꿨다

### 케이스를 임의로 고르지 않고 **스키마 상한**에서 가져온다

```
이름            24자      match-input.ts
한글 표기       51자      global-order (어절 12자 × 4)
해설 필드       2,000자   global-order
자유서술        3,000자   checkInputFactorsSize
후보            5개       global-order
서체            5개
```

분량은 값이 커질수록 단조롭게 늘어난다. **양 끝이 버티면 그 사이는 따로 볼 필요가 없다.**
지금 두 앱이 케이스 6 × 로케일 23으로 **607개 PDF**를 매번 만든다. 스키마를 고치면 케이스도
고쳐야 하고, 그 사실을 스크립트 주석에 적어 두었다.

### 지면을 기계가 훑는다

`scripts/audit-pdf-layout.py` — 넘침·겹침·빈 지면·빈 글리프(.notdef)를 잡는다. 눈으로 볼
범위를 크게 줄인다. **꼬리글·서체 표기가 놓이는 아래 띠는 세지 않는다** — 그것만 남은 지면이
진짜 빈 지면이고, 본문 두어 줄이 넘어온 지면은 어느 조판에서나 나오는 정상이다.

### 길이 가정을 코드에서 걷어냈다

| 자리 | 전 | 후 |
| --- | --- | --- |
| 표 머리행 이름 | 그대로 | 10자에서 자름(전체는 머리글에 있다) |
| 음절 표기 | `에·밀·리` | `에 · 밀 · 리` — **서버 normalize**로 끊길 수 있게 |
| 절 묶음 | `wrap={false}` | `minPresenceAhead` — 제목만 남는 것은 막되 쪼개지긴 한다 |
| 2단 배분 | 2절·3절 고정 | **무게로 나눔**(한자·가나·한글은 라틴의 2.1배) |
| 본문 크기 | 고정 | 분량에 따라 5단계(10.5 → 7.4pt) |
| 표 행 | 그대로 | `minPresenceAhead` — 카드 여백만 넘어가는 것을 막는다 |
| 꼬리글 여백 | 56 | 78(두 줄 고지를 견딘다) |
| 서체 표기 | 흐름 안 | 흐름 밖 + `fixed` |

**`fixed` 없이 절대 위치만으로는 부족하다.** @react-pdf는 `fixed`가 아닌 요소를 흐름 기준으로
장에 배정해서, 남은 자리가 없으면 절대 위치라도 다음 장으로 넘어간다.

## 3. 회귀도 한 번 났고, 검사가 잡았다

본문 밀도를 **페이지 전체**에 걸었더니 머리글 줄 간격까지 좁아져 제목이 겹쳤다 — 6건이던
문제가 67건이 됐다. 본문에만 걸도록 고쳐 되돌렸다. 눈으로 봤다면 못 봤을 종류다.

```
42 → 12 → 8 → 6 → 67(회귀) → 6 → 1 → 0
```

## 5. 남은 것

- 아랍어·크메르어 **문단**은 여전히 라이브러리가 렌더하지 못한다(문서는 영어로 낸다).
  렌더 스크립트가 그 자리를 계속 시험하며, 성공하면 알려 준다.
- 결제 키가 없어 **주문 → 결제 → 생성** 배선만 실주문으로 못 태웠다. 번역·렌더는 직접 불러
  확인했다.
