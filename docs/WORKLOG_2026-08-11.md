# 2026-08-11 — 심사 모드: 광고 관문을 끄되 사이트 연결은 지킨다

_naminglink 재심사 준비. 코드 작업은 끝났고 배포·콘솔 작업이 남았다._

---

## 0. 시작점 — 지시서를 그대로 따르지 않았다

외부에서 「심사 기간에 **구글 광고 요청 0건**」을 목표로 하는 지시서가 왔다. 그대로 따르기 전에
사실 확인을 먼저 했고, 두 가지가 달랐다.

**① 광고 코드 전면 제거는 구글의 절차가 아니다.** 표준은 「콘텐츠를 고치고, 코드는 둔 채
재심사 요청」이다. 게다가 애드센스는 **코드가 설치된 상태**를 확인하므로, 로더를 빼면 심사가
오히려 멈출 수 있다.

**② 이 저장소에는 소유권 확인 메타 태그가 아예 없었다**(전수 grep 0건). 즉 사이트 연결이
**로더 스니펫에만** 얹혀 있었고, 광고를 손대는 순간 연결까지 흔들리는 상태였다.

사장님 확인: 콘솔 상태는 **승인 후 정책 위반**, 광고 범위는 **결과 화면 배너만 유지**.
그래서 목표를 다시 잡았다 — **관문을 끄고 배너와 연결은 지킨다.**

---

## 1. 광고 판정을 둘로 갈랐다

한 값(`adsEnabled`)이 다섯 가지를 정하고 있었다: 로더 · `<ins>` · 오퍼월 · CSP · **ads.txt**.
그래서 광고를 끄려면 퍼블리셔 ID를 지워야 했고, 그러면 ads.txt가 404가 됐다.

    adsConfigured   퍼블리셔 ID가 있다      → ads.txt · 소유권 메타 · 배너 · CSP
    adsLive         NEXT_PUBLIC_AD_MODE     → 기본값이 심사 모드다
    adGatesEnabled  = adsLive               → 오퍼월 · GAM 보상형 · 대기 관문 · 문구 · 후보 봉인

**`adsEnabled`라는 이름은 지웠다.** 남겨 두면 새 호출부가 옛 뜻으로 쓴다 — 소비처 일곱 곳이
각각 둘 중 하나를 명시적으로 고르게 했다.

`<meta name="google-adsense-account">`를 **전 로케일**에 새로 넣었다(사장님 결정). 광고를
요청하지 않는 확인용 태그라 미지원 언어 화면에 있어도 정책 대상이 아니다.

## 2. 관문을 껐다 — 문구까지 같은 스위치로

「광고가 안 나가면 광고 관문도 없다」를 **불변식**으로 뒀다. 스위치를 둘로 두면 한쪽만 꺼진다.

| 자리 | 심사 모드에서 |
|---|---|
| 자체 게이트(`useSelfGateNeeded`) | false — 분석 대기 관문이 아예 안 돈다 |
| 제출 버튼 | "광고 확인 후 분석 시작" → **"분석 시작"**(23로케일 새 표) |
| 분석 대기 오버레이 | 셀프 광고 카드·카운트다운 제거, 진행 표시만 남음 |
| 추가 후보 패널 | **저절로 사라진다** — 봉인이 없으면 `remainingCount === 0` |
| 한글 발음 재분석 | 보상형·5초 관문·"광고 확인 후 다시 분석" 제거 |

**후보 전부 공개는 서버에서 한다.** `sealCandidates`가 심사 모드면 정렬만 하고 봉인하지
않는다. 화면 코드도, 23로케일 사전도 손대지 않았다 — 잠긴 것이 없으면 패널이 스스로 빠진다.

**서버 표(`unlock-ticket`)는 그대로 뒀다.** 그것은 광고 관문이 아니라 남용 방지다.

## 3. 「준비 중」을 걷어냈다 — 그리고 문서가 팔지 않는 가격을 찍고 있었다

살 수 없으면 **자리째 내지 않는다**(굿즈 카드 · 한자 프리미엄 결제 패널 · 글로벌 PDF 패널).
예전에는 다 그리고 단추만 "판매 준비 중"으로 잠갔다 — 결과 화면마다 죽은 상품이 한 칸씩 붙는
셈이라, 사이트가 미완성으로 보이는 가장 큰 자리였다. `/stamp-order`는 **주소를 살려 두고**
신청서 대신 사실 한 줄 + 문의 링크로 바꿨다(sitemap 등재 경로라 지우지 않는다).

그러다 **안내 문서 쪽에서 하나 나왔다.** `doc-values.ts`가 `getProductSetting`을 직접 읽어
**상품이 켜져 있는지만** 보고 있었다. 「지금 살 수 있는가」의 단일 판정은 이미 있었고
(`getPurchaseDisplay` — 상품 enabled **AND** 결제 수단), 문서 쪽만 그것을 안 쓰고 있었다.

결과: 화면의 구매 단추는 전부 "준비 중"인데 **안내 문서만 정가를 찍고 있었다.** 한 줄을 바꾸니
자리표시자가 안 채워지고 → `DocBody`가 그 절을 빼고 → **23개 언어에서 함께 사라졌다.** 번역 0건.

## 4. 홈·404·JSON-LD

- **홈 본문** — 히어로는 그대로 두고 아래에 안내 카드·숫자판·소개를 놓았다. **새 URL 0개**이고
  문구는 전부 `doc-content`·`docValues`에서 온다(이미 23로케일). 푸터는 히어로 안에서 문서
  끝으로 옮겼다.
- **`not-found.tsx` 신설** — 이 앱에 한 장도 없어 Next 기본 404가 나가고 있었다. canonical은
  넣지 않고 `noindex`만, 링크는 `localePath`로.
- **JSON-LD** — `Organization`·`WebSite` 둘만. 값은 **푸터가 그리는 것과 같은 자료**에서 오고,
  비한국어는 푸터와 같은 로마자 규칙을 쓴다. FAQPage·Article·BreadcrumbList는 넣지 않았다.
- **빈 `<h2>`** — 원인은 `doc-content`의 절 제목이 `""`인 것이었다. 자료를 고치면 23로케일 +
  번역기를 다시 돌려야 하므로 **그리는 쪽**(`GuideSection`)에서 한 줄로 고쳤다.

## 5. 도중에 잡은 것 — 번역기가 힌디어를 중국어로 냈다

요금 문단을 21개 언어로 옮기는데 **힌디어 자리에 중국어가 통째로** 들어왔다.

    hi: 汉字意义匹配、全球名称转换、韩国名称转换…

그런데 **약관 검사기 넷이 전부 초록불**이었다. 구조(절·문단 수)·금액·**한국어** 잔재·사업자
정보 보간만 보기 때문이다 — 중국어는 「잔재」가 아니다. 「빈 응답이 모든 검사를 통과했다」와
같은 자리다.

`scripts/verify-locale-script.mjs`를 세웠다. **문자 체계의 비율**로 본다 — 그 로케일의 것도
라틴도 아닌 문자가 문장의 30%를 넘으면 결함이다.

처음에는 「그 언어의 문자가 하나도 없는 긴 문장」도 함께 셌다가 **뺐다.** 두 가지 정상 상태가
빨간불이 됐기 때문이다: 번역기가 일부러 남기는 **영어 잎**(자리표시자를 못 맞춘 잎)과, 예시
주소처럼 어느 문자도 없는 값. **가짜 빨간불을 내는 검사는 없느니만 못하다.**

네 앱 115개 파일 · 문자열 25,235개를 훑어 ALL PASS. 대조군은 오늘의 실제 결함 문장이다.

## 6. 검사기 — 대조군이 모드를 알게 했다

`verify-ads-locale-policy`의 대조군이 **손으로 적은 `en·ja·ru`**였다. 적격 목록을 좁히는 날
(재거절 시 검수 로케일만 남기는 2차 조치) 이 검사기는 **고쳐진 코드를 결함이라 부른다.**

그래서 **배포가 스스로 말하게** 했다. 응답 헤더 둘을 `next.config.ts`가 `lib/ads.ts`의 값으로
만든다 — 화면을 그리는 값과 같은 곳이라 어긋날 수 없다.

    X-Ad-Mode      review | live
    X-Ad-Locales   ko,en,ja,…      광고를 실어도 되는 로케일(지원 ∩ 검수)

헤더가 없으면 「확인 못 함」으로 **실패**시킨다 — 옛 배포를 검사해 놓고 통과로 세지 않는다.

`verify-ad-mode.ts`는 **두 모드를 각각 자식 프로세스로** 돌려 양쪽 기대값을 함께 센다.
「관문을 껐는가」만 세면 승인 후 **켜지지 않는 회귀**를 못 잡는다.

## 8. 남은 일

### 사람이 하는 일 (`docs/POST_LAUNCH_CHECKLIST.md` A-0)

콘솔 Auto Ads OFF 확인 · sitemap 재제출 · 대표 URL 색인 요청 · 구글 선택 canonical 확인 ·
그 뒤 재심사 요청. **승인 뒤 `NEXT_PUBLIC_AD_MODE=live` + 재배포**로 관문·후보 잠금이 함께
돌아온다(체크리스트에 복원 항목으로 적어 두었다).

### 코드 쪽

- **첫 화면 분량**은 늘었지만(안내 카드·숫자판·소개) `landingCopies`는 여전히 손으로 관리하는
  23벌이다. 재심사에서 다시 걸린다면 여기일 가능성이 크다
- **형제 세 앱에 같은 분리가 없다.** `doc-values`가 `getProductSetting`을 보는 같은 결함이
  있는지도 확인할 것 — 「고침은 원본으로도 안 돌아온다」가 이 저장소에서 실제로 있었던 방향이다
- `HUMAN_REVIEWED_LOCALES`는 지금 지원 19개 전부다. 좁히려면 `docs/LOCALE_REVIEW_LOG.md`에
  근거를 먼저 적을 것
