# 기준 자료 갱신 주기 (2026-08-02 조사)

> 이 서비스의 답은 **바깥에서 정해 준 자료**에 기대고 있다. 그 자료가 갱신되면 우리 표만 옛날
> 값으로 남고, 그때부터 화면에 적힌 숫자가 사실과 달라진다. 언제쯤 바뀌는지 미리 적어 둔다.

## 1. 인명용 한자표 — 가장 중요하고 실제로 바뀐다

**출처**: 대법원 「가족관계의 등록 등에 관한 규칙」 별표. 전자가족관계등록시스템
(`efamily.scourt.go.kr`)이 조회 화면과 PDF를 제공한다. `scripts/sync-official-reference-data.mjs`가
이 두 곳에서 받아 온다.

**지금 우리가 쓰는 값**: 기준일 **2024-06-11**, 화면 표기 9,938자
(원본 추출 10,380행, `data/official/scourt-hanja.json`, 마지막 동기화 2026-07-15).

### 확인된 개정 이력

| 시행일 | 자수 | 비고 |
| --- | --- | --- |
| 2015-01-01 | 8,142 | |
| 2022 (월 미확인) | 8,319 | 소폭 추가 |
| 2024-06-11 | 9,389 (+1,070) | 대법원규칙 제3151호. 2014년 이후 최대 확대 |

### 언제쯤 다시 바뀌나

**정해진 주기는 공표되어 있지 않다.** 관측된 간격만 놓고 보면 이렇다.

- 소폭 추가는 **2~3년 간격**으로 있었다(2015 → 2022 → 2024).
- 대폭 확대는 드물다 — 2014년과 2024년, 약 10년 간격이다.

마지막이 2024-06-11이므로 **2026~2027년 사이에 한 번 있을 가능성이 높다.** 지금이 2026년
중반이니 **이미 그 구간에 들어와 있다.** 확인을 미룰 이유가 없다.

### ⚠ 확인이 필요한 어긋남

공식 발표는 2024-06-11 기준 **9,389자**인데 우리 화면은 **9,938자**로 적고 있다. 세는 기준이
다를 가능성이 크다(허용자체·이체자를 포함하는지). **어느 쪽이 맞는지 확인해 두어야 한다** —
숫자를 안내 문서에 적어 두고 파는 서비스라 틀리면 그대로 표시 오류가 된다.

### 갱신 절차 (이미 있는 것)

```
npm run official:sync       대법원에서 다시 받아 온다
npm run official:validate   받은 자료의 형식·개수를 검사한다
npm run official:publish    검수본으로 올린다(화면이 이것을 본다)
```

**분기에 한 번 돌려 개수와 기준일이 달라졌는지 보는 것으로 충분하다.** 달라졌다면 그때
공지사항(`lib/notices.ts`)에 한 항목을 올린다 — 이용자가 쓸 수 있는 글자가 늘어난 것은
알릴 값어치가 있다.

## 2. 로마자 표기 자료

**출처**: 같은 대법원 시스템(`CsNtcMttrMgtRomanAjax.do`). 여권 로마자 표기 관례를 정리한 표다.
2,321행을 받아 두었다. 한자표와 **같은 스크립트로 함께 갱신**되므로 위 절차를 돌리면 같이 온다.

국립국어원 로마자 표기법 자체는 2000년 고시 이후 크게 바뀌지 않았다. 자주 볼 자료는 아니다.

## 3. 만세력 (사주 계산)

**출처**: npm `@fullstackfamily/manseryeok`, **1.0.8로 고정**(`packages/core/package.json`).

버전을 고정해 두었으므로 **우리가 올리지 않는 한 바뀌지 않는다.** 올릴 때는 반드시 회귀
검사를 먼저 돌린다 — 날짜 하나가 달라지면 이미 나간 결과의 숫자가 달라진다.

```
apps/inyeonlink → npx tsx scripts/verify-match.ts   (베이스라인과 대조)
```

1956-12-31 같은 표의 구멍은 `packages/core/src/saju/calendar.ts`가 메우고 있으므로, 라이브러리를
올릴 때 그 보정이 여전히 필요한지도 함께 본다.

## 4. 명리 규칙 (십신·지지 관계·용신)

**바깥 자료가 아니다.** 우리가 전통 해석을 규칙으로 옮긴 것이고 `apps/inyeonlink/src/lib/engines/`에
있다. 바뀔 때는 우리가 바꾸는 것이므로 주기가 없다. 대신 바꾸면 **엔진 버전을 올리고**
회귀 하니스로 기존 결과가 움직였는지 확인한다(지금 v10).

점수가 달라지는 변경이면 공지사항에 올린다. 이미 결과 링크를 가진 사람의 숫자가 달라지기
때문이다.

## 5. 서체

**출처**: Noto 계열(OFL). `apps/*/assets/fonts/LICENSES.md`에 파일별로 적어 두었다.

원본이 갱신돼도 우리 서브셋은 그대로다. 다시 뜨는 것은 **글자가 빠졌을 때뿐**이고, 그건
`verify-pdf-glyphs.ts`가 알려 준다. 주기적으로 볼 자료는 아니다.
