## 3. 결과 진입 관문을 naminglink 방식으로 옮겼다 (미커밋 — 이 항목 작성 시점)

**왜.** 드림링크의 광고 관문(`AdWatchOverlay`)은 **입력 화면**(`DreamForm`)에 있었고 GAM 보상형 단위가 있을 때만 켜졌다.
입력 화면에서는 오퍼월 유무를 잴 수 없어 오퍼월이 도는 방문에서 광고가 둘이 된다 — naminglink 가 2026-08-19 에 버린 방식이다.

**한 일.**
- `src/components/ResultEntryGate.tsx` 신설 — 오퍼월 → GAM 보상형 → 셀프 광고 3초. 새 문구 없이 기존 `analyzing.watching`·`remaining` 만 쓴다.
- `src/lib/offerwall.ts` — naminglink 와 같은 파일을 복사(오퍼월 판정은 관측 기반 · `NEXT_PUBLIC_OFFERWALL_ENABLED` 가 `true` 일 때만 기다린다).
- `DreamResultView.tsx` — `outcome.matched.length` 가 있을 때만 관문을 세운다(상징 0건 화면은 발행한 콘텐츠가 없다).
- `DreamForm.tsx` — 입력 화면 관문 제거. `AdWatchOverlay.tsx`·`submitAdGateEnabled` 삭제, 남은 주석을 `ResultEntryGate` 로 갱신.
- 검사기: `verify-result-entry-gate.mjs`(드림링크 구조에 맞게 새로 씀 — 결과 화면에 있고 입력 화면에 없고 옛 부품이 안 살아났는가),
  `verify-offerwall-detection.ts`(naminglink 것 복사 — `offerwall.ts` 의 순수 판정 8가지).

**달라지는 동작(배포하면).** 관문을 세우는 조건이 「GAM 보상형 단위가 있는가」에서 「`NEXT_PUBLIC_AD_MODE=live` 인가」로 바뀐다.
운영이 live 이면 **지금까지 관문이 없던 드림링크에 셀프 광고 3초 관문이 처음 생긴다**(GAM 단위가 없어서 지금까지는 꺼져 있었다).
광고 노출 집계(`trackAdEvent`)는 옮기지 않았다 — 드림링크 집계 이벤트에 그 종류가 없다.
