## 2. 결함 여섯 — 전부 실제로 돌려 봐야만 나왔다

### ① 광고 라벨이 정책 형식에 안 맞았다 (`fce8db8`)

`AdBanner`가 `label`을 **화면낭독기용과 화면용에 동시에** 썼다. 그래서 결과 화면에
「한자 추천 결과 상단 배너 광고」가 그대로 찍혔다. 애드센스는 라벨을 붙일 경우 **「광고」나
「스폰서 링크」만** 허용하고, 저 문구는 **광고가 「한자 추천 결과」인 것처럼 읽힌다.**

서술형은 `aria-label`에만 남기고 화면에는 「광고」 한 단어. `Record<LocaleCode, string>`이라
23개를 다 채워야 tsc가 통과한다.

### ② `enableServices()` 누락 — 보상형이 요청조차 안 했다 (`ceeeeaa`)

슬롯을 정의하고 `addService`·`display`까지 불러도 **서비스를 켜지 않으면 광고를 요청하지
않는다.** 보상형이 늘 4초 뒤 `unavailable`로 떨어져 셀프 광고만 돌던 원인이 이것이다.

공식 흐름으로 맞췄다 — 정의 → addService → 이벤트 등록 → `enableServices()` → `display()`.
`display()` 뒤의 `refresh()`는 뺐다(요청이 두 번 나간다).

함께: 모든 종료 경로가 같은 `cleanup()`을 지나게 · 이벤트마다 `event.slot === slot` 확인 ·
`makeRewardedVisible` 실패 처리 · **광고가 보이면 준비 대기 시계를 끄고 닫힘용 안전망(5분)으로
갈아 끼우기**(안 그러면 이용자가 보는 중에 타임아웃이 슬롯을 부순다).

### ③ 표를 못 끊으면 관문이 **닫혔다** (`90fcbb1`)

발급과 검증이 같은 태도를 주석에 적어 두고 코드는 반대로 갔다.

    issueUnlockTicket    RPC 오류 → ticket: null   "관문이 통째로 열린 채로 돈다"
    consumeUnlockTicket  ticket 없음 → "missing" → 403   "관문을 걸 수 없을 때는 통과시킨다"

Supabase가 **아예 없으면** 양쪽이 통과시킨다. 어긋나는 것은 **DB가 있는데 RPC가 실패할 때**다.
광고를 끝까지 본 이용자가 「후보를 열지 못했습니다」를 받는다.

고침: 표가 없을 때 **짐작하지 않고 RPC에 물어본다.** 아무 표로 한 번 불러 오류면 통과(+운영
알림), 「그런 표 없음」이면 진짜 우회로 보고 막는다.

### ④⑤ CSP가 보상형을 두 겹으로 막고 있었다 (`4fb16d4`, `ae658c0`)

②를 고치자 광고가 처음으로 실제 요청까지 갔고, **그제서야 다음 자리들이 막혀 있는 것**이
드러났다.

    script  www.gstatic.com/.../rewarded_web_video_ko.js  → GoogleRewardedWebVideo is not defined
    frame   cm.g.doubleclick.net · <해시>.safeframe.googlesyndication.com
    style   fonts.googleapis.com
    media   **media-src 지시문 자체가 없어** default-src 'self'로 폴백 → 광고 동영상 차단

`media-src`가 없던 것은 애드센스 동영상 소재에도 해당한다. 이미지에 대해서는 이미
「어느 도메인에서 올지 알 수 없다」고 `https:`로 열어 두었는데 **동영상만 빠져 있었다.**

### ⑥ 구글 메시징이 통신을 못 했다 (`e18f821`)

`fundingchoicesmessages.google.com`이 **script-src에는 있는데 connect-src에 없었다.**
`ad_blocking_detection_executable`·`web_iab_tcf_v2_signal_executable`·`cookie_refresh_executable`이
줄줄이 차단됐다. **광고 차단 회복을 켠 직후에 드러났다.**

## 3. 막다른 길 둘 — 확정했다

### 오퍼월은 진입 화면에 뜰 수 없다

7월 설계는 「진입=오퍼월, 후보 열기=GAM 보상형」이었다. 그런데 **오퍼월은 애드센스 태그가
페이지에 미리 있어야 하고, 입력 화면에는 그 태그가 일부러 없다** — 8월 10일 반려 이후
「광고는 발행한 화면에만」으로 걷어냈다. **8월 11일의 결정이 7월 설계의 전제를 무너뜨렸는데
둘을 다시 이어 본 사람이 없었다.**

    입력 /hanja-meaning   adsbygoogle 없음 · window.googlefc undefined
    결과 /result          있음 · googlefc object

그래서 진입 관문도 **GAM 보상형**으로 바꿨다(`e18f821`). 보상형은 `showRewardedAd()`가
**버튼을 누른 뒤에** `gpt.js`를 스스로 붙이므로 입력 화면이 광고 코드 없이 남는다.

오퍼월은 게시했다가 **일시중지**했다 — 뜰 수 있는 유일한 화면이 결과 화면인데, 거기서 뜨면
이미 광고를 본 이용자를 또 세운다. 그리고 **한 번 통과하면 24시간 전체 접근**이라 후보 열기
관문으로는 쓸 수 없다(이 저장소가 이미 겪은 결함이다).

### 이 GAM 계정에는 보상형에 채울 수요가 없다

    광고주문 0 · 광고 항목 0
    메뉴에 「판매」·「프로그래매틱」·Ad Exchange 없음
    연결된 계정 = Google 애널리틱스뿐
    네트워크 설정의 AdSense 백필은 켜져 있음

**무료 Google Ad Manager**다. Ad Exchange(공개 입찰)가 없다. 그리고 구글 문서상 **보상형이
지원하는 수요 목록(예약·우선거래·공개입찰·비공개입찰·프로그래매틱 개런티)에 AdSense 백필이
없다.**

운영 도메인에서 본인 광고 단위로 직접 호출해 확인했다.

    slot defined → slotRequested → slotResponseReceived → slotRenderEnded isEmpty: TRUE

**코드는 정상이다.** 구글 공개 샘플 단위(`/22639388115/rewarded_web_example`)로는 전 흐름이
완벽하게 돌았다 — 광고 표시 → 10초 카운트 → `granted` → `closed` → 후보 정확히 1개 해제.
중간에 닫으면 `dismissed`로 후보가 열리지 않는 것까지 확인했다.

**즉 지금 광고 수익은 결과 화면 배너뿐이다.** 관문 둘은 셀프 광고로 돌고 수익은 0이다.

## 4. 결과 화면 배너 (`934fc8c`)

「한자 종합 상세 잠금」과 「한자 이름 상세 상품」 사이에 본문 배너를 하나 더 뒀다.
**후보 열기 버튼 바로 밑은 일부러 피했다** — 표시 광고가 「광고를 봐야 열린다」는 그 광고로
오인되면 정책 위반이다.

모바일 배너 높이 50 → 100. 폭은 원래 컨테이너를 채우고 있었고(요청 파라미터 `w=401`),
작아 보인 것은 높이 때문이었다. `full-width-responsive`는 **켜지 않았다** — 예전에 화면이
가로로 넘친 사고가 있고, 넘침 방지 장치가 생긴 지금 다시 시도할 값은 있지만 실측 전에는 켜지
않는다.

한자 화면에만 넣었다. 나머지 셋은 구조가 달라(한국이름은 유료 패널이 둘, 글로벌 변환은 없다)
이 자리가 검증된 뒤에 옮긴다.
