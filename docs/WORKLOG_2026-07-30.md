## 1. 실 도메인 연결

```
naming-link.com          Vercel naminglink 프로젝트에 apex + www 등록
가비아 DNS               A @ 76.76.21.21 · A www 76.76.21.21
결과                     apex·www 모두 HTTPS 200, 인증서 발급 완료
```

`NEXT_PUBLIC_SITE_URL`은 이미 설정돼 있어 canonical이 실 도메인으로 나가고 있었는데, **정작
도메인이 가비아 파킹 페이지를 서빙하는 상태**였다. 코드가 정본이라 말하는 주소가 빈 페이지인
셈이라 서둘러 연결했다.

### 딸린 수정

- **크론이 옛 주소를 치고 있었다** (`3679ffb`). `naminglink.vercel.app`을 하드코딩했는데, 이 크론이
  하는 일이 결제 미완료 배송정보 파기와 만료 리포트 삭제다. 도메인을 정리하는 순간 **아무 오류
  없이 죽고 개인정보가 계속 남는다.** 저장소 변수 `CRON_TARGET_URL`로 빼고 기본값을 실 도메인으로.

## 2. 애드센스 라이브

### 등록한 값

```
NEXT_PUBLIC_ADSENSE_CLIENT            ca-pub-5084236528895241
NEXT_PUBLIC_ADSENSE_SLOT_* (9개)      화면별 개별 슬롯
```

자리를 합치지 않고 화면마다 나눈 것은 어느 화면이 실제로 버는지 콘솔에서 갈라 보기 위해서다
(사용자 결정).

### 가장 큰 발견 — 슬롯이 하나도 이어져 있지 않았다 (`071458b`)

`lib/ads.ts`의 키는 camelCase(`serviceHeader`)인데 화면이 넘기는 값은 snake_case
(`service_header`)였다. `adSlots["service_header"]`는 undefined라 **아홉 자리가 전부 자리
표시로 떨어졌다.** 퍼블리셔 ID를 넣어도 광고가 한 칸도 안 나올 상태였다.

`slotKey?: string` + `as AdPlacement` 캐스팅이 타입 검사를 통과시켜 배포까지 갔다. `AdBanner`의
주석이 바로 이 경우를 경고하고 있었는데도 못 잡았다.

    slotKey?: string  →  slotKey: AdPlacement   (필수 + 키 타입)

이제 `lib/ads.ts`에 없는 이름을 쓰면 컴파일이 깨진다. 슬롯을 아예 안 넘기던 세 자리(분석
대기·후보 열기·발음 대안 열기)도 이 변경으로 드러나 채웠다.

### 소유권 확인·ads.txt

로더는 JSX상 `<body>` 끝에 있지만 React가 `<head>`로 끌어올려, 서버 HTML은 구글이 준 스니펫과
글자까지 같다(실측). `ads.txt`는 정적 파일이 아니라 라우트(`src/app/ads.txt/route.ts`)가 만든다 —
퍼블리셔 ID가 없으면 404를 내기 위해서다.

## 3. 광고가 화면을 망가뜨리던 것 — 브라우저 실측으로 원인 확정

증상은 둘이었다. **모바일에서 오른쪽이 잘림**, **머리글 배너가 463px로 커짐.**

코드만 읽어서는 못 잡았다. 브라우저에서 `<ins>`를 직접 재고 나서야 원인이 나왔다.

```
margin-left: -20px;  width: 456px;  height: auto !important;
```

**둘 다 `data-full-width-responsive="true"` 탓이었다.** 광고를 컨테이너 패딩 밖까지 늘리려는
장치인데, 음수 마진과 고정 폭이 조상 grid 트랙을 벌려 456px 뷰포트에서 문서 폭이 477px이 됐다.
소재가 안 채워지면 `height: auto !important`를 써서 우리 클래스 important까지 이겼다.

### 이 과정에서 내가 틀린 것들 (기록해 둔다)

1. **`min-w-0`을 nav에만 넣음** — 머리글 자체가 grid 항목인 것을 놓쳤다
2. **Tailwind v4 문법 가설** — 앞자리 `!h-[50px]`이 v4에서 안 만들어진다고 판단했으나, 배포된
   CSS를 열어보니 `.\!h-\[50px\]{height:50px!important}`가 정상 생성돼 있었다
3. **`overflow-x-hidden`을 방어용으로 넣음** — 넘침을 자르면서 가로 스크롤까지 막아 모바일에서
   오른쪽 내용에 **아예 닿을 수 없게** 만들었다. 증상만 바꾸고 더 나쁘게 했다
4. **`full-width-responsive`를 껐다가 되돌림** — 되돌린 쪽이 원인이었다

**HTML 문자열만 보고 판단한 것이 공통 원인이다.** 배포된 CSS와 브라우저의 실제 요소를 열어보고
나서야 잡혔다.

### 최종 형태

```
높이      <ins>를 고정 높이 상자로 감쌈 (모바일 50px · PC 90px, 동의 영역 250px)
폭        data-full-width-responsive="false" + !max-w-full
모양      header/leaderboard=horizontal, consent=rectangle, sidebar=vertical
```

인라인 `!important`는 클래스 `!important`를 이기므로 높이는 CSS로 못 막는다. 바깥 상자가 잡는다.

## 4. 광고 구조 확정 (사용자 결정)

자리마다 광고 종류가 다르다. **폴백은 전부 셀프 광고로 통일한다.**

```
정보 입력 → "광고 확인 후 분석 시작"
          → 오퍼월          (페이지가 바뀌므로 오퍼월이 맡을 수 있다)
          → 없으면 셀프 광고
          → 결과 페이지, 후보 1개만 공개

잠긴 후보 열기 (같은 페이지)
          → GAM 보상형      (오퍼월은 같은 페이지에서 다시 못 뜬다)
          → 없으면 셀프 광고
          → 후보 1개씩
```

### 고친 결함 — 오퍼월 한 번으로 전부 열리던 것 (`4baaf29`)

`useSelfGateNeeded()`(오퍼월 판정)를 후보 열기와 다시 분석에서도 보고 있었다. 오퍼월이 도는
방문이면 대기가 0초가 되어 **한 번 통과한 이용자가 나머지 후보를 전부 공짜로 열었다.**
"1광고 1결과"가 성립하지 않는다. 그 연결을 끊었다.

후보 열기는 `CandidateUnlockPanel` 하나를 네 서비스가 공유하므로 한 곳 수정이 전부에 적용된다
(한자 매칭·글로벌 변환·한국 이름 만들기·발음 표기). 발음 표기의 "다시 분석"만 별도 컴포넌트라
따로 고쳤다.

### 셀프 광고 (`6c0252b`·`f7527c1`)

```
인연링크      inyeon-link.com   사주와 띠로 보는 두 사람의 궁합
플레이스링크   place-link.com    한국의 데이트 코스 공유 · 추천 서비스
```

문구는 지어내지 않았다. 인연링크는 자기 사전의 tagline을 그대로 옮겼다. **아직 링크로 걸지
않는다** — 두 주소 모두 실 도메인이 연결되지 않아 누르면 안 열린다. 배경 이미지는 나중에 받는다.

판정은 애드센스가 붙이는 `data-ad-status`로 한다(MutationObserver). 게이트를 없애거나 기다림을
건너뛰지 않는다 — **채울 것만 바꾼다.**

### GAM 보상형 다크 런치 (`44d87c8`)

`NEXT_PUBLIC_GAM_REWARDED_UNIT`이 없으면 gpt.js도 CSP 완화도 안 붙는다.

- `unavailable`을 **오류가 아니라 정상 경로로** 다룬다. 초기 트래픽에서는 no-fill이 잦고,
  광고차단기·네트워크 실패도 이용자에게는 같다. 준비 신호가 4초 안에 없으면 없는 것으로 본다
- `dismissed`(보상 전 닫음)는 후보를 열지 않고 폴백으로도 안 넘긴다
- `frame-src` 조건에 `gamRewardedEnabled`를 함께 넣었다 — 보상형은 iframe이라, GAM만 켜고
  애드센스를 끈 상태에서 `frame-src 'none'`이면 통째로 막힌다

## 5. 글로벌 이름 변환 속도 — 36초 → 15초 안쪽

### 실측이 근거였다

```
GLOBAL_TO_KOREAN      출력   741토큰   13.2초
KOREAN_TO_GLOBAL      출력 1,562토큰   36.0초  (최악 53.8초)
PREMIUM_HANJA_REPORT  출력 6,372토큰   12.3초  ← 출력 4배인데 시간 1/3
```

프리미엄은 후보별 호출을 `Promise.all`로 돌린다. 글로벌 변환만 단일 호출로 순차 생성했다.

### 두 번에 걸쳐 만들었다

**1차(`a53dd79`) — 전략별 5개 독립 호출.** 8초까지 줄었지만 **후보 수가 매번 달라졌다**(2개·3개).
호출들이 서로를 몰라 집합이 흔들리고, 동시 6요청이 분당 한도에 걸려 거절되면 그 후보가 통째로
사라졌다.

**2차(`39f4b61`) — 선정과 서술을 나눴다.**

```
1단계 (단일 호출)  후보 5개 + 총평 + 배제 후보. 이름·전략·짧은 근거만
2단계 (5개 병렬)   후보별 긴 서술 7개 필드만
```

후보 집합·전략 배분·총평이 한 모델 안에서 정해지므로 어긋날 수 없고 **개수가 고정된다.**
서술 호출이 실패해도 후보는 사라지지 않는다(짧은 정보로 남는다).

**교훈**: 빠르지만 매번 다른 결과보다, 조금 느려도 일관된 결과가 낫다(사용자 판단).

`temperature`는 0.6 그대로다. 같은 입력에도 후보·순서가 매번 달라지는데, 이는 병렬화와 무관한
원래 성질이다. 낮추면 일관되지만 후보가 뻔해진다 — 지금은 그대로 두기로 했다.


## 7. 보안 재감사

### 정상 확인

- 관리자 API 9곳 전부 `requireAdmin`
- 프리미엄 리포트 토큰은 `timingSafeEqual`
- 포트원 웹훅 서명 검증, 토스는 **주문에 저장된 금액**으로 승인(클라이언트 금액 미사용)
- CSP `object-src 'none'`·`frame-ancestors 'none'`·`base-uri 'self'`·`form-action 'self'`,
  HSTS preload, X-Frame-Options DENY
- 결과 저장 동의 **기본 꺼짐**, 입력 검증은 클라이언트·서버 양쪽

### 조치한 것

| 등급 | 항목 | 커밋 |
| --- | --- | --- |
| HIGH | Supabase 인증 메일이 일반 이용자에게 안 감 | 대시보드 설정 |
| MEDIUM | 크론이 옛 도메인 호출 → PII 파기 중단 위험 | `3679ffb` |
| MEDIUM | `hanja/surname` 무제한 공개 조회(요청당 DB 2회) | `0ba2751` |
| LOW | 로그인 진입점 부재 | `99e64fa`·`7444320` |

**HIGH가 가장 컸다.** Supabase 기본 메일은 2024-09-26부터 **조직 구성원에게만** 발송된다.
본인 계정으로 테스트하면 오니까 정상으로 보였을 뿐, **일반 이용자는 아무도 로그인할 수 없는
상태**였다. Resend 커스텀 SMTP를 붙여 해결했다.

### 조치 안 한 것

- **의존성 4건**(`postcss` 3·`sharp` 1) — Next.js 내장 전이 의존성이라 직접 못 올린다.
  빌드타임 도구라 런타임 노출은 제한적. Next 릴리스 대기
- **CSP `script-src 'unsafe-inline'`** — Next 구조상 필요. nonce 전환은 별건

## 8. 그 밖에 고친 것

- **랜딩 글자 깨짐** (`72553fd`) — 커밋 `ba89993`이 UTF-8을 CP949로 흘려 써서 `漢`·`名`·`意`가
  `?`로 소실되고 "네이밍 - 링크"가 모지바케가 됐다. 원인은 편집 경로다 — 이 환경의
  PowerShell 5.1은 `Set-Content`가 시스템 ANSI 코드페이지를 기본으로 쓴다. **소스 파일을 셸로
  써 넣으면 안 된다.**
- **도장 신청 404** (`bcf1e14`) — `localePath("/stamp-order", locale)` 뒤에 `&name=`을 이어 붙여
  `/ko/stamp-order&name=홍길동`이 만들어졌다. 경로 기반 URL 전환(`d0ad948`) 때 이 자리가 같이
  안 고쳐졌다. 같은 실수가 다른 곳에는 없는 것을 확인했다
- **죽은 구매 버튼** (`bcf1e14`) — 도장 3종이 판매 중지인데 신청 버튼은 살아 있었다.
  `/api/product-info`가 빈 응답이면 "판매 준비 중"으로 잠근다
- **성·이름 입력 검증** (`7d6bb7c`) — 제출 시 되돌리지 말고 **입력 단계에서** 한글 아닌 글자를
  막는다. 조합 중인 자모(ㄱ·ㅏ)는 허용해야 IME가 동작한다
- **발음 버튼 로케일 뒤바뀜** (`39f4b61` 이전 확인) — 커밋 `62e2cf1`이 `submitTransliteration`을
  23개 로케일로 채우면서 응답을 엉뚱한 블록에 써 넣어 **17개 언어가 다른 언어로 표시**됐다.
  사용자 지시로 되돌리고 손대지 않음
- 결과 화면 머리글 설명 문구 4개 삭제, 계정 화면 예고 문구 2개 삭제(사전에서도 제거)
- 상품 설정에 인연링크/네이밍링크 배지, 운영자 콘솔 "테스트 주문 포함"을 조회 기간 왼쪽으로
- 운영 지표 3종 초기화 — `ai_usage_logs` 195 / `site_events` 1,289 / `ad_events` 546 → 0

## 10. 남은 것

### 구글 대기

- 애드센스 사이트 검토 승인
- `ads.txt` 상태 갱신(최대 24시간, 우리 쪽은 구글봇 요청까지 정상 확인)

### 사용자 몫

- **오퍼월 게시** — 승인 후. 게시하면 `NEXT_PUBLIC_OFFERWALL_ENABLED=true` 넣고 재배포
- **GAM 계정** — `admanager.google.com` 가입 → 애드센스 연결 → 보상형 광고 단위 생성 →
  `/네트워크코드/단위이름` 경로를 `NEXT_PUBLIC_GAM_REWARDED_UNIT`에
- **통신판매업 신고번호**
- **토스페이먼츠 계약·키** — 없어서 `product_settings` 20건 전부 판매 중지 상태
- 셀프 광고 배경 이미지, `inyeon-link.com`·`place-link.com` 도메인 연결

### 미결 판단

- **`GLOBAL_TO_KOREAN` 병렬화** — 13초라 급하지 않다. 글로벌 변환의 2단계 구조가 검증되면 적용
- **오퍼월 보상 단위** — 24시간 접근이면 "1광고 1결과"와 어긋난다. 게시 후 실제 동작을 보고 판단
