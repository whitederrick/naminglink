## 0. 들어온 것 — 외부 검토 둘의 합의

ChatGPT·클로드앱 검토 결과가 결론으로 들어왔다. 요지는 **코드상 재심사 블로커는 없다**이고,
방침 하나가 새로 정해졌다.

**심사 모드에서도 ko 실결과 화면의 광고는 유지한다.** 발행한 콘텐츠가 충분할 때만 붙는
설계이므로 8월 10일 반려 사유(가치 없는 콘텐츠에 광고)와 다른 자리다.

그래서 **광고 CSP는 `adsConfigured`로 열어 둔다.** `adsLive`로 닫으면 위 결정과 정면으로
충돌한다 — 심사 중 유지하기로 한 그 광고를 CSP가 막아 죽인다. 그리고 **화면으로는 티가 안
난다**(no-fill과 CSP 차단이 똑같이 빈 자리로 보인다). 폐기된
`docs/issues/ADSENSE_NEXT_SESSION.md`가 「review 모드 광고 CSP도 닫기」라고 적어 두었으므로,
그 문서를 근거로 되돌리지 말 것.

## 2. 검사기가 「끈 것」과 「죽은 것」을 구분하지 못하고 있었다

`verify-no-ad-requests`의 `PATHS`가 전부 **붙으면 안 되는 화면**뿐이었다. 로더를 `AdBanner`가
그릴 때만 부르도록 좁힌 뒤로 **제대로 껐다**와 **배선이 통째로 죽었다**가 같은 모양이 됐다.
승인 뒤 `live`로 바꿔도 광고가 안 나가는 회귀는 화면으로 티가 안 난다.

**양성 단계를 세웠다.** 검수 로케일의 진짜 결과를 하나 만들고 광고 요청이 나가는지 센다.

- 폼은 로케일 문구에 기대지 않고 `#naming-input-form` 안의 **차례로만** 잡는다
- React가 값을 쥐고 있어 `value` 직접 대입은 안 먹는다 — 네이티브 setter + `input` 이벤트
- 동의란은 `.click()`이라야 `onChange`가 돈다(좌표 클릭은 재렌더로 어긋난다)

로케일 표본도 5개 → 8개(ko·en·ja·**ru** / kk·km·**mn**·**uz**). 여덟 전부 200인 것을 먼저
확인했다 — 빈 주소를 세면 「0건」이 거짓으로 통과한다.

### 운영 실측

    양성  /hanja-meaning 결과           pagead2 · doubleclick · adtrafficquality 확인
    ALL PASS · exit 0

슬롯 자리는 비어 있다 — **승인 전이라 no-fill이 정상**이고, 요청이 나갔다는 것과 채워졌다는
것은 다른 말이다.

## 4. 그 뒤에 나온 것 — 검사기가 `ALL PASS`를 찍고 안 끝난다

`verify-declared-urls`를 운영으로 돌렸더니 `ALL PASS` 뒤 **7분을 매달렸다.** 종료 코드가
안 나왔다.

원인은 **성공 경로에만 `process.exit`이 없는 것**. 실패는 전부 `process.exit(1)`인데 성공은
파일 끝으로 떨어져, `fetch`의 keep-alive 소켓이 이벤트 루프를 놓지 않는다.

**localhost에서는 안 걸린다** — dev 서버가 연결을 닫아 줘서 우연히 빠져나온다. 그런데 이
검사기들은 전부 운영을 겨눈다. sitemap 재제출·재심사 직전에 돌려야 하는 것들이다.

위험은 둘이다. 전수 스윕이 거기서 멈춘다. 그리고 사람이 **`ALL PASS`만 보고 통과로 센다** —
종료 코드는 영영 안 온다.

여섯 파일의 `ALL PASS` 다음 줄에 `process.exit(0)`을 넣었다. 실패 쪽과 대칭이 된다.

    verify-declared-urls    verify-internal-links    verify-ads-locale-policy
    verify-reachable-links  verify-rendered-locale   verify-robots-open

`verify-structured-data`는 이미 `process.exit(failures === 0 ? 0 : 1)`이라 대상이 아니다 —
grep이 삼항 연산자를 못 봐서 낸 가짜 빨간불이었다.

## 5. 이 날 내가 낸 실수 — 같은 자리를 두 번 밟았다

**검사기를 부르는 법을 안 읽고 `--base`를 일괄로 붙였다.** 셋이 틀렸다.

| 검사기 | 실제 인자 | 내가 준 것 | 결과 |
|---|---|---|---|
| `verify-reachable-links` | `<앱이름> <baseUrl>` | `--base URL` | 사용법 출력 후 exit 1 |
| `verify-rendered-locale` | `[호스트접두어]` — **localhost용** | `--base URL` | 「연 화면 0개」로 거부 |
| `verify-rendered-locale` | 〃 (`${prefix}:${port}`) | `https://naming-link.com` | `…com:3001`을 두드리며 **15분 매달림 → exit 124** |

세 번째가 특히 나빴다. 열리지 않은 포트를 두드리는 것을 **「원래 무거운 검사로 보인다」고
넘겨짚고 두 번 보고**했다. 파일의 `prefix` 한 줄을 봤으면 1분이면 알았다. 올바르게 부르니
**83초**였다.

그리고 이 저장소에는 **정답이 이미 있었다.** `node scripts/audit-verifiers.mjs`는 정확히 이
문제 때문에 만들어졌고, 그 파일 머리에 **`verify-reachable-links`가 가짜 빨간불 예시로 이름까지
적혀** 있다. 결론도 「부르는 법을 코드가 알아야 한다」다. 알고도 손으로 루프를 짰다.

**다음부터: 검사기를 부르기 전에 `node scripts/audit-verifiers.mjs --list`.**

## 7. 남은 일

### 코드 (커밋 안 됨 — 작업 트리에 있다)

- 검사기 여섯의 `process.exit(0)`. **`declared-urls`·`internal-links` 두 개의 러너 확인이
  남았다.** 통과하면 커밋한다
- `verify-no-ad-requests`는 **화면이 실제로 떴는지(200) 안 본다.** 경로가 틀리면 「광고 요청
  0건」으로 조용히 통과한다. 지금은 여덟 로케일이 다 200이라 거짓 통과가 아니다
- 부분 판매 가격 필터 — 지금은 전 상품 OFF라 문제없다. **상품을 하나라도 켜기 전에**
  여러 금액이 든 문단에서 미판매 금액만 걸러지는지 보완할 것

### 사람이 하는 일 — 다음 차례

콘솔 Auto Ads 확인 · **sitemap 재제출** · 대표 URL 색인 요청 · 구글 선택 canonical 확인 ·
그 뒤 **재심사 요청**. 승인 뒤 `NEXT_PUBLIC_AD_MODE=live` + 재배포로 관문·후보 잠금이 함께
돌아온다.
