# 띠별 12편(B)을 만든 도구 — 사주링크 C 에서 같은 방식으로 쓰려고 보관한다

작성 2026-10-12. **저장소 스크립트가 아니다**(스윕·검사기 목록에 들어가지 않는다). 경로는 그날 세션의
스크래치패드를 가정하고 있으므로 쓸 때 `SP`·`OUT` 경로를 바꾼다.

| 파일 | 역할 |
| --- | --- |
| `gen-zodiac-12-ko.mts` | 엔진 함수(`branchRelation`·`BRANCH_RELATION_SCORE`)로 한국어 원문 12편을 만든다. 사실 단언 포함(최고 점수=육합 · 최저=충 · 원진은 충 자리의 옆 …) + 한자 뒤 조사(과/와·은/는·이/가) 사후 검사 |
| `gen-zodiac-12-en.mts` | 같은 사실로 영어 원문. **한국어와 구조(절·블록·표 크기)·자리표시자 집합이 같은지 단언** |
| `prep-translate.mjs` | 영어 잎을 **고유 문자열**로 중복 제거(292개), 언어별 띠 성향 문구를 뽑는다 |
| `validate-unique.mjs` | 고유 문자열 번역 검사: 자리표시자·강조·링크·숫자·한글·한자 표본·**성향 문구가 글자 그대로인지** |
| `apply-translations.mjs` | 번역을 경로 단위로 펼쳐 기존 검사기와 표의 띠 이름을 확인하고 문서 구조에 얹어 삽입 |
| `insert-docs.mjs` | `"guide/ten-gods"` 앞에 문서 12편 삽입(앵커가 1번이 아니거나 이미 있으면 던진다) |
| `validate-translation.mjs` | 경로 단위 검사(`translate-doc-content.ts` 의 `mismatch` 와 같은 규칙) |
| `check-values.mts` | 문서가 쓰는 자리표시자가 `docValues` 에 전부 있고 값이 손계산과 같은지(`NODE_OPTIONS=--conditions=react-server` 필요) |
| `check-yukhap-subject.mjs` | 육합 문장의 「가장 높은 점수」 주어가 그 문서의 띠인지 대조 |

## 절차 (실제로 한 순서)
1. 생성기로 한국어 → 영어 원문(구조 단언). 2. 코드 등록(`guide-index` · 슬러그 `page.tsx` · `doc-values` ·
`ko.ts`/`en.ts` 삽입). 3. `prep-translate` → 에이전트 7개 × 3개 언어 번역(`validate-unique` 로 스스로 검증).
4. 반영 검사 → 삽입. 5. **독립 검토 에이전트 7개**(템플릿으로 조립한 번역이라 문법 결함이 실제로 나왔다:
it 28 · fil 24 · mn 24 · ja 36 · pl 32 · km 24 …). 6. 수정본으로 되돌려 다시 삽입 → 검증 스위트.

## 배운 것
- 템플릿 번역은 **검사기를 다 통과해도 문법·의미 결함이 남는다**(조사 · 관사 · 격 · 주어 뒤바뀜). 독립 검토가 필요하다.
- 같은 폴더를 여러 에이전트가 쓰면 서로의 생성 스크립트를 덮어쓴다 — 에이전트마다 폴더를 나눌 것.
- 정규식·역슬래시가 든 파일은 히어독이 아니라 파일 쓰기 도구로 만든다(CLAUDE.md §7).
