## 1. "8%만 인용한거야?"에서 시작해 사전의 근본 문제로 번졌다

12차 배치 결과(원문 988줄 중 82줄, 약 8% 인용)를 보고받은 사용자가 순서대로 물었다:

1. "8%만 인용한거야?" → 답: 원문 전체를 옮기는 게 목표가 아니라 기존 218개 상징과
   겹치는 것만 쓰는 구조라고 설명.
2. "그럼 참고자료가 메인이 되어야하는거 아니야?" → 답: 새 상징 생성은 허용할 만하지만
   원문을 전면 메인으로 삼는 건 현대 관련성이 떨어진다고 답변(송대 궁중 생활 위주).
3. **"근거도 없는 자료를 기준으로 잡은게 문제인거 같은데"** — 이 질문이 결정적이었다.
   AI가 상식으로 채운 218개 상징 자체가 처음부터 근거 없이 "기준"이 돼 있었다는 지적.

## 2. 발견 — `source: "tradition"` 99%가 거짓 라벨이었다

사용자 지적을 확인하러 데이터를 열어 보니:

- 전체 의미 347개 중 **345개(99%)가 `source: "tradition"`**.
- 그중 **166개는 그 상징에 `culture_note`(원문 인용) 자체가 없었다.**
- 원인: `scripts/backfill-dream-meaning-source.mjs`(2026-08-06)가 "값이 없으면
  무조건 tradition"으로 스키마 기본값을 기계적으로 채웠다. 그 시점 사전 209개 상징
  대부분(24개만 근거 있었음, `5cf4333` 원 커밋 메시지에 스스로 적혀 있었다)이 AI가
  한국 상식으로 채운 것이었는데, 전부 "전통 근거 확인됨"으로 라벨링됐다.
- 화면(`dream/symbol/[id]/page.tsx`)은 "전해 오는 뜻"/"일반적인 해석" 두 절로 정직하게
  나누도록 이미 잘 설계돼 있었다 — **데이터만 거짓으로 차 있었다.**

### 재검증 — git 이력 21개 커밋 전부 대조

상징 단위(`culture_note` 존재)가 아니라 **의미(symbolId+context) 단위**로 실제 원문
인용이 그 정확한 의미에 붙어 있는지 하나씩 확인했다. 이 파일을 건드린 21개 커밋의
diff를 전부 읽어, 신규 addMeaning·`citeOnly` 패턴·"기존 X를 원문으로 확인" 선언을
전부 골라내 **100개만 진짜 근거가 있다**는 걸 확인했다(`scripts/reclassify-dream-meaning-source.mjs`).

```
tradition: 345 → 100
general:     2 → 247
```

`fire`처럼 한 상징 안에서도 의미별로 근거 유무가 갈리는 경우가 흔했다(활활 크게
타오름=근거 있음, 작은 불·꺼져감=근거 없음). `money`는 4개 중 2개만 근거 있었다.

CLAUDE.md §21, memory `dream-dictionary-source-field-was-fake`로 남겼다.

## 3. "왜 자꾸 네가 만든 걸 보완만하려는거지?" — 방향을 다시 물었다

라벨만 정직하게 고친 결과를 보고하자 사용자가 "전체 진행해. 기본이 잘못되었는데 뭘
대충 수습하려는거지?"·"참고자료를 기준값으로 두라고 했는데"·"왜 자꾸 네가 만든 걸
보완만하려는거지?"로 거듭 지적했다. AskUserQuestion으로 정확한 뜻을 확인한 결과:

**"218개 틀 자체를 버리고 원문부터 다시 짠다."**

이어서 "주공해, 밀러 자료가 원문이란 말이야" · "다른 참고자료도 있잖아"로 정정 —
**원문은 주공해몽만이 아니라 밀러(Miller, 1901)도 포함**이라는 것. 확인해 보니
`apps/dreamslink/data-sources/miller-1901-parsed.json`(퍼블릭 도메인·상업 이용 가능,
2,257개 표제어)이 저장소에 이미 파싱돼 있었다 — 지금까지 12번의 배치가 전부
주공해몽만 쓰고 밀러는 **한 번도 열어보지 않았다.**

## 5. 밀러 1차 배치 — 거미·반지·열쇠

`scripts/add-dream-miller-batch1.mjs`. 밀러 원문 인용을 근거로 문맥 3개를 새로 넣고,
기존 의미 2개(반지를 낌·열쇠를 얻음)의 근거를 보강해 `source`를 tradition으로 되돌렸다.

| 상징 | 새 문맥 | 밀러 원문(1901) |
| --- | --- | --- |
| 거미 | 죽임(흉 — 배우자·연인과 다툼) | "To kill one, signifies quarrels with your wife or sweetheart." |
| 반지 | 깨짐(흉 — 다툼·이별) | "A broken ring, foretells quarrels and unhappiness..." |
| 열쇠 | 잃어버림(흉 — 곤란한 일) | "If the keys are lost, unpleasant adventures will affect you." |

218개 상징 그대로, 의미는 347 → 350가지.

**사용자가 확정한 새 규칙 — "상충되는건 한국을 우선합시다."** 까치 울음처럼 밀러(서양)와
한국 상식이 정반대인 경우(한국=길조, 밀러="dissatisfaction and quarrels")는 밀러 근거를
안 쓰고 기존 한국 상식을 그대로 둔다. 이번 배치(거미·반지·열쇠)는 상충이 없어 그대로
반영했다.

### 시험하며 잡은 것 둘

- "손가락에 낀 반지가 깨졌다"가 "반지를 낌"(기존 매칭 키 "손가락"·"꼈다"와 겹침)으로
  잘못 갈렸다 — 시험 문장에서 착용 관련 낱말을 빼 "반지가 갑자기 깨졌다"로 고쳤다.
- "열쇠를 잃어버려서 곤란했다"가 매칭 키("잃어버렸")와 활용형("잃어버려서")이 어간부터
  달라 아예 안 걸렸다 — 키를 "잃어버"(공통 어간)로 넓혔다.

```
verify-dream-context-parity   실패 0건
verify-dream-match             ALL PASS
verify-guide-numbers           ALL PASS(347→350 갱신 후)
tsc                             0건
```

새 문맥 3개 전부와 보강된 기존 문맥 2개를 손으로 `matchDream`에 태워 재확인했다.

## 7. 감사 스크립트를 짜다 실제 결함을 하나 더 잡았다

기록을 정리하며 "72개·77개 목록이 어디에도 저장 안 됐다"는 걸 알아채고
`scripts/audit-dream-source-coverage.mjs`를 짰다(수치를 손으로 세지 말라는 §10 #40·41).
그런데 **스크립트 수치가 손으로 셌던 것과 어긋났다(72 vs 74).**

원인을 파니 호랑이·소·말·물고기·거북이 다섯이었다. `dc28636`(2026-08-26)이 이 다섯에
주공해몽 근거로 새 의미를 넣으면서 **인용문을 커밋 메시지에만 적고 `culture_note`에는
안 넣었다.**

```
의미           source: "tradition"   ← 올바름(실제로 근거가 있다)
culture_note   없음                  ← 화면 "전해 오는 배경" 절이 아예 안 뜬다
```

근거가 git 이력에만 살아 있고 제품에는 없는 것과 같은 상태로 하루 넘게 방치됐다.
다섯 인용 전부 `zhougong-jiemeng-parsed.json`에서 재확인한 뒤(커밋 메시지를 그대로
믿지 않고) `scripts/backfill-missing-culture-notes.mjs`로 채웠다.

**손으로 셌으면 못 잡았다.** CLAUDE.md §21에 덧붙였다.

갱신된 수치:

```
근거 있음 · 밀러 표제어에도 있음   54개
밀러에 있는데 아직 안 씀           69개  ← 다음 배치 우선순위
근거 있음 · 밀러 표제어엔 없음     18개
둘 다 근거 없음(AI가 만든 것)      77개  ← 존치/제거 미결정
```

전수 목록과 배치 절차는 **`docs/DREAM_DICTIONARY_SOURCE_AUDIT.md`**에 남겼다 — 다음
세션이 이 문서 하나로 이어받을 수 있다.
