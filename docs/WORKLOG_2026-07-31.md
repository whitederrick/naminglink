## 1. 인연링크 화면 재구성 (사용자 결정)

### 머리글 — naming-link와 같은 구성으로

로고와 브랜드명을 뺐다. 화면을 열자마자 로고와 언어 단추 여섯 개가 먼저 눈에 들고, 정작 이
화면이 무엇인지는 그 아래에서 시작했다.

| 화면 | 버튼 |
| --- | --- |
| 입력 | `[🏠 처음으로]` `[사주 궁합 보기]` `[인연의 결]` (지금 화면이 눌린 상태) |
| 결과 | `[← 다시 계산하기]`/`[← 다시 보기]` + `[🏠 처음으로]` |
| 약관·가격 | `[🏠 처음으로]` + 메뉴 둘 |

naminglink `ServiceShell`(입력)과 `HanjaMeaningResultPage`(결과)를 그대로 옮긴 것이다.

**문구를 새로 짓지 않았다.** `footer.backHome`·`landing.cta`·`affinity.menu`·`result.recalculate`
는 이미 23로케일에 있다. 머리글 하나 때문에 번역을 23벌 더 만들면, 그 목록이 다음에 또 어긋난다.

### 배너를 하나로 합쳤다

로고 줄 자리에 배너를 넣으면 바로 위 최상단 배너와 둘이 연달아 붙는다. **최상단 가로형 하나만
남기고 그 아래에 버튼 줄을 뒀다.** naminglink가 PC에서만 버튼과 광고를 좌우로 갈랐다가
오클릭(간격 12px 실측) 때문에 위아래로 되돌린 그 배치다.

그 결과 **제목 옆 `header` 광고 자리가 사라졌다.** `lib/ads.ts`·`AdBanner`·`.env.example`에서
함께 지웠다 — 값을 넣어도 안 붙는 환경변수를 남겨 두면 나중에 "왜 안 나오지"를 다시 찾는다.
입력 화면 광고가 셋에서 둘로 줄어, 어제 문서에 남긴 우려(`AUDIT`/`WORKLOG_2026-07-30-2` §9)가
함께 해소됐다.

### 언어 선택기 — 제목 줄 오른쪽 끝

넓은 화면은 `<details>` 드롭다운(23개, 오른쪽 끝 고정, 폭 `min(92vw,34rem)`), 좁은 화면은
네이티브 `<select>`. naminglink `ServiceLanguageSwitcher`와 같은 방식이다.

**랜딩의 단추 줄(`LocaleSwitcher`)은 그대로 뒀다** — naminglink 랜딩과 같은 꼴이라야 두 서비스가
한 사이트로 읽힌다.

`<a href>`를 쓴다(`next/link`가 아니다). 로케일은 미들웨어가 `x-locale`로 알려 주고 루트
레이아웃이 `<html lang>`·`dir`을 정하는데, 소프트 내비게이션은 루트 레이아웃을 다시 그리지
않아 아랍어로 바꿔도 `dir="rtl"`이 따라오지 않는다.

### 계산 근거 링크

푸터 근처에 있어 푸터의 안내 링크와 중복처럼 보였다. 설명 문구 바로 아래로 올리고 왼쪽
정렬로 바꿨다 — 무엇을 근거로 계산하는지는 생년월일을 넣기 **전에** 궁금해지는 것이다.

## 2. 운영자 콘솔 — 서비스 분리

### 시작 상태: 섞여 있었다

| | 그때 |
| --- | --- |
| 굿즈 주문 | 인연링크 주문이 함께 뜸. `orderTypeLabels`에 라벨이 없어 `GUNGHAP_PDF` 코드가 그대로 |
| 대시보드 매출 | `admin_analytics_snapshot`이 `orders`를 통째로 집계 → 인연링크 매출이 조용히 합산 |
| 접속·이용 통계 | 인연링크는 `site_events`를 **아예 남기지 않음** → 통계가 없음 |
| 상품 설정 | 20건이 한 표에 (배지로만 갈려 있었음) |

### 가르는 기준

**DB가 가를 수 있으면 DB에 맡긴다.** 처음에는 `order_type` 목록으로 가르려 했는데,
`orders.service` 컬럼이 이미 있었다(20260727120000, 제약 + 인덱스까지). 목록을 코드에 적어 두면
주문 종류가 늘 때마다 함께 고쳐야 하고, 빠뜨리면 그 매출이 조용히 반대편으로 잡힌다.

```
orders                   service   (이미 있음)
site_events / ad_events  app       (이번에 추가, 기본값 'naminglink')
product_settings         컬럼 없음 → 코드 목록 (packages/core/src/apps.ts)
```

`site_events`에 컬럼이 필요한 이유: `PAGE_VIEW`에는 어느 서비스인지 알아낼 단서가 **하나도
없다.** `service_type`은 분석 이벤트에만 붙는다.

기본값을 `'naminglink'`로 둔 덕에 기존 464건·64건이 정확히 채워졌고 naminglink 코드는 한 줄도
안 고쳤다. `orders.is_test`처럼 기본값을 없애 래퍼를 강제하지는 않았다 — 그쪽은 값이 틀리면
매출이 오염되지만, 여기는 **이벤트 기록이 실패하는 쪽이 더 나쁘다.**

### 마이그레이션 (`20260731100000_app_scoped_analytics.sql`)

`admin_analytics_snapshot`에 `p_app`을 더했다. 인자를 늘리면 `create or replace`가 교체가 아니라
오버로드를 만들어 "function is not unique"가 되므로 옛 시그니처를 지우고 새로 만든다.
기본값이 있어 기존 2인자 호출은 그대로 동작한다.

AI는 naminglink만 쓴다. `ai_usage_logs`에는 컬럼을 두지 않고 인연링크로 물으면 빈 집합이 되게
했다 — **0이 사실이다.**

### 새 메뉴 넷

```
인연링크 현황      /naming-artist/inyeon          방문·분석·주문 + 일별 추이 + 국가별
인연링크 주문      /naming-artist/inyeon/orders   GUNGHAP_PDF·AFFINITY_PDF만
인연링크 상품      /naming-artist/inyeon/products 리포트 4종 + 판매 스위치
오픈 상태 점검     /naming-artist/inyeon/status   잠금 현황
```

현황 화면에서 **AI 호출·회원 수 칸을 뺐다.** 항상 0인 칸을 늘어놓으면 어느 0이 정상이고 어느
0이 고장인지 구분이 안 된다. 광고는 남기되 "아직 집계를 남기지 않습니다"라고 적었다.

네이밍링크 대시보드에는 인연링크 요약을 **한 줄로만** 붙였다(합치지 않는다). 서비스별 성과를
보려면 갈라야 하지만, 인연링크가 이 콘솔 어딘가에 있다는 사실은 대시보드에서 보여야 한다.

### 오픈 상태 점검 — 왜 엔드포인트가 필요한가

인연링크의 잠금은 전부 환경변수인데 그 값은 **그쪽 배포 프로세스 안에만** 있다. naminglink
콘솔은 다른 배포라 읽을 방법이 없다. Vercel 대시보드에서 눈으로 보는 것은 "무엇이 설정돼
있는지"이지 "지금 어떻게 동작하는지"가 아니라, 오타나 재배포 누락을 잡지 못한다
(`NEXT_PUBLIC_` 값은 빌드 시점에 박힌다).

`inyeonlink /api/ops/status` → 콘솔이 서버에서 프록시. **boolean과 라벨만 나간다** — 슬롯 ID나
키가 실리면 이 엔드포인트 자체가 유출 경로가 된다. 그래도 토큰으로 막고, 토큰이 없으면 503으로
닫는다(열어 두고 잊는 것보다 낫다).

환경변수 둘이 새로 필요하다: `INYEONLINK_BASE_URL`(naminglink) · `OPS_STATUS_TOKEN`(양쪽 동일).
없으면 화면이 빈 표가 아니라 **"설정하라"는 문장**을 보여 준다 — 빈 표는 "전부 꺼짐"으로 읽힌다.

## 3. 잡은 결함 하나

`/api/ops/status` 응답에서 `rewarded` 항목의 `enabled`가 **통째로 빠져 있었다.**

`gam-rewarded.ts`가 `"use client"` 모듈이라, 거기서 내보낸 값을 서버 라우트에서 읽으면
`undefined`가 된다(Next가 클라이언트 모듈을 참조로 바꿔 넘긴다). `JSON.stringify`는 undefined
키를 지우므로 항목이 사라진 것이다.

설정값만 `gam-rewarded-config.ts`(`"use client"` 없음)로 갈랐다. `ads.ts`·`next.config.ts`도
그쪽을 보게 했다 — `ads.ts`의 `submitAdGateEnabled`가 같은 함정에 걸려 있었는데, 클라이언트에서만
읽혀 드러나지 않았을 뿐이다.

## 6. 배포 뒤 이어서 고친 것 (`41ba264`)

### 상품 고시의 제작·공급자가 네이밍링크였다 (사용자 지적)

인연링크 리포트를 파는 화면인데 상품 정보 고시의 **제작·공급자가 `Naming-Link`로 나가고
있었다.** naminglink의 고시 문구를 옮겨 오면서 값까지 함께 따라온 것이다. 전자상거래법이 요구
하는 고시 항목이라 잘못된 상호가 나가면 안 된다.

**값을 로케일마다 고쳐 박는 대신 `{brand}` 자리표시자로 뒀다.** 표기가 언어마다 다르고
(ko 인연링크 · ja インヨンリンク · th อินยอนลิงก์), 박아 두면 브랜드를 바꿀 때 46곳을 다시
찾아야 한다. 화면이 그릴 때 그 로케일의 `brand`를 채운다(`fillTemplate`, 이미 있던 helper).

```
23로케일 × 상품 2종 = 46곳 치환
ko  제작·공급자 = 인연링크        (결과 화면에서 실측)
ja  制作・供給者 = インヨンリンク  (결과 화면에서 실측)
남은 "Naming-Link" 0 · 남은 "{brand}" 0
```

### 대시보드가 한쪽만 가리키고 있었다

네이밍링크 대시보드에는 인연링크로 건너가는 줄이 있었는데 반대쪽에는 없어서, 인연링크 현황에
들어간 사람은 메뉴로 돌아가야 했다. 줄을 `OtherAppLink` 하나로 모아 **양쪽이 서로를 가리킨다.**
색은 서비스 배지와 같은 계열로 간다(인연링크 자두 · 네이밍링크 틸) — 어느 쪽 숫자를 보고
있는지가 색으로도 구분돼야 한다.
