## 3. 엄격 CSP(nonce) 적용

**조건**: 실결제를 한 바퀴 돌린 뒤 · 스테이징에서 검증 후

지금도 CSP는 **전 경로에 적용돼 있다**(`next.config.ts`의 `securityHeaders`). 남은 것은
`script-src`의 `'unsafe-inline'`을 없애고 nonce로 바꾸는 것이다.

**왜 지금 안 하는가**: 결제·광고 SDK(토스·포트원·애드센스·GAM)가 인라인 실행에 의존하는
부분이 있어, 켜는 순간 **결제가 막히는 사고**가 날 수 있다. 실거래를 검증하기 전에는 그
사고를 감지할 방법도 없다. 반면 이 서비스는 남의 글을 보여 주지 않아 XSS 유입 경로가 좁다 —
**위험 대비 실익이 낮은 상태**다.

- [ ] 스테이징에서 nonce CSP 적용
- [ ] 결제 한 바퀴(토스·페이팔) · 광고 한 바퀴(애드센스·GAM 보상형·오퍼월) 확인
- [ ] 콘솔에 CSP 위반이 없는지 확인한 뒤 운영 적용

## 4. 광고 잠금 서버화

**조건**: 없다. **①②가 모두 끝났다**(①: 2026-08-02, ②: 2026-08-03).

**왜 미뤘었나**(2026-07-22 기록): 서버가 잠금을 판정하려면 "누구의 어떤 결과가 열렸는지"를
알아야 하고, 그러려면 결과를 저장해야 한다. 그런데 이 서비스는 **비회원 결과 미저장**을 팔고
있다. 원칙과 정면으로 부딪혀 보류했다.

**저장 없이 하는 길을 찾아 ①을 넣었다**(2026-08-02).

① **봉인 전송 — 완료.** 서버가 후보를 만들 때 무료 공개분 하나만 평문으로 주고, 나머지는
**후보 하나당 하나씩** 서버 비밀키로 봉인(AES-256-GCM)해 내려보낸다. 열 때 그 봉인문을
서버에 보내면 서버가 풀어 준다. 서버는 아무것도 보관하지 않는다.

```
lib/result-seal.ts            봉인·해제(서버 전용). 키는 RESULT_SEAL_SECRET
lib/candidate-seal.ts         잠긴 자리의 모양과 화면 쪽 도구(공용)
api/candidates/unseal         광고 경로 — 하나씩
api/candidates/unseal-all     결제 경로 — 상품표의 candidateLimit까지만
scripts/verify-candidate-seal.ts   봉인 검사
```

**같이 드러난 것**: 새는 것이 광고만이 아니었다. 프리미엄 상세(6~10번 후보)도 같은 평문에
들어 있어 **결제를 우회**할 수 있었다. 함께 막았다.

② **광고 관문**(2026-08-03) — 여기 적혀 있던 계획은 "GAM 보상형의 SSV 콜백을 받아 일회용
토큰을 발급한다"였다. **그 계획은 성립하지 않는다.** 웹 보상형에는 SSV가 없다:

> Server-side verification is an app only feature and it is unavailable for web use.
> — [Ad Manager Help](https://support.google.com/admanager/answer/9116812)

슬롯을 붙여도 오지 않을 콜백이었다. 인연링크 쪽 주석에는 이 사실이 처음부터 적혀 있었고,
두 앱의 전제가 어긋난 채 한쪽이 기다리고 있었던 것이다.

**증명할 수 없다면 부과할 수 있는 것은 시간뿐이다.** 광고를 시작할 때 서버가 표를 끊어
준비 시각을 적고(`/api/candidates/unlock-ticket`), 후보를 열 때 그 표를 받아 쓴다. 한 장에
후보 하나이고 쓰면 사라진다. 표를 몰아 끊어도 발급이 줄을 서므로 넷을 여는 데 광고 넷과
같은 시간이 든다. 보관하는 것은 **표의 해시·방문자 해시·시각**뿐이라 미저장 원칙과
충돌하지 않는다.

```
lib/unlock-ticket.ts                      발급·사용(server-only)
api/candidates/unlock-ticket              광고를 시작할 때 부른다
supabase/…_unlock_tickets.sql             줄 세우기·만료·정리가 전부 여기 있다
scripts/verify-unlock-ticket.mjs          실제 DB에 대고 확인(13항목)
```

**남는 한계**: 방문자 판정이 IP 기반이라 IP를 갈아 가며 병렬로 도는 것은 여전히 가능하다.
다만 그때도 후보 하나에 정직한 이용자와 같은 시간이 들고 시간당 60건 제한이 걸린다.
광고를 안 보고 **즉시·무제한**이던 것은 끝났다.

- [x] ① 봉인 전송 (2026-08-02) — **`RESULT_SEAL_SECRET`을 운영 환경변수에 넣어야 동작한다.**
      없으면 잠긴 후보를 아예 안 내려보내고(무료 하나만 보인다) 운영 알림이 간다
- [x] ② 광고 관문 표 (2026-08-03) — 환경변수는 필요 없다. 표를 끊을 수 없으면
      (Supabase 장애) 관문 없이 통과시키고 `unlock-ticket-unavailable` 알림이 간다
